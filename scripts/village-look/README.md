# village-look — 마을 화면 회귀 검사

판 열 개(보스의 아홉 + 수업 판 `town3-origin`) × 다섯 장면을 찍습니다. 장면은 3D 셋(`default` · `near` · `whole`)과 **UI 둘**(`card` 판 시작 카드 · `hud` 목표판·트레이·위 띠)입니다. 그리고 **기준 사진과 픽셀 차이**를 냅니다.

규칙·판정은 그대로인데 **그림만 조용히 틀어지는** 것을 PR 마다 잡는 장치입니다. 기준 ①(`village-sim`)은 판정 값만 보기 때문에 이런 것을 못 잡습니다. 예를 들어 #922 flipY 는 판 바닥 그림이 한 구역 뒤집혀 있었는데, 기준 ① 은 늘 0 이었습니다.

출력은 **차이 %** 와 **차이 난 칸 표**뿐입니다. 사진과 차이 그림은 파일로만 남습니다.

```bash
node scripts/village-look/shots.mjs --vs-ref origin/main
```
(PR 을 내기 전에 쓰는 명령입니다. main 을 방금 찍어 지금 작업 트리와 견줍니다. 저장된 기준은 건드리지 않습니다.)

## 쓰는 법

| 명령 | 하는 일 |
|---|---|
| `--vs-ref origin/main` | 그 ref 의 `village/` 를 임시 폴더로 풀어 찍고, 이어서 작업 트리를 찍어 장면마다 견줍니다. **PR 검사는 이것.** |
| `--more <판,판>` · `--soft <판,…>` | 표준 판에 더하기 · 그 판(판 이름이면 모든 조합)의 차이는 FAIL 이 아니라 '⚠ 바뀐 판 — 의도한 차이? PR 에 적기'. village-check 가 PR 이 바꾼 판에 스스로 쓴다(MAC-CHECKCHANGED). `--vs-ref` 에서 옛에 판 파일이 없는 새 판은 견주지 않는다 |
| `--update` | 작업 트리로 기준 사진을 새로 찍습니다(`tmp/village-look/기준/` + `meta.json`). |
| `--update --ref origin/main` | 기준을 그 ref 로 찍어 둡니다. 여러 번 고치며 볼 때 씁니다. |
| (인자 없음) | 작업 트리를 찍어 저장된 기준과 견줍니다. |
| `--self` | 같은 코드를 두 번 찍어 견줍니다. **사진이 흔들리지 않는지**(결정성)를 스스로 봅니다. 새 기능을 넣은 뒤 한 번씩 돌립니다. |
| `--boards a,b+저장본` | 판을 고릅니다. `판이름` 또는 `판이름+저장본` 꼴입니다(village-hunt 와 같음). `기본` = 판 없음. |
| `--shots card,default,hud,near,whole` | 장면을 고릅니다(기본은 다섯 모두).<br>· `card`: 판 시작 카드(교과가 있거나 `"카드": true` 인 판 · 처음 여는 판). 첫날 사진이 붙은 뒤 찍습니다. 카드가 없는 판은 '없음'입니다.<br>· `hud`: 첫 카메라 + UI(목표판을 펼침 · 토스트·풍선은 숨김). **`default` 바로 뒤**에 두어야 첫 카메라입니다. 위 띠의 그래픽 단추는 하네스가 단계를 고정해 '⚙ 낮음'으로 보입니다.<br>· `near`: 시작 배율 × 1.8 로 다가간 것.<br>· `whole`: '판 전체 보기' 단추를 누른 것. |
| `--gfx fixed\|high` | 그래픽 단계입니다. `fixed` 는 아이가 처음 보는 단계(그림자 없음 · 배율 1), `high` 는 그림자입니다. |
| `--hour 10` · `--lookseed 1` · `--frames 60` | 시각 · 난수 시드 · 장면마다 돌리는 가짜 프레임 수입니다. |
| `--max 0` · `--tol 2` | 허용 차이(%)와 '다른 점'의 문턱(RGB 채널 차 > tol)입니다. 기본값은 한 점도 다르면 FAIL 입니다. |
| `--ui` | UI 도 찍습니다(토스트·풍선은 숨김). 기본은 3D(`#cv`)와 미니맵(`#mini`)만 찍습니다. |
| `--json <파일>` · `--dir <폴더>` · `--keep` | 결과 JSON · 사진 폴더(기본 `tmp/village-look` — git 이 무시) · 임시 폴더 남기기입니다. |

끝값은 `0` = PASS, `1` = 허용을 넘은 장면이 있음(FAIL), `2` = 돌리지 못함(기준 없음 · 렌더러가 기준과 다름 · 크로미움 없음)입니다.

기본 판과 저장본: `기본+pop88` · `town3` · `town3-origin` · `farm+mid36` · `city+mid36` · `sea` · `mountain` · `origin` · `proto-flow` · `proto-vote`. `town3`·`town3-origin`·`origin`·`proto-*` 는 판의 시작 땅이 저절로 깔립니다. `sea`·`mountain` 은 지형이 보이게 빈 땅으로 둡니다.

한 번 도는 데 약 64초(판 열 × 다섯 장면), `--vs-ref` 는 그 두 배가 걸립니다. 3D 만 볼 때는 `--shots default,near,whole`(약 30초). CPU 는 한 자릿수 %입니다.

## 같은 코드면 같은 사진 — 어떻게

- **GPU** 는 `--use-angle=metal --use-gl=angle` 입니다(이 맥 M5 · swiftshader 금지 — 보스 09-24). 렌더러 문자열을 기준의 `meta.json` 에 적고, **다르면 견주지 않습니다**(끝값 2). 다른 기기(학교 Windows 등)는 그 기기에서 기준을 따로 찍어야 합니다.
- **난수** — `Math.random`(그림)과 `window.__SIM_RAND`(판정 · #926)를 시드로 고정합니다.
- **가짜 시계** — 페이지의 `performance.now` 와 `requestAnimationFrame` 을 이 스크립트가 한 장씩(1/60초) 돌립니다. 실제로 몇 초가 걸리든 그림은 같은 순간입니다. 안내·판 카드는 실제 시간 1.5초 동안 조용할 때까지 닫되, 그동안에는 프레임을 돌리지 않습니다.
- **고정** — 그래픽 단계(`__gfxMode`) · 시뮬 멈춤(`__setSpeed(0)` · 장면마다 다시) · 시각(`__setHour`) · 화면 1366×610 · 배율 1입니다.
- **CSS 전환·애니메이션 끔** — 실제 시간으로 흘러 사진을 흔듭니다. `visibility` 전환이 0.2초 남아 트레이 카드가 3D 사진에 찍히기도 했습니다(09-24).
- **바깥 주소는 전부 막습니다**(CDP Fetch — 이 스크립트의 127.0.0.1 서버와 `data:`·`blob:` 만). sid 는 늘 guest 라 운영 DB 에 닿지 않습니다. 창 0 · 한 번에 한 판 · 끝나면 브라우저와 서버를 닫습니다.

재 본 것(09-24):
- 판 열 × 세 장면을 두 번 찍어 **모두 픽셀 0 차이**였습니다. `--gfx high`(그림자)도 같습니다.
- UI 두 장면을 더한 뒤에도 판 열 × 다섯 장면(카드 없는 기본+pop88·origin 제외 48장)이 `--self` 로 **모두 0**이었습니다. 한 번 도는 데 약 64초 걸립니다.
- 검사력 ①: flipY 한 줄을 되돌리면 기본 45% · 바다 89~95% · 산 60~81% 로 **FAIL** 이 납니다.
- 검사력 ②: 모래 색을 채널 8만큼 바꾸면 바다 10~17% 로 FAIL 이 나고, 칸 표에 **모래 칸(147~149 줄)만** 나옵니다.

## 차이 난 칸 표

차이 점을 3칸(화면 px)마다 하나씩 `window.__screenCell(x, y)`(화면 점 → 칸 · 읽기만)로 짚어 칸별로 셉니다. 한 점을 ×9 로 셉니다. 짚는 것은 **그 장면을 찍은 카메라 그대로**입니다.

칸마다 바닥(지형 판이면 `__terrain`)과 그 칸의 물건(`__stream(x,y).칸.종류`)을 함께 적습니다. `판 밖` 은 하늘 등 판이 아닌 곳입니다.

차이 그림은 `tmp/village-look/차이/<판>__<장면>.png` 에 남습니다(다른 점은 빨강, 나머지는 흐린 회색).

## PR 절차 — '의도한 차이'

1. 브랜치에 main 을 합친 뒤 `node scripts/village-look/shots.mjs --vs-ref origin/main` 을 돌립니다.
2. **그림을 안 바꾼 PR**(판정·도구·문서)은 **PASS(0)** 여야 합니다. 차이가 나면 '그림이 조용히 바뀐 것'이니, 원인을 찾기 전에는 올리지 않습니다.
3. **그림을 바꾼 PR** 은 PR 본문에 `## 의도한 차이` 절을 둡니다.
   - 표를 그대로 붙이고, **판 · 장면 · 차이 % · 칸 · 왜 바뀌었나**를 적습니다.
   - 의도한 판·장면 **밖**에서 난 차이는 '의도 안 함'으로 따로 적고 까닭을 밝힙니다. 모르면 올리지 않습니다.
   - PR 에 적는 한 줄: `village-look · <렌더러> · --vs-ref origin/main (<main 짧은 해시>) · 차이 장면 N`.
4. 머지된 뒤 기준을 저장해 쓰는 사람은 `--update --ref origin/main` 으로 **기준을 새로 찍습니다**. `--vs-ref` 는 저장된 기준을 쓰지 않으므로 이 단계가 필요 없습니다.
5. 새 기능이 실제 시간(`setTimeout`·`Date`)으로 그림을 움직이면 사진이 흔들릴 수 있습니다. 넣은 뒤 `--self` 로 0 인지 봅니다. 흔들리면 그 기능은 `performance.now`·`requestAnimationFrame` 에 묶는 것이 맞습니다.

## 한계

- 시뮬을 멈춘 채 찍습니다. 사람은 불러온 순간 자리에 있고, **걷는 모습**은 안 봅니다(village-hunt 몫).
- 계절은 저장본의 날짜를 따릅니다. 날씨는 맑음입니다(멈춰 있어 비가 안 옴).
- 기준은 기기(GPU)마다 다릅니다. 기기끼리 사진을 견주지 않습니다.
- `whole` 장면에서 판의 **가까운 쪽 절반이 잘려** 하늘로 보입니다. 직교 카메라가 목표에서 150 만큼만 떨어져 있어, 판 전체 보기(배율 1)에서 가까운 절반이 카메라 뒤(near 면 밖)로 넘어가기 때문입니다. 이것은 게임 쪽 현상이고 main 에서도 같습니다. 고치면 `whole` 이 모든 판에서 '의도한 차이'로 나옵니다.
