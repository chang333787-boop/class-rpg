# 우리 마을 백업 · 되살리기 절차서

> 대상: 보스 · 선생님. 스크립트는 `scripts/village-backup.mjs` · `scripts/village-restore.mjs`.
> 마을(`classRPG_villages`)은 **RPG 백업에 들어가지 않고**, **지우기는 규칙으로 못 막습니다.** 그 빈자리를 이 두 스크립트로 메웁니다.

---

## 1. 백업 — 하루 한 번 (읽기만, 운영 쓰기 0)

저장소 폴더에서:
```bash
node scripts/village-backup.mjs --out "C:/Users/USER/OneDrive - 정림초등학교/바탕 화면/클로드코드/tmp"
```
- 운영 `classRPG_villages` 를 **GET 1번** 받아 `village_backup_<YYYYMMDD_HHMM>.json` 로 씁니다.
- 끝에 **학생 수 · 구역 수 · 크기 · SHA-256** 과 학생별 마지막 저장을 보여 줍니다. `되읽기 확인: 받은 것과 같음 ✅` 이 나와야 정상입니다.
- 마을이 아직 없어도 **빈 백업을 남깁니다**(언제부터 비어 있었는지가 기록이 됩니다).
- 읽기가 실패하면(인터넷·권한) **파일을 쓰지 않고** 종료 코드 1.
- `--out` 을 안 주면 지금 폴더의 `tmp/` 에 씁니다(`tmp/` 는 `.gitignore` 에 있어 커밋되지 않습니다).

크기 참고: 학생 한 명 최대 약 135KB → 7명 최대 약 1MB/일.

## 2. 되살리기 — 한 학생씩

### 먼저 알아야 할 것 두 가지
1. **그 학생 마을이 닫혀 있어야 합니다.** 열린 기기는 몇 초 안에 자기 판을 올려 복원을 덮습니다. 스크립트가 `session` 을 보고 **90초 안에 박동이 있으면 거절**합니다. 학생이 마을을 닫고(✕) **90초** 기다린 뒤 하세요.
2. **복원본의 저장 시각을 "지금"으로 바꿔 씁니다.** 백업의 옛 시각을 그대로 두면 학생 기기가 "원격이 더 옛것"으로 보고 **자기 판으로 복원을 덮습니다**(에뮬레이터 실측). 지금 시각이면 기기는 복원본을 받고, 그 기기에만 있던 것은 `rpg.village.<sid>.sync-backup` 에 남깁니다.

### 순서
```bash
# ① 보여 주기만(쓰기 0) — 백업·지금 상태·열림 여부·쓸 크기를 확인
node scripts/village-restore.mjs --file <백업 파일> --sid <학생 id>

# ② 확인했으면 실제로 되살리기(운영이면 --yes-production 까지 필요)
node scripts/village-restore.mjs --file <백업 파일> --sid <학생 id> --apply --yes-production
```
- 쓰는 것: `classRPG_villages/<sid>` 한 곳에 **PUT 1번**(백업의 meta + plots · `savedAt`=서버 지금 · `dev`=`restore-<시각>` · `session` 없음).
- 끝나고 **다시 읽어 구역 문자열이 백업과 같은지** 확인합니다. `백업과 구역 문자열 같음` 이 나와야 정상.
- 학생 id 는 교사 화면 → 🏘️ 우리 마을 표, 또는 백업 파일 요약에 나옵니다.

### 되살린 뒤 학생 기기에서 일어나는 일
| 그 기기 상태 | 다음에 열 때 |
|---|---|
| 마지막으로 올린 뒤 바꾼 것 없음 | 복원본으로 열림 |
| 올리지 못한 변경이 있음 | **복원본으로 열리고**, 기기에만 있던 판은 `.sync-backup` 에 남음 + "이 기기에만 남은 마을이 있어요" 알림 |

### 거절되는 경우
| 메시지 | 뜻 |
|---|---|
| `지금 열려 있는 마을입니다` | 학생이 닫고 90초 뒤 다시 |
| `운영에 쓰려면 --yes-production` | 실수 방지. 운영에 쓸 게 맞으면 붙이기 |
| `백업(…)에 <sid> 마을이 없습니다` | 그 날 백업에는 그 학생 마을이 없었음 — 더 옛 백업 파일로 |
| `village-backup.mjs 로 만든 파일이 아닙니다` | 다른 JSON 을 넣었음 |
| `sid 모양이 규칙과 다릅니다` | `guest` 이거나 글자가 규칙 밖 |

## 3. 검증 기록 (2026-09-15, Firebase RTDB 에뮬레이터 v4.11.2 — 운영 0)
- 백업 → 되읽기 일치 · 읽기 실패(서버 없음 / 401) → 파일 0개 · 종료 코드 1
- 지워진 마을: 보여 주기만 → 쓰기 0 · `--apply` → 구역 문자열 백업과 같음 · `savedAt` 지금 · `session` 없음
- 열린 마을 → 거절 · 운영 `--apply` 에 `--yes-production` 없음 → 네트워크 전에 거절
- **되살린 뒤 저장소 `village/sync.js` 로 학생 기기 열기**:
  - 스크립트로 되살림 → 기기 `remoteBackup` → 복원본(AAAA)으로 열림 · 기기 변경(BBBB)은 `.sync-backup`
  - 비교: 옛 `savedAt` 그대로 PUT → 기기 `pushDirty` → **복원이 기기 판(BBBB)으로 덮임** ← 시각을 바꾸는 이유
- 운영 백업(GET 만): 마을 0명 · 빈 백업 파일 정상
