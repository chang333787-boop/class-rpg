## B. 엔진을 '규칙 모듈 + 스위치' 꼴로 — 기존 코드는 뒤집지 않는다
겨울에 이 엔진을 떼어 다른 게임의 토대로 쓴다(사용자). 지금 큰 공사는 하지 않고, **새로 쓰는 규칙부터** 아래 꼴을 지킨다.

```js
/* 프리모드 기본값을 가진 설정 객체 하나. 교과 스테이지는 나중에 이 값만 바꿔 얹는다. */
const RULES = {
  whyBubble:   { on: true,  every: 8000, show: 3500 },          // 성장이 멈춘 집의 이유 풍선(E)
  moveInByJoy: { on: false, fast: 100, slow: 300 },             // 만족이 이사 속도로(C-0, 판단 뒤)
  hoodScore:   { on: false, r: 2, pretty: 7, shabby: 3 },       // 동네 점수 → 집 모습(C-1)
  demandFlow:  { on: false },                                   // 수요 유출·역유입(C-2)
  titles:      { on: false },                                   // 마을 칭호(C-3)
  sameKindHalf:{ on: false, from: 3, mul: 0.5 },                // 같은 건물 3개째부터 반감(D — 수치 제안만)
};
```
규칙 하나 = **① 순수 함수**(칸 배열·주민 목록·상수를 받아 값을 돌려준다. `THREE`·`document` 를 안 만진다) **② 상태 한 덩이**(저장본에 없으면 기본값으로 살아난다) **③ 고리 한 줄**(기존 틱·그리기에서 `if (RULES.x.on) …`). 그리기는 그 상태를 **읽기만** 한다. 숫자는 `RULES`·`K`·`GOALS`·`UNLOCKS` 같은 **표**에만 둔다.
- 무화면 하네스(Node 에서 하루 10분 × 30일을 몇 초에): 지금 `simTick` 은 `tickFolks`→`claim`·`roadBFS` 까지는 순수하지만 `toast`·`sndFx`·`dirtyChunks`·`document.getElementById('folk')` 가 섞여 있다. **브라우저 안에서는 이미 된다** — `__tickBench(600)` = 시뮬 1분, 60분이 5초(계획표의 실측이 이것). Node 로 떼려면 그 네 가지를 빈 함수로 바꿔 끼우는 얇은 껍데기가 필요하다 → 여유 있을 때, 큰 공사 없이 가능해 보인다(미검증).

## C. 제안 3건 + 0번 (구현은 보스·사용자 판단 뒤)

### C-0. 만족이 인구로 돌아오게 — *가장 먼저* (협업자에게 첫 질문으로 물어 둠)
지금: 이사 조건 = 빈 방 · 집 앞 길 · 길 6칸. 우물 0개·1층 집 174채가 정상 플레이와 같은 속도로 인구 206.
후보: **A** 이사 올 집을 😊 집부터 고른다(속도 그대로) · **B** 마을의 😊 비율로 이사 간격이 달라진다(무직 벌칙 ×2 와 같은 꼴) · **C** 😟 집에 오려던 사람이 집 앞까지 왔다가 고개를 젓고 돌아간다(보이는 유출 + 이유 풍선).
내 추천: **C 를 보이는 장치로, B 를 속도로** — 단 "마을은 리셋되지 않는다·저절로 사라지지 않는다"(사용자 결정)를 지켜 **이미 사는 주민은 떠나지 않는다.** 협업자 답을 받은 뒤 확정.

### C-1. 동네 점수 → 집 모습 (가치 2)
- 규칙(손가락으로 센다): 집에서 **2칸 안**의 것만. 나무·꽃밭·의자 **+1씩**, 연못·분수·조각상 **+2**, (나중에 생길) 쓰레기·소란 **−1**. 시작 5, 0~10.
- 그림: **7↑ 예쁜 집**(화단·밝은 지붕) / 4~6 보통 / **3↓ 낡은 집**(바랜 색). 층과는 따로 — 3층 낡은 집도 있다.
- 지금의 F33(둘레 4칸·소수 무게·성장 배율)을 **정수·2칸·그림**으로 바꾸는 것. 성장 배율은 그대로 두거나 뺀다.
- 구역: 점수 계산·상태·저장은 프로그램, **예쁜 집/낡은 집의 모양·색은 디자인 담당**. 새 저장 필드 없음(놓을 때·치울 때 다시 센다 — F33 과 같은 방식).
- 함정: 나쁜 이웃(−)이 아직 없어 **더하기뿐**이면 "나무로 도배"가 정답이 된다 → 상한 10 + C-3 칭호와 묶거나, 쓰레기(자라나는 순서 표의 다음 후보)가 들어온 뒤 켠다.

### C-2. 수요 유출 / 역유입으로 걷는 주민 (가치 3)
- 유출: 주민이 볼일을 보러 나섰는데(F26 시간대 끌림) **14칸 안에 그 건물이 없으면**, 길 끝(이사 오는 자리)으로 걸어 **마을 밖으로 나갔다가 한참 뒤 돌아온다.** 머리 위 풍선 `🪣?`. 나간 횟수를 필요별로 센다 → 하루 소식(`dayNote`)에 "어제 8명이 물 뜨러 옆 마을에 다녀왔어요".
- 역유입: 이미 있다(손님·이웃 구경꾼). **우리에게 있는 볼거리 종류가 많을수록 더 자주** 오게만 잇는다.
- 돈이 없으므로 '세수 상실'은 없다 — **보이는 것 자체가 피드백**이다. 벌은 없다(D10 ④ "무시해도 벌 없음").
- 성능: 새 사람을 만들지 않는다. 있는 주민의 목적지만 바꾼다(길찾기 예산 `PATH_BUDGET` 안).
- 함정: 길 끝이 여러 개면 어디로 나가나 → 이사 오는 자리와 같은 규칙(가장 먼 끝). 밤·학교·출근 리듬(F24·F27)보다 우선순위가 낮아야 한다.

### C-3. 마을 칭호 (가치 6)
- 등급이 아니라 **성격**: 놓인 것의 비율로 하나를 고른다 — 🌳 숲속 마을(자연 ≥ 40%) · 🛝 놀이 마을(쉼·놀이 많음) · 🏪 장터 마을(가게·일터 많음) · 📚 배움 마을(도서관·학교) · 🛣️ 큰길 마을 · 🏡 오순도순 마을(기본). 탭 분류(PR #438 `USE_TABS`)를 그대로 센다.
- 보이는 곳: 위쪽 마을 이름 옆 · 하루 소식 · (규칙 게시 뒤) 친구 마을 목록. 바뀌면 토스트 한 번.
- 저장: 없음(매번 센다). 서버 `meta` 에 넣을지는 `sync.js` 를 건드리므로 **따로 판단**.

## D. 같은 건물 반감 — 수치 제안만 (가치 5)
지금은 필요 건물이 '있나/없나'뿐이라 반감시킬 **양**이 없다. 넣으려면 먼저 "한 건물이 돌보는 집 수"가 있어야 한다.
- 제안: 필요 건물 **정원 = 그 건물이 닿는 집 수 기준** — 우물 8채 · 가게 10채 · 놀이터 12채 · 의자 3채 · 꽃밭 2채(손가락으로 셀 수 있는 수). 넘치면 **가까운 집부터** 채우고 나머지는 '멀어요' 대신 **'붐벼요'**.
- 같은 종류 **3개째부터 정원 절반**(사회시뮬 Q4-①). 그래야 "우물 열 개"보다 "우물 + 분수 + 연못"이 낫다 = 종류를 섞게 된다.
- 위험: 지금 😊 인 마을이 패치 뒤 😐 로 떨어진다(층은 안 내려가니 손해는 성장 정지뿐). **기존 마을 보호**: 스위치 기본 꺼짐 → 새 마을부터, 또는 정원을 넉넉히(위 수치 ×2) 시작.
- 실측 필요: 정상 플레이 마을(집 30채)에서 위 정원이면 필요 건물이 몇 개 필요한가 — 하네스로 잰 뒤 확정.

## E. 바로 구현하는 것 — 성장이 멈춘 이유 풍선 (가치 4 · 보스 지시 '꾸밈→주민 반응'과 한 몸)
- 집을 누르지 않아도, **성장이 멈춘 집의 주민 머리 위에 이유 그림**이 뜬다: 🪣 물 · 🛒 장보기 · 🛝 놀이 · 🪑 쉼 · 📚 배움 · 🚶 붐빔 · 💼 일자리 · 🌳 삭막. 꾸밈이 많은 집 주민은 가끔 🌸.
- 지금 얼굴 풍선(😊😐😟)과 같은 장치(InstancedMesh 판)를 쓰고, 표정 대신 **가장 급한 이유 하나**를 고른다 — 새 그리기 호출은 그림 종류 수만큼(8)만 는다. 전/후 draw call·프레임 시간을 PR 에 적는다.
- `RULES.whyBubble` 스위치. 이유 고르기는 순수 함수 `whyStuck(sat, crowded, jobless, amen)`.
