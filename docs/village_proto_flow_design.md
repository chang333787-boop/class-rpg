# 고장 프로토타입 — 설계 한 장 (2026-09-21 · **문서만 · 구현 전**)

> 정본 `docs/village_proto_spec.md` 2절. 답할 질문: **"마을을 작게 묶어 보여 줘도 아이가 물건이 어디서 와서 어디에 쓰이는지 따라가 고칠 수 있는가."**
> **버릴 셈으로 만드는 시험**이다. 2-4가 요구한 다섯 물음에 답하고, 기존 흐름(#745~#754)에 이미 정한 것은 **"그대로"**라고 적는다.
> 이어지는 문서: 고장 화면의 **운반 표현**은 `docs/village_proto_field_act.md`(#758)가 비교판으로 정했다 — 이 설계는 그 결론을 그대로 쓴다.
> 관찰 잣대는 `docs/creator_notes/2026-09-21_proto_watch_plan.md`(#755) — **세 상태의 말이 서로 다른가 · 그 말이 가리키는 곳으로 갈 수 있는가 · 한 수로 풀리는가.**

## 0. 가장 큰 결정 — 계산은 한 세계 그대로, '마을'은 화면일 뿐

정본의 ⚠ 제약: **'줌 단계 = 단위 단계'는 가설이므로 내부 계산을 마을 단위로 다시 만들지 않는다.**

그래서 이렇게 한다:

- **한 판(한 세계)** 안에 두 동네를 **멀찍이 미리 배치**한다(시작 저장본). 사이는 긴 길 하나로 잇는다.
- 계산은 **지금 흐름 그대로** — 밭 → (길 BFS · 거리 × 칸당틱) → 가게 → 세대. 마을 집계·마을 재고 같은 새 단위를 **만들지 않는다**.
- '마을 A / 마을 B / 고장'은 **카메라 자리와 요약 카드**다. 화면을 바꿔도 **같은 세계·같은 시간**이 흐른다(정본 2-2 요구가 저절로 충족된다 — 세계가 하나이므로).

> 이 선택의 값: 집계가 정말 필요한지는 **시험 결과로** 판단할 수 있다. 지금 만들면 답을 정해 놓고 묻는 꼴이 된다.

## 1. 2-4의 다섯 물음

| 물음 | 답 | 지금과 |
|---|---|---|
| **생산한 물건을 어디 두나** | **밭 안**(`담을수`까지). 창고 건물 없음 | **그대로**(#745) |
| **출발 때 어느 재고가 변하나** | 밭 재고 **−1**, 그 순간 '운반 중'이 하나 생긴다(밭·가게·양·남은틱) | **그대로** |
| **도착 때** | 가게 재고 **+1**, 운반 중 하나가 사라진다 | **그대로** |
| **운반 중 끊기면 기다리나 돌아가나** | **출발한 밭으로 돌아간다**(안 잃어버린다). 길이 다시 이어지면 저절로 다시 나선다 | **그대로**(#745) |
| **생산 시설을 없애면 남은 재고는** | 아래 **1-가** — **고쳐야 한다** | ✗ 바꿀 곳 |
| **저장·복원 때 운반 중 물건** | 밭·가게 재고 · 운반 중(출발·목적·남은틱) · 세대의 '오늘 받았나'를 저장본 `flow` 칸에 | **그대로**(#750에서 확인) |

### 1-가. 지금은 물건이 **설명 없이 사라진다** (통과 못 할 자리)

지금 규칙: **밭을 치우면** 그 밭에서 출발해 길 위에 있던 물건이 **사라진다**(돌아갈 곳이 없으므로). 정본 2-4는 *"물건이 설명 없이 생기거나 사라지는 구현은 통과시키지 않는다"*고 못박았다.

**고칠 안 (제안)**

1. **길에 나선 것은 목적지까지 간다.** 밭이 없어져도 운반 중인 물건은 **가게에 도착한다** — 이미 사람이 지고 길에 있기 때문이다(연기와도 맞는다).
2. **밭 안에 쌓여 있던 것**은 밭과 함께 사라진다 — 다만 **치울 때 한마디**: `🌾 밭을 치우면 쌓여 있던 3개도 없어져요`(되돌리기 ↩ 로 복구되면 재고도 함께 돌아온다).

3. **안에 쌓여 있던 재고는 [MAC-KEEP](식구 맡아 두기)과 같은 꼴로 1분 맡아 둔다** — ↩ 되돌리거나 같은 것을 다시 놓으면 **재고까지 돌아온다**. 1분이 지나면 버린다(그 전에 화면이 "1분 안에 돌아와요"라고 말해 두었다). **가게를 치울 때도 같다.**
4. **밭도 가게도 없어져 갈 곳이 없으면** 그때 한마디 — 조용히 없애지 않는다.

→ 이러면 '사라짐'이 **아이가 고른 행동의 결과**로만 일어나고, 화면이 그것을 말한다.

**✅ 구현됨 — `[MAC-FLOWGONE]`.** 실화면에서 확인한 말:
`🌾 쌓여 있던 곡식 5개를 1분 맡아 둬요 — ↩ 되돌리거나 다시 놓으면 돌아와요` → ↩ → `밭을 되살렸어요` · `🌾 곡식 5개가 돌아왔어요`(재고 5 그대로).
덤으로 **반대쪽 어긋남도 닫혔다**: 전에는 치워도 `FLOW` 기억에서 안 지워져, 한참 뒤 같은 자리에 새 밭을 놓으면 **옛 재고가 말없이 되살아났다**.

### 1-나. 합계 검산 — **내가 먼저 도구로 돌려 두었다** (관찰자 1-5)

관찰자가 *"출발지 재고 + 운반 중 + 도착지 재고의 합이 맞는지"*를 보겠다고 했다. 같은 검산을 시뮬로 돌렸다.
검산식: **만듦 = 밭에 남은 + 운반 중 + 가게에 있는 + 세대가 쓴 것** (밭 2 · 집 4 · 거리 26칸 · `?stage=farm`)

| 언제 | 만듦 | = 밭 + 운반중 + 가게 + 씀 | 맞나 |
|---|---|---|---|
| 하루 뒤 | 4 | 0 + 0 + 4 + 0 = 4 | ✓ |
| 이틀 뒤 | 10 | 0 + 0 + 6 + 4 = 10 | ✓ |
| 사흘 뒤 | 16 | 0 + 0 + 8 + 8 = 16 | ✓ |
| **길 한 칸을 끊고** 반나절 | 18 | **2** + 0 + 6 + 10 = 18 | ✓ (밭에 쌓인다) |
| 다시 잇고 | 22 | 4 + 0 + 4 + 14 = 22 | ✓ |
| **밭 하나를 치우고** | 24 | 0 + 1 + 7 + 14 = **22** | ✗ **2개가 말없이 사라진다** |

→ **끊김·복구·저장 경로는 합이 맞는다.** 어긋나는 자리는 **오직 1-가 하나**였다.

**고친 뒤 다시 돌렸다** (`[MAC-FLOWGONE]` · 검산식에 `맡아둔것`을 더한다):

| 언제 | 만듦 = 밭 + 운반중 + 가게 + 씀 + 맡아둔것 | 맞나 |
|---|---|---|
| 하루 · 이틀 · 사흘 | 4 / 10 / 16 | ✓ |
| 길 끊고 → 다시 잇고 | 18 / 22 | ✓ |
| **밭 하나 치움** | 24 = 0 + 1 + 7 + 14 + **2** | **✓** |
| 그 자리에 다시 놓음 | 24 = 2 + 0 + 8 + 14 + 0 (**돌아옴 1**) | ✓ |
| 가게까지 치움 | 26 = 4 + 0 + 0 + 14 + **8** | ✓ |

**'길에 나선 것은 목적지까지 간다'**는 밭 하나뿐인 판에서 따로 쟀다 — 길 위에 짐 1개가 있을 때 밭을 치우면:

| | 가게에 닿음 | 가게 재고 | 남은 짐 |
|---|---|---|---|
| 옛 판정(`flowGone.on = false`) | **0** | 0 | 0 → **1개 증발** |
| 새 판정 | **1** | 1 | 0 |

→ 관찰자의 검산은 이제 모든 자리에서 맞아야 한다. **어긋나면 그건 새 결함이다.**

## 2. 시험 세계 수치 (고정 · 정상 상태에서 공급이 끊기지 않게)

**단위**: `틱`이 프로그램의 시간 단위다. **1틱 = 0.1초 실시간(1× 배속)** · **하루 = 1800틱 = 3분** · 하루는 시뮬 24시간.

| 값 | 정할 값 | 단위로 옮기면 | 까닭 |
|---|---|---|---|
| 상품 | **한 종류**(곡식) | | 정본 |
| 마을 A | **밭 2** | 하루 생산 **6개** | 밭마다 600틱에 1개 → 1800÷600 × 2 |
| 마을 B | **가게 1 · 집 4** | 하루 사용 **4개** | 세대몫 1 × 4세대 → 여유 2 |
| 밭 `간격틱` | **600틱** | **60초** · 시뮬 8시간 | 그대로 |
| 밭 `양` · `담을수` | 1 · 5 | 한 번에 1개 · 밭에 5개까지 | 그대로 |
| 가게 `담을수` | 8 | 이틀치 | 그대로 |
| `쓰는시각` · `세대몫` | 낮 12시 · 1 | 집마다 하루 1개 | 그대로 |
| **`칸당틱`** | **13** | 한 칸에 **1.3초** | 사람 걸음과 같은 값(#754에서 재서 정함) |
| 두 동네 사이 거리 | **28칸** | 28 × 13 = **364틱 ≈ 36초** | 아래 2-가에서 실측으로 정했다 |
| `운반상한` | 4 | 길 위에 한 번에 4개까지 | 그대로 |

**정상 상태 확인**: 하루 생산 6 ≥ 사용 4. 가게 `담을수` 8이라 이틀치까지 쌓인다. 끊기면 밭에 5까지 쌓이고 그다음 `full`.

### 2-나. 고장 화면은 **줌아웃이 아니라 별도 화면**이다 (보스 조건 ③)

내가 2-가에서 *"한 화면에 다 들어오니 묶어 보이는 화면이 필요 없다"*고 적은 것은 **시험 자체를 없애는 결론**이었다. 보스가 바로잡았다:

> 우리가 답하려는 것은 **"마을을 작게 묶어 보여 줘도** 아이가 물건이 어디서 와서 어디에 쓰이는지 따라가는가"다. 한 화면에 다 보이면 **묶어 보여 준 적이 없으니 시험이 성립하지 않는다.**

그래서:

- **고장 화면 = 마을을 작은 모형으로 그린 별도 화면.** 같은 카메라를 뒤로 뺀 것이 아니다. #758이 잰 대로 그 배율에서는 사람 2.9px · 짐 6.6px라 **마을 안의 연기를 축소해 쓰는 길은 없고**, 따로 된 표현(ⓒ 늘 보이는 선 + ⓑ 짐수레)이 그 화면의 언어다.
- **줌 애니메이션은 여전히 없다** — 전환 버튼 셋이면 된다.
- 즉 '한 화면에 들어온다'는 사실은 **거리를 28칸으로 정해도 좋다는 근거**일 뿐, 화면 왕복을 뺄 근거가 아니다.

### 2-가. 거리를 30칸이 아니라 **28칸**으로 정한 까닭 — 땅이 그만큼이다

실측: 판을 처음 열면 **열린 땅은 32×32 한 구역뿐**이다(`__plots()` → `열린구역: ["4,4"]` · `구역크기: 32` · x 128~159). 그 밖에 놓으려 하면 **"아직 내 땅이 아니에요 · 인구 10명이면 옆 땅이 열려요"**로 막힌다.

- **28칸이면 한 구역 안에 들어간다**(가게 x=129 ↔ 밭 x=156). 땅 해금을 건드릴 필요가 없다. **두 마을이 물리적으로 가까운 것 자체는 괜찮다**(땅이 한 구역뿐이므로 — 보스 확인).
- 실측: 28칸은 **기본 줌에서도 한 화면에 들어온다**(아래 사진). ⚠ **그렇다고 고장 화면을 '기본 줌 그 장면'으로 삼으면 안 된다** — 아래 2-나.
- ⚠ 다만 **인구가 10명이 되면 "🔓 땅을 하나 더 가질 수 있어요"** 소식이 뜬다(실측 45초 지점). 프로토는 아이를 땅 고르기로 끌고 가면 안 되므로 **시작 저장본에 이미 인구를 채워 두거나 그 소식을 판에서 끈다**(아래 6-다).

## 3. 화면 셋 (버튼 전환 · 애니메이션 없음)

세 화면은 **같은 세계**를 다른 자리에서 볼 뿐이다.

| 화면 | 무엇인가 | 함께 보이는 것 | 딸린 단추 |
|---|---|---|---|
| **🗺️ 고장 전체**(기본) | **마을을 작은 모형으로 그린 별도 Scene**(2-나 · 줌아웃한 기본 장면이 아니다) | 덩이마다 요약 카드(밭 n·쌓인 양 / 가게 선반 n / 집 n채·오늘 받은 집 n) · 가운데에 **연결 한 줄**(🚚 / ✂️ / ❌) | — |
| **밭 마을**(만드는 곳) | 같은 세계를 마을 배율로 — 카메라만 그 동네로 | 밭마다 상태·쌓인 양(누르면 카드) · 나르는 사람 | **[⏸ 생산 멈춤]** / [▶ 생산 다시] |
| **가게 마을**(쓰는 곳) | 〃 | 가게 선반 · 가게를 누르면 **까닭**(이미 있는 네 줄) | **[🔗 공급 경로 보기]** → 고장 화면으로 가며 **선을 4초 동안 굵고 밝게 짚는다** |

- 단추는 화면 **왼쪽 세로**에 있다(트레이와 안 겹친다). 화면을 바꿔도 **세계는 계속 돈다** — 셋 다 시각·재고가 같다(실측: 4일째 아침 11시 · 가게 6).
- **[⏸ 생산 멈춤]**은 밭의 `간격틱`을 아주 길게 두는 시험용 장치다(쌓인 것은 그대로 가게로 간다 = '생산만' 멈춤). 실측: 누르고 12초 동안 `만듦` 0. ⚠ 이미 잡혀 있던 수확 한 번은 날 수 있다.
- 마을 화면의 **줌은 안 건드린다**. 동네 크기에 맞춰 배율을 자동으로 맞춰 봤더니 **빈 풀밭만 크게** 나왔다 — 아이가 `+ −`로 보는 쪽이 낫다.

- 전환은 **버튼 세 개**. 화면을 바꿔도 세계는 계속 돈다(정본 요구).
- **마을 사이 운반의 그림은 #758이 정한 ⓒ+ⓑ**를 쓴다: 연결선이 **늘 보이고**(끊기면 끊긴 자리에서 멈추고 어둡게), 그 위로 **밝은 마디가 A→B로 흐르고**, 운송 중일 때 **짐수레 하나**. 사람과 짐은 이 배율에서 2.9px·6.6px라 **안 보인다** — 사람에 기대지 않는다.

## 4. 원인 셋 — **이미 있는 것으로 충족된다**

| 정본이 요구한 상태 | 지금 있는 것 | 반드시 보일 것 |
|---|---|---|
| 공급원 없음 | `flowWhyEmpty` → **"이 가게에 오는 밭이 없어요"** | 마을 A 화면으로 보내 밭을 놓게 · 고장 화면엔 **연결선 자체가 없다** |
| 연결 단절 | 밭 `cut` + **"밭에 쌓여 있는데 길이 끊겼어요"** + 밭 모서리에 **자루 더미** | 고장 화면에서 **선이 끊긴 자리에서 멈춘다** + 출발지 재고 |
| 운송 중 | `moving` + **"곧 와요 — 오는 중이에요"** | 고장 화면에 **흐르는 마디 + 짐수레** · **운반 중 n개** |

→ **새 판정을 만들지 않는다.** 고장 화면의 '강조'와 '요약 숫자'만 더하면 된다.

## 5. 관찰자에게 주는 넷 (진입 경로 · 저장 키 · 훅 · 값)

관찰 계획 4절이 *"이 넷을 받아야 '설명과 실제가 어긋난다'를 셀 수 있다"*고 했다. 여기에 못박는다.

### 5-가. 진입 경로 — 주소 하나 (본편 화면에 버튼을 만들지 않는다)

```
village/index.html?sid=guest&stage=proto-flow
```

- **`sid=guest` 를 반드시 붙인다** — 그래야 `sync.js`가 네트워크를 한 번도 쓰지 않는다. 진짜 학생 id 금지.
- 본편(기본 마을) 화면에는 **이 판으로 가는 버튼을 만들지 않는다.** 아이가 실수로 들어가는 길을 만들지 않기 위해서다. 프로토는 **주소로만** 연다.
- 화면 안의 버튼 셋(고장 · 마을 A · 마을 B)은 **판 안에서만** 보인다 — 본편 UI에 안 생긴다.
- ✅ **판이 생겼다**: `village/stages/proto-flow.json` + 시작 저장본 `village/stages/starts/proto-flow.json`. 실제로 열어 확인한 값 — `__stage()` → `저장키: "rpg.village.guest.proto-flow"` · **`원격: false`** · `막음: 0` · `시작판: true`.

### 5-나. 시험 저장 키 — 본편과 완전히 다른 이름

| | 키 |
|---|---|
| 본편(아이 마을) | `rpg.village.<sid>` |
| **이 프로토** | **`rpg.village.guest.proto-flow`** |

판 구조가 이미 그렇게 만들어져 있다(`SAVE_KEY = 'rpg.village.' + SID + stageKeyPart()` — `village/index.html:9202`). 관찰자가 **그 자리에서 확인할 수 있는 증거**:

```js
__stage()     // → { id:'proto-flow', 저장키:'rpg.village.guest.proto-flow', 원격:false, ... }
```

`?stage=farm`에서 실제로 찍어 확인했다 — `저장키: "rpg.village.guest.farm"` · **`원격: false`**(원격 동기 꺼짐). 아이 저장본과 운영 DB에 **닿지 않는다.**

### 5-다. 훅 이름과 **반환 꼴** (화면 말과 대조할 것)

| 훅 | 무엇을 준다 | 실제 반환(실측) |
|---|---|---|
| `__flow()` | 세계 전체의 흐름 — **재고·운반 중·합계** | `{켜짐, 물건:"곡식", 짐:0, 밭:[{자리:[153,138], 양:0, 상태:"growing"}], 가게:[{자리:[129,138], 양:4, 상태:"stocked"}], 세대:{받음,못받음}, 만듦:4, 보냄:4, 닿음:4, 되돌림:0, 씀:0, 못씀:1, 가득:0, 끊김:0}` |
| `__flowAt(x, y)` | 그 칸 하나의 상태·**화면에 뜨는 말**·카드 글 | 밭: `{상태:"growing", 말:"자라는 중", 양:0, 닿는가게:[[129,138,27]], 카드:" · 곡식 0/5 · 자라는 중"}` · 가게: `{상태:"stocked", 말:"물건이 있어요", 양:4, 카드:" · 곡식 4/8 · 물건이 있어요"}` · 그 밖: `"흐름과 무관"` |
| `FLOW(root)` | 담당끼리 쓰는 계약(#752) — 밭/가게/집 한 곳의 상태 | 위 `__flowAt`과 같은 꼴 |
| `__stage()` | 어느 판인가 · **저장 키** · 원격 동기 여부 | 5-나 |
| `__pop()` | 인구·집·빈집 | `{인구:11, 사람:11, 빈집:6, ...}` |
| **`__protoMap()`** | 지금 어느 화면인가 · 덩이마다 무엇이 몇 채인가 · 생산 멈춤·짚는 중 | `{켜짐:true(고장 화면), 모형:'flow', 생산멈춤:false, 짚는중:false, 덩이:[{이름:'밭 마을', 셈:[['field',3],['well',1],['house',2]], 자루:false}], 덩이수:2, 마디수:14}` |
| `__protoMap('map'\|'v0'\|'v1')` | 화면을 바꾼다(단추와 같은 일) | 위와 같은 꼴 |
| `__protoMap('다시')` | 모형을 다시 짓는다(`VRULES.protoMap.모형`을 `'flow'`↔`'count'`로 바꿔 견줄 때) | 〃 |
| `__flowGone()` | 치운 물건을 맡아 둔 것 · 길에 나선 것이 목적지까지 간 횟수 | `{맡아둔것:[['field',5]], 맡김:1, 돌아옴:0, 계속감:1, 갈곳없음:0}` |

- **`말`·`카드` 칸이 화면에 실제로 뜨는 문장**이다. 관찰자는 `__flowAt`의 `말`과 눈으로 본 카드를 **글자 그대로** 견주면 된다.
- 합계 검산(1-나)은 `__flow()` 하나로 된다: `만듦 == 밭들의 양 합 + 짐 + 가게들의 양 합 + 씀`.
- ⚠ **`hookAdd`·`THREE`는 `window`에 없다**(모듈 안). 토스트를 가로채려면 `#toast` 요소를 `MutationObserver`로 본다 — 내가 쓴 방법이 아래 6절이다.

### 5-라. 쓴 값과 단위 → **2절 표 그대로**. 요약하면:

**하루 = 1800틱 = 3분(1× 배속) · 밭 1개/600틱 · 집 1개/하루(낮 12시) · 운반 13틱/칸 · 28칸 = 36초.**

## 6. 첫 화면 30초 — **내가 먼저 재 보았다**

관찰 절차 0단계가 *"첫 화면에서 30초 동안 아무것도 누르지 않는다"*이다. 그대로 재 봤다(`?sid=guest&stage=farm`에 설계와 같은 배치를 놓고).

### 6-가. 잰 것 (사실만)

| 언제 | 화면에 무엇이 있었나 | 흐름 | 뜬 말 |
|---|---|---|---|
| **0~30초 · 아무것도 안 누름** | **판 소개 카드가 화면 한가운데를 덮는다**(질문 · 목표 셋 · [시작]). 시계 **"1일째 아침 6시"에서 멈춤** | 아무 일도 없음 | **0개** |
| [시작] 누른 뒤 **0~30초** | **조작 안내 카드 3장**(*"아래에서 길을 고르고 칸을 누르면 놓여요"* · 건너뛰기/다음). 시계 여전히 멈춤 | 아무 일도 없음 | **0개** |
| 건너뛴 뒤 **0~30초**(세계가 돈다) | 사람들이 이사 온다 · 시각 6시 → 10시 | 밭 둘 다 `growing` · **만듦 0** | **0개** |
| 이어 **2분** | 인구 11명 · 가게 옆에 📦(재고 4) | 첫 생산 11초 · 첫 출발 11초 · **첫 도착 25초** | **5개** — `누가 이사 왔어요 👥6명` · `🔓 분수·정자가 열렸어요` · `🔓 땅을 하나 더 가질 수 있어요` · `누가 이사 왔어요 👥11명` · `🔓 땅이 넓어졌어요` |

사진: `docs/village-shots/2026-09-20-proto-watch-*.png`(첫화면 · 조작안내 · 30초 · 2분30초).

### 6-나. 이것이 뜻하는 것 (내 해석)

1. **"아무것도 누르지 않고 30초"를 하면 관찰자는 소개 카드 한 장만 본다.** 세계가 돌지 않는다 — 시계가 멈춰 있다. 관찰 절차 0단계가 **지금 구조에서는 아무 정보도 낳지 못한다.**
2. **누를 것이 두 겹이다**(판 소개 → 조작 안내 3장). 게다가 조작 안내는 *"길을 고르고 칸을 누르면 놓여요"* — **프로토에서 아이는 마을을 만들지 않는데** 놓기부터 가르친다. 화면이 시험의 과제와 **다른 말**을 한다.
3. **흐름은 첫 1분 동안 아무것도 안 보인다.** 밭 첫 수확이 600틱(60초)이고, 거기서 가게까지 다시 36초다. → 가만히 보면 **첫 1분 36초 동안 물건이 한 번도 안 움직인다.**
4. **2분 30초 동안 화면이 한 말 다섯 개가 전부 흐름과 무관하다**(이사·해금·땅). **물건의 흐름에 대해 화면은 한마디도 하지 않았다.** 관찰자가 "설명과 실제가 어긋나는가"를 세려 해도 **애초에 설명이 없다.**
5. 하루가 3분이라 **관찰 중 절반은 밤**이다(2분 30초 지점이 새벽 5시 · 화면이 어둡다).

### 6-다. 그래서 프로토에 반드시 넣을 것 (설계 변경)

| 고칠 것 | 어떻게 |
|---|---|
| **첫 화면이 죽어 있다** | 시작 저장본에 **흐름이 이미 돌고 있는 상태**를 담는다 — 밭에 곡식 3 · 길 위에 운반 중 2 · 가게 재고 4 · 집에 사람이 산다. 저장 형식은 #750에 이미 있다(`flow` 칸). 그러면 **0초부터 짐이 길 위를 간다.** |
| **누를 것이 두 겹** | 프로토 판은 **조작 안내를 끈다**(아이가 놓기를 배울 자리가 아니다). 판 소개 카드 한 장은 **남긴다** — 과제 셋을 말해 주는 유일한 자리다. |
| **소개 카드 문구** | 지금 판 카드는 목표(밭 4곳 …)를 말한다. 프로토는 **과제 셋**(빈 가게의 까닭 찾기 → 한 가지 바꾸기 → 왜 풀렸는지 말하기)을 말해야 한다. |
| **땅 해금 소식이 끼어든다** | 시작 저장본의 인구를 이미 10명 위로 두거나, 판에서 땅 해금 소식을 끈다. **아이를 땅 고르기로 끌고 가지 않는다.** |
| **관찰 절차 0단계** | 관찰자에게 알린다: **"[시작]을 누른 뒤부터 30초"**가 실제 첫 화면이다(소개 카드는 시계가 멈춰 있다). 위 셋을 고치면 그 30초 안에 **짐이 움직이는 것이 보인다.** |

> ⚠ 이 다섯은 **화면과 판 파일 쪽 고침**이다. 흐름 셈(판정)은 **한 줄도 안 바뀐다.**

### 6-라. ✅ 다섯을 만들고 첫 30초를 다시 쟀다 (판 `proto-flow`)

| | 전(`farm` 에 손으로 놓은 마을) | **후(`?stage=proto-flow`)** |
|---|---|---|
| 아무것도 안 누른 첫 화면 | 판 소개 카드 + **시계 정지** | **과제 셋을 말하는 카드 한 장**(목표 줄 없음) + 시계 정지 |
| 눌러야 할 것 | 판 소개 → **조작 안내 3장** = 2~4번 | **[시작] 한 번** |
| [시작] 뒤 0초의 마을 | 빈 땅 · 인구 0 · 흐름 0 | **인구 12 · 밭 셋에 곡식 2·2·1 · 길 위에 짐 2 · 가게 6** |
| [시작] 뒤 30초 | 이사 오는 사람들 · **흐름 0** | 낮 12시에 **여섯 집이 모두 받음**(씀 6 · 못씀 0) · 짐 4 · 닿음 2 |
| 그동안 뜬 말 | 5개 — 전부 이사·해금·땅 | **0개** — 방해가 없다. 볼 것은 화면에서 움직인다 |

**만들며 새로 배운 것 넷**(설계에 없던 것):

1. **판의 `건물` 목록 밖 종류는 저장본에서 버려진다.** 처음에 `["road","field","shop"]` 로 좁혔더니 **집 6채가 통째로 사라져 인구가 0** 이 됐다(`__stage().막음 = 10`). 시작 저장본에 있는 종류는 **모두** 목록에 넣어야 한다.
2. **기본 목표 일곱이 열자마자 "🎯 목표 달성!" 으로 줄줄이 떴다**(길 6칸·집 3채·첫 주민·우물·가게·인구 10·놀이터 — 14초를 차지했다). 시작 저장본의 `goals` 칸에 **이미 이룬 것으로 적어** 껐다.
3. **저장본 시계 `t = 0` 은 자정이 아니라 아침 6시다.** 낮 11시는 `t % 180000 = 37500`.
4. **하루 생산과 하루 소비가 같으면 매일 한 집이 못 받는다.** 집이 6채(마을 A 의 일꾼 집 2 포함)가 되어 소비 6 · 생산 6 이었다 → **밭을 셋으로**(생산 9) 늘리고 가게 시작 재고를 6 으로 두자 못 받는 집이 0 이 됐다.

**아직 남은 것**: 하루가 3분이라 **90초쯤이면 밤**이다(관찰 30초~1분은 낮). 과제를 **다시 볼 곳이 없다**(카드를 닫으면 끝 · 🎯 목표판은 비어 있다) → `docs/village_backlog.md`.

## 9. 아직 못 정한 것 (구현하며 정할 것)

- ~~'작은 모형으로 묶기'를 멀리서 보기로 충분한가~~ → **아니다 · 별도 화면으로 그린다**(2-나 · 보스 조건 ③). 멀리서 보기로 대신하면 '묶어 보여 준' 적이 없어 시험이 성립하지 않는다.
