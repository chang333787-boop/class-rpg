## 2. '칸을 덮는 식물' — 두 길 비교

| | **가. 바닥 타일로** (🖌️ 바닥 칠하기) | **나. 장식 조각으로** (울타리 d_y70 식 자동 이음) |
|---|---|---|
| 아이 손 | **끌어서 칠하기** 그대로. 9칸 꽃밭 = 한 번 긋기 | 9번 놓기(끌어 연달아 놓기는 있음) |
| 위에 물건 | **놓을 수 있다** — 꽃밭 위 벤치·나무·동물 = '장소'가 된다 | 못 놓는다(칸을 차지) |
| 이음 | 이미 된다(변형 a~d 해시, 번짐·물가 12조각 파이프라인) | 새로 짜야 한다(h/v/모퉁이 판정은 울타리에 있지만 '면'은 없다) |
| 개수·값 | 바닥은 개수·값이 없다 → **꽃 장식(12~18G)이 안 팔릴 수 있다** | 개수 차감·값 있음 → 사다리에 들어간다 |
| 그림 장수 | 색 하나에 바탕 2~4장. 테두리 있는 화단은 **+12조각**(`bed_n·e·s·w`, `bed_in_*`4, `bed_out_*`4 — 물가 `shore_*` 와 같은 구성, 색끼리 공유) | 울타리처럼 조각 6~16장 × 색 |
| 코드 | 기존 'flower' 그림만 바꾸면 **0줄**(#432). 새 이름(`flowerbed`·색 4종·테두리)은 `FLOOR_TILES`·`_FLOOR_VARIANTS`·고르기 단추 + 물가 판정 복사 | 새 자동 이음 규칙 |
| 저장 | `yardFloor` 그대로 | `houseDecorations` 가 칸 수만큼 는다(통짜 저장 26KB 가 더 커짐) |

**제안: 가(바닥)로 간다.** 순서 — ① #432 로 기존 '꽃' 바닥을 꽃밭답게(코드 0) → ② 프로그램 담당이 바닥 이름을 늘려 주면 **단색 꽃밭 4색**(빨강·노랑·분홍·흰)과 **덤불·잔디 무늬** 바탕을 그림 → ③ **벽돌/돌 테두리 12조각**(한 벌로 모든 색이 같이 쓴다).
값이 없는 문제는 "꽃밭 바닥은 **꽃 장식을 n개 가진 아이에게 열린다**"(예: 꽃 장식 5개 보유 → 그 색 꽃밭 바닥 해금) 같은 **모으기 보상**으로 풀 수 있다 — 꽃 장식이 사다리의 첫 칸이 된다. 코드·결정 필요.

### 색 변형을 한 파일에서 뽑을 수 있나 — 시험 결과 (크롬, 캔버스 `drawImage` 기준)

| 방법 | 결과 | 비고 |
|---|---|---|
| 1. 바깥 페이지 CSS 변수(`--petal`)가 `<img>`/캔버스 SVG 안으로 | ❌ 안 들어간다(기본색 `#c92f3a` 그대로) | SVG 가 그림으로 쓰이면 바깥 스타일과 끊긴다 |
| 2. **주소 뒤 `#yellow`** + SVG 안 `#yellow:target ~ .p{fill:…}` | ✅ `cv.svg#yellow`→`#f3d55b`, `#white`→`#ffffff` | **코드는 주소에 `#색` 만 붙이면 끝.** 색은 파일 안에 미리 정한 것만. ⚠️ 사파리(아이패드)는 미확인 — 학교 기기가 크롬북이면 된다 |
| 3. SVG 를 글자로 읽어 루트에 `style="--petal:…"` 넣고 blob 주소로 | ✅ 임의 색(`#8a5ed6`·`#ee5aa0`), 캔버스 오염 없음 | '색 고르기' 같은 자유 색이면 이쪽. fetch 1회 + 색마다 비트맵 캐시(DECO-PERF-1 의 `_svgBmp` 키에 색을 넣으면 된다) |

그림 쪽 약속: 색이 바뀌는 면은 `class="p"`(주색)·`class="q"`(밝은 면)만 쓰고 `fill` 을 직접 안 적는다. 그러면 2·3 어느 쪽으로도 쓸 수 있다.
