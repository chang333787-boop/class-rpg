## 0. 쉬운 말 요약 (한 페이지)

> **왜 지금?** 학기 중엔 학생이 매일 쓰니까 "로그인 방식·저장 방식·데이터 구조"를 못 건드렸다. 방학은 **깨져도 되는 유일한 기간**이다.
>
> **뭘 갈아엎나?** 겉모습·기능이 아니라 **속**이다. ① 아무나 데이터를 볼 수 있는 보안 구멍 막기 ② 저장이 서로 덮어써서 데이터가 사라지는 구조 고치기 ③ 백업이 반쪽인 것 고치기. 여기까지가 핵심.
>
> **가장 중요한 원칙:** **연습장(스테이징) 없이 시작하지 않는다.** 지금은 코드를 고쳐도 브라우저에서 확인할 방법이 없고, 실수하면 실제 학급 데이터가 날아간다. 그래서 1주차는 "안전망 만들기"에 쓴다.
>
> **안 하는 것:** React 같은 걸로 처음부터 다시 만들기(1만 줄을 다시 만들 수 없다), 밸런스 수치 조정과 구조 수술을 같이 하기, 개학 직전 배포.

## 2. 갈아엎기의 정의 — 바꾸는 것 / 안 바꾸는 것

**바꾼다 (속):**
- 로그인·권한 구조 (Auth + 보안 규칙)
- 저장 방식 (통짜 → 필드 단위/트랜잭션)
- `pendingRewards` 자료구조 (배열 → 객체맵)
- 백업·복구 체계 (오프사이트 + 전 노드)
- 로그 무한 누적 정리
- (선택) 학급별 데이터 분리 = 멀티학급 기반
- (선택) 코드 구조 = 거대 파일 쪼개기·인라인 onclick 제거

**안 바꾼다 (겉):**
- 학생이 보는 화면·게임 흐름·기능
- 게임 밸런스 수치 (별도 트랙 — 구조 수술과 절대 섞지 않는다)
- 캐릭터 SVG·canvas 렌더 방식
- 바닐라 JS 기조 (프레임워크 전환 안 함)

## 3. 절대 순서 (의존성 사슬) — 왜 이 순서인가

```
Phase 0  안전망 (스테이징·백업·런타임 검증)
   ↓  ← 이게 없으면 아래 전부가 "운영에서 실험"이 된다
Phase 1  보안 (Auth → 규칙)
   ↓  ← Auth 없이 규칙만 배포하면 학생 전원 즉시 로그인 불가
Phase 2  저장 원자성 (pendingRewards 구조 → 필드 저장 → 트랜잭션)
   ↓  ← 자료구조를 먼저 바꿔야 부분 저장이 의미를 가진다
Phase 3  데이터 위생·확장 (로그 정리 → 백업 전노드 → (선택) 학급 분리)
   ↓
Phase 4  코드 구조 (이벤트 위임 → 모듈화)   ※ 선택
Phase 5  UX·접근성·PWA                      ※ 선택
Phase 6  교육·제품 결정 (형평성·승인 통합·농장 재구성)  ※ 사용자 결정 필요
```

**순서를 어기면 벌어지는 일**
- Phase 0 생략 → 잘못 만지면 실제 학급 데이터 소실, 되돌릴 스냅샷도 반쪽.
- Phase 1에서 규칙 먼저 배포 → 학생 전원 로그인 불가(개학 후 발견하면 최악).
- Phase 2를 배열 구조 그대로 → 부분 저장을 해도 경합이 남는다.
- Phase 4를 먼저 → 큰 리팩토링 후 보안·저장 수술 = 회귀 원인 구분 불가.
