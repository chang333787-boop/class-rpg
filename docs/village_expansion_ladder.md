```
집 ─── 동네 ─── 마을 ─── 고장 ─── 나라 ─── 세계
 │       │        │        │        │        │
 │       │        │        └─ 여기서 단위가 처음 바뀐다(집 → 마을)
 │       │        └─ 지금 서 있는 칸 (엔진 1~5번)
 └───────┴─ 이미 섰다 (집 판정 · plotOf 구역 · 📣 바람표)
```

| 칸 | ⓐ 세계의 단위 (무엇이 하나로 셈되나) | ⓑ 아이가 놓는 것 | ⓒ 아이가 정하는 것 (정치 층) | ⓓ 보이는 변화 | ⓔ 교과 자리 (확인된 것만) |

## 2. 판정 단위가 어떻게 바뀌나

**지금** ✅확인: 판정은 **집**, 연기는 **사람**. `jobsHomes`·`crowdHomes`·`turnAway` 가 전부 집 단위로 셈하고, 걷는 사람은 `FOLK_CAP = 120` 으로 잘린 표본이다(인구는 120을 넘어도 계속 는다 — `[MAC-POPCAP]`). 이 갈라짐이 엔진의 가장 좋은 결정이고, 사다리 어디서도 흔들면 안 된다.

**사다리를 올라가도 판정 단위는 집으로 남는다.** 마을·고장은 **판정 단위가 아니라 보는 단위**다. 이유:

| 왜 | 만약 마을을 판정 단위로 만들면 |
|---|---|
| 보이지 않는 곱셈·확률 금지 | 마을을 하나로 셈하려면 평균·지수·가중치가 필요하다 → "우리 마을 72점" = 아이가 못 보는 수 |
| 아이가 틀린 것을 배우면 즉시 고침(엔진 스펙 예외 조항) ✅확인 | 남의 저장본이 바뀌어 내 마을 판정이 말없이 달라지면, 아이는 **원인을 읽을 수 없다** |
| 판정 규칙 ≤6 ✅확인 | 마을 단위 판정은 새 판정 규칙이다 — 넣을 자리가 없다(§3-가) |

**그래서 셈의 규칙 한 줄 💭제안: 한 칸 올라갈 때마다 아래 칸의 *개수*로 센다. 나눗셈·평균·가중치는 쓰지 않는다.**

| 칸 | 세는 것 | 화면이 보여 주는 꼴 | 안 쓰는 것 |
|---|---|---|---|
| 동네 | 그 구역 안의 **집 수** | `🏘️🏠🏠 12채` (그림 길이가 채 수를 따라간다) ✅확인(`voiceHouses`) | % · 점수 · 동네 순위 |
| 마을 | 마을 안의 **집 수**(합계) | 목표판 "주민 60명" · 칭호 | 만족도 · 평균 |
| 고장 | 그 일이 일어난 **마을 수** | 마을 카드 25장 중 몇 장에 같은 표시가 있나 | 반 종합 점수 · 1등 마을 |
| 나라 | 그 법이 걸린 **마을 묶음 수** | 테두리 색이 칠해진 카드의 수 | 찬반 막대 · 득표 |
| 세계 | 약속을 지킨 **마을 묶음 수** | 함께 쓰는 것의 그림 한 장 | 국가 지표 · 랭킹 |

**대표값은 딱 하나만 허용한다 💭제안:** 마을 카드의 "돌아선 까닭 셋" — 그건 평균이 아니라 **가장 많이 나온 이유 세 개(개수 순)**다. 이미 `JOB_WHY`·`whyStuck` 이 내는 말 그대로라, 아이가 자기 마을에서 본 문장과 글자가 같다 ✅확인.

**도구 쪽 ✅확인:** `run.mjs` 는 `--save` 한 벌만 읽는다. 여러 마을을 한 번에 재는 `--saves` 는 없다(정치 층 문서 §2도 같은 지적). 고장 칸을 재려면 이게 필요하다.

## 3. 각 칸이 엔진에 요구하는 것

엔진 일곱 칸 ✅확인: ①판 하나=파일 하나 ②규칙 조각(판정 ≤6) ③3D 없이 재기 ④상태→말·그림 한 곳 ⑤컨셉 스킨 ⑥세계가 커지는 축 ⑦누구의 기기에서나.

| 칸 | 요구하는 엔진 칸 | 구체적으로 무엇 | 지금 상태 |
|---|---|---|---|
| 집·동네 | ①②④ | 집 단위 판정 · 구역 · 바람표 | ✅섰다 |
| 마을 | ①②③⑤ | 판 파일 · 판정 상한 · 시뮬 도구 · 스킨 | ✅섰다 — 단 ②가 **꽉 찼다**(아래 가) |
| **고장** | **⑥ + ⑦** | 여러 저장본을 한 화면에 · 인증 · 남의 마을 읽기 | ❌ ⑥ 미착수 · 🔶 ⑦ 저장만 |
| **나라** | ⑥⑦ + ①(`모아보기` 칸) + ②(법 스위치) | 교사 한 번의 확인 · 반 범위 쓰기 규칙 | ❌ |
| **세계** | ⑥⑦ + ②(공유 자원 규칙 한 겹) | 마을 묶음 개념 · 함께 쓰는 것의 셈 | ❌ |

### 지금 엔진 결정 가운데 이 사다리 때문에 바꿔야 할 것

**(가) 판정 규칙 ≤6 상한이 이미 꽉 찼다** ✅확인 — 지금 켜진 판정 규칙은 정확히 **6개**: `manyLibrary` · `jobsHomes` · `jobAway` · `turnAway` · `crowdSkipNight` · `crowdHomes`(`stages.mjs` 실행 결과 "켜진 판정 규칙 6개 (≤6 · 수업 판)").
- 뜻: **정치 층의 법이 판정 규칙이면 단 하나도 못 들어간다.** 사다리 위 칸(공유 자원·법)이 전부 여기에 막힌다.
- 상한을 늘리는 것은 답이 아니다 — 근거가 있다(A11: 아동이 한 결정에서 동시에 저울질하는 것 ≤3, 화면 규칙 5~6) ✅확인.
- 답은 **끄기가 판 설계의 기본 동작이 되는 것**이다. 판 파일 `규칙` 칸으로 끌 수 있다고 README 에 적혀 있지만 ✅확인, **실제로 판정 규칙을 끈 판은 0개다**(town·farm·jobs-short 모두 "기본과 다른 판정 규칙 0개"). 설계상 된다와 해 봤다는 다르다.

**(나) 저장 구조가 마을 하나(`sid`)에 묶여 있다** ✅확인 — localStorage `rpg.village.<sid>[.<stage>]` · 원격 `classRPG_villages/<sid>` · 구역별 문자열 + `meta`. 남의 마을을 보는 길은 `?visit=<sid>` **한 번에 한 마을**이고, 그때는 시간이 멈추고 판도 무시한다.
- 고장·나라·세계 칸은 전부 "여러 마을을 한 화면에"를 요구한다. 25마을의 `plots` 본문을 다 받으면 무겁다(한 구역 가득이 3.5KB ✅확인 — 구역이 여럿이면 마을당 수십 KB).
- 💭제안: **마을 카드 노드**(`classRPG_villages/<sid>/card` — 사진 한 장 + 칭호 + 돌아선 까닭 셋 + 집 수)를 본문과 따로 둔다. 고장 화면은 `card` 만 읽는다. `[MAC-STAGECARD]` 가 이미 같은 재료를 `localStorage` 에 만들고 있으므로 ✅확인, 만드는 코드가 아니라 **두는 자리**의 문제다.
- **왜 지금인가:** 저장 v3(층)가 지금 살아 있는 결정이고 ✅확인(`village_save_v3_proposal.md`), 서버 규칙(`.validate`)이 한 번 게시되면 노드 모양이 거기에 묶인다 — v3 문서 자신의 논리다.

**(다) 엔진 6번의 완료 시험 글이 위험한 쪽을 가리킨다** ✅확인 — 지금 `village_engine_spec.md` 6번 칸의 시험은 **"이웃 마을이 서로의 부족을 채운다"**이다. 이 글대로 만들면 내 집의 필요가 **남의 저장본에 달린다**.

| | 해법 A 💭제안 (추천) | 해법 B (지금 스펙 글) |
|---|---|---|
| 무엇 | 걸어 나감은 **연기**다 — 내 집의 모자람은 그대로 남고 "장 보러 옆 마을까지 갔어요"가 뜬다 | 이웃 시설이 내 필요를 **채운다** |
| 판정 규칙 | **0개 더함** (보기·말 층) | 새 판정 규칙 필요 → ≤6 에 막힘 |
| 아이가 원인을 읽나 | 읽는다 — 내 마을 안에 까닭이 있다 | 못 읽는다 — 친구가 가게를 치우면 내 마을이 말없이 나빠진다 |
| 교과 | 4-1 교류는 **오가는 그림**으로 충분 ✅확인(교과 지도 '주민이 걸어서') | — |

**(라) 판 파일에 넣을 `범위` 칸은 뜻이 다르다** 💭제안 — 정치 층 문서는 판 칸 `범위`(동네/마을/반)를 제안한다 ✅확인. 그런데 규칙은 **언제나 내 마을에만** 걸려야 한다(한 아이가 전체를 결정하는 함정을 그 문서 §6이 이미 막아 두었다). 25명이 같은 `?stage=` 를 열면 같은 시작 땅·같은 규칙은 이미 된다 ✅확인 — 모자란 것은 **결과를 모아 보는 것**뿐이다.
→ 칸 이름을 `범위`가 아니라 **`모아보기`**(`"없음" | "고장" | "묶음"`)로 두면 뜻과 코드가 어긋나지 않는다. 규칙을 넓히는 칸이 아니라 **카드를 몇 장 모아 보는가**의 칸이다.

**(마) 싸게 되는 것(상한과 무관)** ✅확인 — `STAGE_HOOKS` 는 지금 `일닿음%` 하나뿐이다. 훅은 **읽기**라 판정 규칙 수에 들어가지 않는다. 사다리 위 칸이 쓸 훅(동네 수·바람 맨 위 셋·마을 카드 재료)은 상한을 건드리지 않고 늘릴 수 있다. `voiceTable()` 이 이미 그 셈을 한다 ✅확인.

**(바) `rules.json` 분류에 '걸리는 범위'가 없다** ✅확인 — 열한 갈래(판정·바로잡음·때·목표·조작·말·보기·연기·성능·저장·안전) 어디에도 "이 규칙이 마을 전체에 걸리나, 구역에만 걸릴 수 있나"가 없다. 지금은 전부 마을 전체다. 💭제안: 갈래를 늘리지 말고, 법 후보 표시(`법`)를 넣을 때 **걸리는 범위를 같은 줄에** 적는다.

## 4. 정치 층의 사다리를 겹치면

정치 층 문서의 축(학교→지역→나라→세계)을 §1의 칸에 얹는다. 벌·점수는 어디에도 없다 — 결과는 **마을 그림으로만** ✅확인(정치 층 §6).

| 정치 칸 | §1의 칸 | 누가 정하나 | 무엇을 정하나 | 어느 규칙 스위치를 켜나 | 벌·점수 없이 어떻게 드러나나 |
|---|---|---|---|---|---|
| **학교** | 동네 | 모둠(= 동네 하나) | 동네에 걸 약속 하나 | `dayMoveIn` ✅확인(갈래 '때' — **판정에 안 센다**) | 밤 골목이 조용해지고, 저녁에 온 가족이 아침까지 기다린다 |
| **지역 ①** | 마을 | 반 전체가 손들기(교실) | 놓기 표 한 장을 **어느 동네에** | 스위치 없음 — 놓기 거르기만 ✅확인(`canPlace` 훅) | 고른 동네의 🏠줄이 줄고, 나머지 동네 줄은 **그대로 남는다** |
| **지역 ②** | 마을 | 반 전체 | 마을 전체에 걸 법 하나 | `manyLibrary.cap`(판정) · `festLitter`(연기) ✅확인 — **판정 법은 살림 판정을 먼저 꺼야 들어간다**(§3-가) | 법 하나가 동네마다 **다르게** 닿는다 |
| **나라** | 고장 → 나라 | 모둠 대표들(교실) · 게임 입력은 **교사 한 번** | 반 전체에 걸 법 하나 | 같은 스위치 · 다만 **내 마을에만 걸린다**(§3-라) | 같은 법인데 마을 카드마다 바뀐 것이 다르다 |
| **세계** | 세계 | 마을 묶음 사이 | 쉬는 날 · 열어 둘 길 | 공유 자원 한 겹(새로 — 집 수로만 셈 · 확률 0) | 한 묶음만 지키면 **모두의 물빛이 그대로다** |

- 화면에 투표 막대·득표 수·대표 얼굴·공약은 없다 ✅확인(흡수 D · 정치 층 §6). **투표는 교실에서, 게임은 결과만.**
- 법 후보 조건(두 얼굴 — 좋아지는 것과 치르는 것이 함께) ✅확인. 좋은 면만 있는 법은 다 켜면 끝이라 토의가 없다.
- 반 범위는 **교사 확인 뒤에만** ✅확인. 아이 기기는 언제나 제 마을만 바꾼다.

## 5. 순서와 전제 — 무엇이 무엇 없이는 불가능한가

```
[집·동네·마을]  ── 이미 섬
      │
      ├─ 결정 칸(놓기 표)  ← 동네 바람표(있음) ✅
      ├─ 법 켜기(lawApply) ← 틱 도중 규칙 덮기 ✅확인: 지금은 부팅 때만 덮는다
      │                     + 살림 판정 끄기(§3-가)
      └─ [고장] ← ⑦ 인증·진입  +  여러 저장본 읽기(마을 카드 노드)  +  run.mjs --saves
             │
             └─ [나라] ← 고장  +  교사 한 번 확인  +  반 범위 쓰기 규칙(안전 모드)
                    │
                    └─ [세계] ← 나라  +  마을 묶음  +  공유 자원 한 겹
[이어받기·점프(C5)] ← 저장 v3  ── 사다리의 '같은 마을이 커진다'가 여기에 달렸다
```

| 단계 | **최소 한 벌** (이것만 되면 그 칸이 섰다고 말한다) | 막는 전제 |
|---|---|---|
| 동네 | 📣 카드에서 동네를 고르고, 그 동네에만 한 채를 놓을 수 있다 | 없음 — 지금 할 수 있다 |
| 마을(법) | 판 파일이 살림 판정 하나를 **끄고** 법 스위치 하나를 켠 판이 검사를 통과한다 | §3-가 |
| 고장 | 내 마을 카드 한 장과 이웃 마을 카드 한 장이 **한 벽에 나란히** 뜬다(순위 0 · 본문은 안 받는다) | §3-나 · 엔진 ⑦ |
| 나라 | 교사가 한 번 켠 법이 그 반의 마을들에서 **각자** 걸리고, 카드 테두리 색으로 보인다 | 고장 · 서버 쓰기 규칙 |
| 세계 | 두 마을 묶음이 같은 것을 쓰고, 한쪽만 약속을 지키면 그림이 **안 바뀐다** | 나라 · 공유 자원 한 겹 |

**순서의 원칙 하나:** 위 칸을 만들기 전에 아래 칸의 최소 한 벌이 **아이 손에서 한 번 돌아야 한다.** 고장 화면을 먼저 만들면, 카드에 담을 말(칭호·돌아선 까닭)이 아직 실판에서 검증되지 않은 채 25배로 퍼진다.

## 6. 안 할 것

| 안 만든다 | 왜 |
|---|---|
| 국회·행정부·법원 건물, 대표 얼굴, 공약 카드 | 외형만 있는 기관 모형. 결정은 교실에서 — 게임은 "정하는 범위가 넓어지면 생기는 현상"만 ✅확인(정치 층 §4) |
| 세계 지도 · 국경선 · 국기 · 나라 이름 | 규모가 세계로 바뀌면 단위가 집에서 떠난다. 우리 '세계'는 늘 **우리 마을 + 이웃 몇** 이다 |
| 반 종합 점수 · 마을 순위 · 1등 마을 | 20~25개 마을 **전부 유효**가 비전이다 ✅확인. 등급이 아니라 칭호 |
| 마을 평균 만족도 · 지역 발전 지수 | 보이지 않는 곱셈. §2의 '개수로만 센다'를 깬다 |
| 마을 사이 자원 자동 이전 · 무역 가격 · 관세 | 돈 금지 ✅확인. 가격·수출입은 (만든다면) 경제 층 몫이고 지금 엔진에 돈·교환·가격은 **없다** |
| 이웃 시설이 내 필요를 **채우는** 것 | §3-다 — 내 마을 판정이 남의 저장본에 달린다 |
| 확률 재해 · 무작위 사건 | 확률 판정 금지 ✅확인. 사건은 예고·만성형만(A9) |
| 규칙을 한 아이 기기에서 반 전체에 켜기 | 한 아이가 전체를 결정하는 함정 ✅확인(정치 층 §6) |
| 판정 규칙 상한 6을 늘려서 법을 넣기 | 상한은 근거가 있다(A11). 늘리면 아이가 못 따라온다 — 끄고 넣는다 |
| 마을 이름에 실명·학교명 | 공개 저장소 ✅확인. 이름은 아이가 지은 것만 |

## 7. 결론 — 지금 당장 바꿔야 할 것

셋뿐이다. **모두 코드가 아니라 문서 한 줄의 결정**이고, 셋 다 나중에 하면 비싸진다.

| # | 무엇 | 왜 지금인가 | 바뀌는 곳 |
|---|---|---|---|
| **1** | **엔진 6번의 완료 시험 글을 바꾼다.** "이웃 마을이 서로의 부족을 채운다" → **"이웃 마을 주민이 오가는 것이 보이되, 내 집의 판정은 내 마을 안에서만 결정된다"** | 11월 이웃이 이 글을 보고 만들어진다. 지금 글대로 만들면 ①판정 ≤6에 막히고 ②친구가 가게를 치웠을 때 내 마을이 말없이 나빠진다 = **아이가 원인을 못 읽는다**(엔진 스펙이 '즉시 고침'으로 못박은 바로 그 경우) | `village_engine_spec.md` 6번 칸 |
| **2** | **저장 v3에서 '마을 카드' 노드를 본문과 따로 둘지 지금 정한다.** 💭제안 = 둔다(`…/<sid>/card`) | 고장·나라·세계 **세 칸 전부**가 "여러 마을을 한 화면에"를 요구하는데 지금 길은 `?visit=` 한 마을씩뿐이다. 서버 규칙(`.validate`)이 게시되면 노드 모양이 거기 묶인다 — v3 문서 자신의 논리 | `village_save_v3_proposal.md` · (뒤에) `sync.js` |
| **3** | **엔진 2번의 완료 시험에 '끄기'를 더한다.** 지금 시험은 "rules.json이 전부를 분류하고 판 검사가 상한을 지킴"인데, **상한이 이미 정확히 6으로 꽉 찬 상태에서도 이 시험은 통과한다** — 새 수업 판을 한 장도 못 만드는 상태를 숨긴다 | 정치 층의 법(판정)이 전부 여기 막혀 있다. 법 판을 만들 때 발견하면 늦다 | `village_engine_spec.md` 2번 칸 · `stages/README.md` |

**보스가 판단할 것**
1. §3-다의 해법 A(걸어 나감 = 연기)를 받아들일지. 받으면 11월 이웃은 **판정 규칙 0개**로 서고, 엔진 6번이 ⑦(인증)과만 묶인다.
2. 판 칸 이름을 `범위` 로 둘지 `모아보기` 로 둘지(§3-라). 뜻이 다르다 — 전자는 규칙을 넓히는 것처럼 읽힌다.
3. 교과 지도에 4-2 자치·6사08·6사11 줄을 **언제** 더할지. 판 검사가 요구하므로 그 줄이 없으면 나라·세계 판은 파일부터 FAIL 이다.
4. 고장 칸 착수 전에 `run.mjs --saves`(여러 저장본 한 번에)를 먼저 만들지 — 없으면 고장 판을 **측정 없이** 설계하게 된다(체득 4지표를 못 뽑는다).
