## ② sim 조각이 바깥과 주고받는 문
파일을 나눠도 `cells`·`K` 같은 판 데이터는 index.html 쪽에 남는다(놓기·그리기가 같이 쓴다). 그래서 **서로 import 하지 않고, 열 때 한 번 건네준다.**

```js
// index.html (module · 이미 top-level await 를 쓴다)
const simJobs = await import('./sim/jobs.js?v=20260920');
let { jobsTick, joblessHome, jobText, jobCount, jobStats } = simJobs.init({
  판:  { cells, K, idx, inb, cX, cY, W, H, footprint, isRoad, plotOf },      // 들어가는 것 — 판 데이터(읽기)
  셈:  { res, sat, folks, population, roadBeside, roadBFS, VRULES: window.VRULES },
  말:  { simSay, simSound, simDirty, simSparkle },                            // 나오는 것 — 그림·말은 오직 이 문으로(#697)
  고리: { hookable, hookAdd },                                                // 규칙 붙이는 자리(#700~#703)
});
window.__jobs = simJobs.stats;   // 시험 훅은 그대로 이름을 유지
```

| 문 | 무엇 | 규칙 |
|---|---|---|
| 들어가는 것 | 판 데이터(`cells`·`K`·`idx`…) · 셈 상태(`res`·`sat`·`folks`) · 규칙(`VRULES`) · 판 파일이 덮은 값 | sim 은 **읽기만**. 판을 바꾸는 것(`placeAt`·`removeAt`)은 안 건넨다 |
| 나오는 것 | 그 조각의 함수·상태(`jobsTick`…) · `simEmit` 네 문(말·소리·청크·반짝) · 시험 훅 `__*` | 훅 이름·`jobCount`·`jobText` 모양은 **그대로**(연기·도구가 읽는다) |
| 고리 | `hookable`·`hookAdd` | 조각 안에서 제 함수를 `hookable` 로 만들고, 바깥 규칙은 전처럼 `hookAdd('jobsTick', …)` |
- **왜 동적 `import` + `init`인가**: 정적 import 는 파일이 서로를 부르는 고리(circular)가 되고, index.html 의 값들이 아직 만들어지기 전에 돈다. 지금 module 은 이미 `await` 를 쓰므로(판 파일 읽기) 같은 자리에서 한 줄이면 된다.
- 캐시: 새 파일마다 `?v=` 를 붙이고 smoke-test 맵에 더한다(다른 파일 값은 건드리지 않는다 — CLAUDE.md §4.1).
- **시뮬 도구는 한 줄 고쳐야 한다(재 봤다)**: `load.mjs` 는 index.html 의 module 을 떼어 **임시 폴더**에 파일로 떠서 부르는데, 그러면 `./sim/jobs.js` 같은 상대 경로가 `ERR_MODULE_NOT_FOUND` 로 깨진다. 임시 파일을 `village/` 안에 뜨면(`village/_simrun-<pid>.mjs` · 끝나면 지움) 상대 경로도 `?v=` 붙은 이름도 그대로 읽힌다(확인함). 걸음 0에서 이 한 줄을 먼저 고친다.

## ③ 저장 쪽 감싸기(serialize·loadSaved·importText·saveNow) — **빼는 것을 추천**
| | 넣으면 | 빼면(추천) |
|---|---|---|
| 좋은 점 | sim 이 제 상태를 스스로 싣고 내린다(나중에 서버 저장·판 이어받기가 깔끔) | 되돌리기 단위가 작다 · 가장 위험한 곳(아이 저장본)을 마지막까지 안 건드린다 |
| 나쁜 점 | `localStorage`·`SAVE_KEY`·판 키·`sync.js`·`markDirty` 까지 sim 안으로 끌려온다 · 저장 형식(v2)·옛 저장본 호환이 이동과 **한 PR에 섞인다** | 저장 코드가 sim 상태를 문으로 읽어야 한다(`res`·`sat`·`hinfo`·`clock`) — 문 하나 더 |
- **추천: 뺀다.** 까닭 셋:
  1. **운영 위험이 여기에 몰려 있다.** 마을은 운영 중이고, 저장은 아이 마을이 사라질 수 있는 유일한 자리다. 이동(코드 옮기기)과 저장(형식·키)을 한 PR에 섞으면 보스가 되돌릴 단위가 굵어진다.
  2. 저장은 **시뮬만의 것이 아니다.** `serialize` 는 구역 문자열·palette·표지판·칭호·자라기까지 묶는다 — 그림·판·연기 담당의 칸이 함께 있다.
  3. 시뮬 도구의 비교는 **저장본을 넣고 여는 경로**가 전과 같아야 성립한다. 그 경로를 같은 PR에서 바꾸면 '전/후 같음'이 증거가 못 된다.
- 대신 **마지막 걸음**으로 따로 둔다: sim 조각이 `dump()`/`load(데이터)` 를 내놓고, `serialize`·`loadSaved` 는 그것만 부른다(형식은 한 글자도 안 바꾼다).
