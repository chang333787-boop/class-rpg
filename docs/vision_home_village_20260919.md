## 만드는 태도 (사용자 말)
- **창조자 시점**: "아, 이러면 얘네한테 이런 문제가 생기겠다 / 뭐가 필요하겠다 / 지내다 보니 이럴 것 같다."
- 새 요소는 **문제가 보임 → 아이가 해결책을 놓음 → 그것이 다음 문제의 씨앗** 순서로만 들어온다. 횡단보도가 있으면 언젠가 자동차, 휴지통이 없으면 쓰레기 — 하지만 **들어와도 될 때** 들어온다. 넣기 전에 "이걸 부르는 앞 단계가 마을에 이미 있는가"를 묻는다.
- 주민은 늘 불만만 있는 게 아니다. **기본은 평온과 기쁨**, 불만에는 단계와 쉼, 고치면 바로 기뻐한다.
- **시뮬레이션의 단위는 집(세대), 걷는 사람은 표본·연기자.** 규칙은 집 단위 숫자로 판정하고 사람은 그 결과를 연기한다 — 아파트 한 동에 300명이 살아도 계산은 세대 묶음 하나다. (통계로 계산하고, 롤러코스터 타이쿤처럼 보여 준다.)
- 사회 시뮬레이션의 옛 설계는 고집하지 않는다(겨울에 이 엔진 위에서 다시 설계). **가치는 잊지 않는다**: "이렇게 하면 이렇게 되는구나" 체득 · 숫자가 아니라 그림이 바뀌는 피드백 · 복수의 정답 · 깊이는 유지, 표면은 얇게.
- 그림은 **숫자로 지시하지 않는다.** 풍성함은 점의 개수가 아니라 덩어리·색 무리·잎의 쉼에서 온다(멀리서 보이는 것은 색 덩어리의 크기). 시안을 여러 개 받아 사용자 눈으로 고른다. 종류는 많을수록 좋다 — 단 파일 수가 아니라 색 변수·매개변수로 늘린다.
- **태블릿(터치)이 기본**, 마우스는 꽂으면 자동으로 덤. 기물마다 놓는 법이 다르다(롤러코스터 타이쿤 방식 — 층 5개, 바닥 위에 되는 것/안 되는 것).

## 품질 기준 — "교사 사이트에 배포할 수 있는 상용 게임"
> 사용자(2026-09-19): "우리의 목표는 교사 사이트에 배포할 수 있는 상용 게임이다. 퀄리티를 생각하면서 만들자." 우리 반만 쓰는 도구의 잣대가 아니라 **처음 보는 선생님과 아이가 설명 없이 써도 되는가**가 잣대다.

**머지 전에 스스로 묻는 것 (모든 PR)**
1. **미완성을 남기지 않았는가.** "모퉁이는 뒤에", "문은 다음에" 같은 빈틈은 제일 먼저 눈에 띈다. 한 단위(선으로 잇는 물건이면 모퉁이·끝·문까지)를 다 하거나, 아직 화면에 올리지 않는다.
2. **조건이 아니라 결과를 봤는가.** "칸 끝까지 닿는다"가 아니라 **"이게 예쁜가, 그것으로 보이는가"**. 그림은 게임 화면 그대로, 가까이·기본 확대·멀리 세 거리에서 본다. 새 종류의 그림은 시안을 여러 개 받아 사용자가 고른 뒤 들어간다.
3. **처음 보는 아이가 막히지 않는가.** 크롬북 1366×610 과 태블릿 터치에서 직접 눌러 본다. 단추 44px, 글자 읽힘, 못 하는 이유는 아이 말로, 실수는 되돌릴 수 있게(비싼 것·사람 사는 집은 스쳐서 사라지지 않게).
4. **가끔 실패하는 것은 실패다.** 세 번 돌려 한 번 떨어지는 검사는 고쳐질 때까지 열린 문제다 — 검사가 틀렸든 코드가 틀렸든 원인을 밝힌다. 조용히 죽은 검사를 통과로 읽지 않는다(줄 수·끝 표식).
5. **무거워지지 않았는가.** 성능 예산 전/후 숫자. 저사양 크롬북이 기준이다.
6. **아이의 것을 지켰는가.** 이미 지어 놓은 마당·마을·가진 물건·골드가 업데이트로 바뀌거나 사라지지 않는다. 저장 구조를 건드리면 옛 저장본·옛 캐시 기기까지 시험한다.
7. **남에게 보여도 되는가.** 문서·주석·화면에 학생 이름·학교명이 없다. 외부 그림·코드를 베끼지 않았다(빌리는 것은 구조와 원리).

**다른 학교에 내놓기 전에 풀려야 하는 것**(보류 문서 #422 가 목록): 인증과 규칙 · 통째 저장으로 골드가 되돌아가는 문제(#288) · 학급·교사 여럿 · 개인정보 처리방침과 보호자 동의 · 학생 삭제와 사진 파기 · 오류 수집 · 그림·글꼴 출처 기록. **매주 기초 하나**로 갚는다.

## 일하는 방식
- 보스 1(검증·머지·결정) + 게임마다 디자인 담당·프로그램 담당 + 조언자(사회시뮬 세션 — 보스에게만 조언, 논거로 채택, 쳐낼 건 쳐낸다).
- 구역을 나눈다(같은 파일을 둘이 만지면 줄 단위로). 스택 PR 금지, `student.js` 를 고치는 PR 은 한 번에 하나. 작업 세션은 머지하지 않는다.
- 보스는 **합쳐서 한 번에 시험하고**(충돌·precheck·하네스·실화면 콘솔 오류 0), 머지한 결과가 시험본과 같은지 확인한다. 하네스는 **줄 수와 끝 표식**을 본다(조용히 죽은 것을 통과로 읽지 않게). 실화면 주소에는 캐시 무효화 값.
- 주말에 개발 브랜치에서 짓는다 → 월요일 학교와 맞춘다 → 검증된 것만 아이들에게 → **아이들 반응을 기록으로 되돌린다**(지금 가장 비어 있는 고리).

## 가장 큰 위험 셋
1. **마을 원본이 두 곳**(학교 PC 폴더 ↔ 저장소). 월요일에 "원본은 저장소"로 정리한다 — 그 전까지 맥북 작업은 새 블록 위주·고친 줄 지도.
2. **`student.js` 13,000줄 한 파일.** 리팩토링 세션은 따로 없다 — 고치면서 덜어 낸다. 첫 로딩에서 늦게 불러도 되는 것부터.
3. **공개 저장소.** 실학생 이름이 한 번 새어 나갔다(#424 로 가림, git 이력에는 남음 — 조용한 때 정리). 문서·주석에 이름·학교명을 쓰지 않는다.
