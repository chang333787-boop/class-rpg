## 한 줄
**자르기 전에 먼저 '통째로 싣기'가 된다 — 이미 재 봤다.** index.html 을 한 줄도 안 고치고, node 에서 module 을 그대로 불러 three 는 진짜(계산만) · 렌더러와 DOM 은 가짜로 두면 저장본을 불러 N일 돌릴 수 있고, **브라우저와 같은 값**이 나온다. 그래서 순서는 ① 통째로 싣는 시뮬 도구 → ② 판 정의 파일(기본 판 = 지금 마을, 달라지는 것 0) → ③ 시뮬이 그림을 부르는 곳을 '알림 한 줄'로 모으기 → ④ 그다음에야 파일 자르기. ④ 는 위험이 커서 ①~③ 이 돌아간 뒤 따로 정한다.

## 이미 잰 것 — '통째로 싣기' 시험 (scratchpad · 커밋 안 함)
- 방법: module 스크립트를 떼어 `import * as THREE` 만 바꾼다(진짜 `vendor/three.module.js` + `WebGLRenderer` 만 가짜). `document`·`canvas` 등은 무엇을 불러도 빈 값을 돌려주는 Proxy로 둔다. `localStorage` 는 Map으로 대신해 저장본 한 벌을 `rpg.village.guest` 에 넣는다. `Math.random` 은 시드를 받는 난수로 바꾼다. 네트워크는 없다(`fetch` 는 실패를 돌려줌 · sync.js 안 부름).
- 고친 것은 가짜 전역 세 개뿐이다(`navigator`·`localStorage` 정의, `WebGL2RenderingContext`). index.html 은 **0줄**.

| 판 | 브라우저(`__tickBench`) | node(가짜 그림) | 걸린 시간(node) |
|---|---|---|---|
| pop167 · 이틀 | 먼 집 56 · 인구 173→184 · 층 74·3·4 · 일자리 26/26 | **같다** (56 · 173→184 · 74·3·4 · 26/26) | 불러오기 0.14초 · 하루(1800틱) 약 2초 |

- 시드를 고정하면 **같은 결과가 되풀이된다**. 브라우저는 시드가 없어 한 번 잰 값이 표본 하나다 → 앞으로 조사 표는 "시드 5개 평균·범위"로 뽑을 수 있다(지금까지 브라우저 표는 한 번씩 잰 값이었다).
- 지금까지 조사 한 번에 Playwright로 판을 열고 닫으며 수 분 걸리던 것이, node 한 줄로 판 3개 × 시드 5개 × 이틀을 1분 안에 돈다.

## (a) 시뮬 층 — 3D 없이 돌리기
**1단계(작은 PR, index.html 0줄): `scripts/village-sim/run.mjs`**
```
node scripts/village-sim/run.mjs --save village/_t/pop167.json --days 2 --seeds 1-5 \
     --rules 'jobsHomes.on=false,jobAway.on=false' --do 'put shop 136 145 0' --table
```
- 나오는 표: 날마다 인구 · 층 · 필요별 없는 집 · 붐벼요 · 일할 곳 먼 집 · 찬 자리/일자리 · 돌아선 수 · 이룬 목표 · 틱 평균/최대 ms. 읽는 것은 **이미 있는 시험 훅**(`__pop/__jobs/__goals/__crowd/__houseText/__snapshot`)뿐이다.
- `--rules` 는 불러온 뒤 `window.VRULES` 를 덮는다. 이렇게 켜기 전/후를 한 판·같은 시드로 비교한다(오늘 #676 표가 이 모양이었다).
- `--do` 는 `__put/__del` 로 '아이의 한 수'를 둔다.
- 시험 틀 자리: `scripts/village-paint/test.mjs` 곁. `verify-safety` 와는 따로 둔다(느리다).
- **운영 안전**: 네트워크를 쓰지 않는다. sync.js 도 부르지 않는다(module 만 싣는다). sid 는 늘 guest.

**한계(1단계에서 받아들이는 것)**
| 한계 | 뜻 | 대처 |
|---|---|---|
| 그리기 코드도 **돈다**(빈 값을 받으며) | 시간 대부분이 가짜 그림·연기에 쓰인다 → 하루 2초 | 쓸 만하다. 빠르게 하려면 ③ 뒤에 `#off=` 로 연기·그림 고리를 끈다 |
| 카메라·화면을 읽는 규칙 | 예: 문 방향(#663 `doorRotCands` 가 카메라 쪽 면을 고른다). 가짜 카메라는 늘 0 | 시뮬 결과에는 문 방향만 달라진다. 표에 "문 방향은 기본값"이라 적는다 |
| DOM에 기대는 규칙 | 토스트·칩·목표판은 빈 동작이다. 상태(예: 소식 키)는 남는다 | 셈에는 영향 없음 |

| index.html 이 바뀌면 깨질 수 있다 | 새 전역(예: 새 브라우저 API)을 쓰면 가짜에 없어서 불러오기에서 멈춘다 | 도구가 "LOAD ERR 줄 번호"를 찍는다. 가짜 목록에 한 줄 더 → 2분 일 |

## (b) 판 = 파일 한 장
`village/stages/<id>.json` — 주소 `?stage=<id>` 로 연다(없으면 **지금 마을 그대로** = 기본 판).
```json
{
  "id": "town-jobs", "이름": "일자리가 모자란 마을", "교과": "4-1 경제활동과 지역 간 교류",
  "땅":   { "w": 256, "열린구역": [[4,4],[4,5]], "시작": "<저장본 v2 문자열 또는 null>" },
  "규칙": { "jobsHomes": { "on": true }, "turnAway": { "graceBelow": 10 } },
  "건물": { "쓸것": ["road","avenue","house","well","shop","playground","windmill","green"],
            "열림": [ { "pop": 0, "kinds": ["road","house","well","shop"] }, { "pop": 30, "kinds": ["windmill"] } ] },
  "필요": ["물","장보기","놀이","쉼"],
  "목표": [ { "t": "가게 3채 열기", "셈": "kind", "k": "shop", "n": 3 },
            { "t": "주민 60명", "셈": "pop", "n": 60 },
            { "t": "일할 곳 먼 집 0", "셈": "hook", "훅": "jobsFar", "n": 0, "비교": "<=" } ]
}
```
- **지금 코드의 접점** (판 파일이 덮어쓸 곳):

| 판 칸 | 지금 코드 | 줄(대략) | 바꾸는 법 |
|---|---|---|---|
| 규칙 | `window.VRULES` (스위치 77개 · 파일 곳곳에서 한 줄씩 정의) | 1047~6661 | 판을 **맨 먼저** 읽어 두고, module 끝(부팅 직전)에 `Object.assign` 으로 덮는다 — 한 곳 |
| 건물 | `K` (322~) · `UNLOCKS` (967) · 트레이 | 322, 967 | 트레이·놓기에서 `쓸것` 밖을 거르고, `UNLOCKS` 를 판 값으로 바꾼다 |
| 땅 | `W,H` (hash `w=`) · `openPlot` · `PLOT_PER` | 304, 1388~1449 | 시작 구역과 저장본을 판에서 받는다 |
| 필요 | `NEEDS_BASE` · `LEARN_POP` | 4459 | 판 값 |
| 목표 | `GOALS` — **목표마다 `ok: () => …` 함수** | 4773~4900 | **여기가 제일 큰 일.** 판 파일은 함수를 못 담는다 → `셈` 세 가지(kind/pop/hook)로 표현한다. 지금 목표도 이 꼴로 옮길 수 있는지 먼저 센다. 못 옮기는 것은 `hook` 이름으로 남긴다 |
| 저장 | `SAVE_KEY = 'rpg.village.' + SID` | 7935 | 판마다 키를 따로 쓴다(`rpg.village.<sid>.<stage>`). **기본 판은 지금 키 그대로** — 아이들 저장본과 운영 DB는 안 건드린다 |

- 기본 판(`?stage` 없음)은 지금 값을 한 파일로 **옮겨 적은 것**이어야 한다. 확인: 기본 판과 지금 판의 (a) 도구 표가 같은 시드에서 같게 나오는지 본다 — 이것이 ② PR 의 검사다.
- 운영 DB(sync.js)는 기본 판만 올린다. 다른 판은 1차에서 **로컬 저장만** 한다(규칙·DB 구조 변경 없음).

### 자를 때 가장 큰 위험 — '감싸기' 꼴
이 파일의 규칙은 대부분 **`const f0 = f; f = function(){ … f0 … }` 로 앞 함수를 다시 대입해서** 붙었다(센 것만 74곳 · 스위치 77개). **ES 모듈로 나누면 import 한 이름은 다시 대입할 수 없다** → 파일을 그냥 자르면 이 감싸기가 전부 깨진다(SyntaxError 가 아니라 실행 중 TypeError이거나, 더 나쁘게는 감싸기가 조용히 빠진다).
→ 자르기 전에 **감싸기를 '고리 목록'으로** 바꾸는 단계가 먼저 필요하다: `HOOKS.awayLacks.push(fn)`처럼. 74곳을 한 번에 바꾸는 것은 고위험(CLAUDE.md §6의 '대규모 전환'과 같은 급)이다 → 새 규칙부터 고리 목록 꼴로 쓰고, 옛 감싸기는 자를 구간에 걸린 것만 옮긴다.
