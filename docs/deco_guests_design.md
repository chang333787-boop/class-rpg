## 0. 먼저 — 지금 저장이 어떻게 되나 (코드에서 확인)
| 사실 | 어디 | 이 설계에 주는 뜻 |
|---|---|---|
| 꾸미기 저장 = `students/<id>` **통째 set** | `gamedata.js` `saveStudent` | 새 필드는 따로 쓰기 경로 없이 기존 저장에 실려 간다. 쓰기 수가 늘지 않게 **언제 더럽히나**만 정하면 된다 |

## 1. 새 필드 — `student.decoLife` (없어도 된다)
```js
decoLife: {
  v: 1,                         // 모양 번호. 모르는 번호면 읽기만 하고 쓰지 않는다
  c: 12,                        // 다음 동물 번호(u = 'a' + c) — 늘기만 한다
  a: {                          // 동물 한 마리(또는 무리 한 자리)마다 한 줄
    a7: { k: 'd_y53', r: 5, c: 9, m: 20355, h: 9, d: 20358, n: 2 },
    //     k 종류(장식 id) · r·c(·sp) 선 자리(공간 1 이면 sp 없음) · m 처음 만난 날 · h 하트 수(늘기만) · d 마지막으로 하트를 준 날
    //     n 이름 번호 = 디자인 목록 번호 1~40(#969 · 1~25 동물별 다섯 · 26~40 공통) · 없거나 0 이면 이름 없음
    //     gd 선물을 받은 날(그날 선물이 땅에서 사라진다 · DECO-LIFE-3)
  },
  s: { frog: 20351, magpie: 20356 },   // 손님 처음 만난 날 — 13칸이 최대. 스티커 = 이 키가 있음
  g: { egg: 3, wool: 1, acorn: 2 },    // 받은 선물 수 — 늘기만(팔기 · 쓰기 없음)
  p: 4                                 // 사진 조각(여섯이면 한 장 — 장 수 = floor(p/6))
}
```
- **날 = 한국 날짜의 일 번호** `Math.floor((Date.now() + 9*3600000) / 86400000)` — 문자열보다 짧고, 코드의 다른 KST 날짜와 같은 기준.
- 친구 줄과 동물 자리는 **선 자리**(`r` · `c` · `sp` = 자리 객체의 `row` · `col` · `sp`)와 종류(`k` = `id`)로 짝짓는다. 자리 객체에는 아무것도 달지 않는다.
  - 친구 줄은 처음 쓰다듬기 · 이름 고르기 때 생긴다. 그 전의 동물은 지금과 글자 하나 다르지 않다.
- **하트는 '한 자리'에 준다.** 닭 3마리(d_y39) · 오리 가족(d_y32)처럼 그림 한 장이 무리인 것은 무리가 한 친구다(카드 하나 · 이름 하나).

## 2. 동물의 '누구' — 쉬는 친구가 돌아온다
옮기기가 '치우기 + 놓기'라, 자리만 보면 치운 순간 그 친구가 사라진다. 그래서:
1. **치우면** 자리 객체만 빠지고 `a.a7` 줄은 남는다 = **쉬는 친구**(가방 속). 치울 때 쓰기 0.
2. 자리 하나의 친구는: ① 그 자리(같은 종류 · 같은 `r·c·sp`)에 선 친구 ② 없으면 같은 종류의 **쉬는 친구**(지금 어느 자리에도 안 선) 중 **하트가 가장 많은 친구**(같으면 먼저 만난 = 번호가 작은) ③ 없으면 새 친구.
   - 옮기기처럼 보인다 — 이름 · 하트 그대로. 짝이 바뀐 친구는 다음 쓰다듬기 때 선 자리만 고쳐 적는다(잎 쓰기).
   - (처음 안의 '가장 최근에 쉬러 간 친구'는 Firebase 가 키를 차례로 돌려줘 '줄 순서'가 없어서 뺐다.)
3. **↩ 로 되살린 자리**는 같은 자리 · 같은 종류라 ①로 그 친구가 그대로 선다. 한 친구가 두 자리에 서는 일은 짝짓기 규칙상 없다.
4. **가진 수보다 친구가 많으면**(선생님 초기화 · 장식 회수 등) 넘치는 친구는 **잠든 친구** — 지우지 않고 보이지도 않는다. 다시 가지면 깨어난다. 하트는 줄지 않는다는 원칙.
5. 친구 줄은 **종류당 가진 수만큼**만 늘어난다(쉬는 친구가 있으면 새 줄을 만들지 않으므로). 그래서 `a` 는 학생이 가진 동물 수를 넘지 않는다.

## 3. 친해지기 — 하트 · 단계
- **하트는 하루에 한 마리당 최대 +1**: 그날 처음 쓰다듬을 때(`d !== 오늘`) `h += 1 · d = 오늘` → **부분 쓰기 한 번**(§6-1 · 통째 저장 아님). 같은 날 더 쓰다듬으면 💗 반응만(저장 0).
- **하트는 줄지 않는다.** 안 와도 벌 없음.
- 단계는 하트 수로 **그때 계산**한다(저장하지 않음):

  | 단계 | 이름(그림) | 하트 문턱(제안 — §8 결정 ①) |
  |---|---|---|
  | 1 | 처음 만남 `friend_stage1` | 0 |
  | 2 | 알아봄 `friend_stage2` | 3 |
  | 3 | 친구 `friend_stage3` | 8 |
  | 4 | 단짝 `friend_stage4` | 15 |
  | 5 | 가족 `friend_stage5` | 25 |
- 카드의 하트 다섯 칸(`heart_full` · `heart_empty`) = **다음 단계까지 남은 몫**을 다섯으로 나눠 보인다(5단계면 다섯 칸 다 참).
- 단계가 오르는 날: `g.sticker += 1` + 알림 한 번(같은 부분 쓰기에 실림).

## 4. 손님 · 선물 — 저장은 '처음'과 '수'만
- **손님은 계산한다.** 놓은 것 · 바닥 · 계절 · 때(낮/저녁/밤)를 보고 그날 올 수 있는 손님을 고른다 — 표는 디자인 문서 그대로. 저장 0.
  - 한 번에 최대 둘. 누가 오나 = `hash(학생 id, 날)` 로 고정 → 같은 날 다시 열어도 같은 손님(무작위로 바뀌지 않음).
  - **처음 본 날만** `s[손님] = 오늘` → 스티커 · 알림(부분 쓰기). 13종 × 한 번 = 평생 쓰기 13번이 끝.
- **선물은 모으기만 한다.** 골드 · 팔기 · 쓰기 0. 가격표 · 경제 값을 건드리지 않는다.
  - 두고 가는 것: 2단계 이상 친구가 그날 `hash(u, 날)` 로 정해진 날에 선물 하나(닭 → egg · 오리 → duck_egg · 양 → wool · 강아지 · 고양이는 디자인 후보가 정해지면). 선 자리 오른쪽 옆 칸에 놓인다. 누르면 `a/<u>/gd = 오늘` + `g[선물]` 을 **서버에서 +1**(`ServerValue.increment` · §6-1) — 한 update.
  - 안 누른 선물은 그날이 지나면 없어진다(쌓여서 문서가 커지지 않게). **벌이 아니다** — 받은 수는 줄지 않는다.
  - 손님 선물(acorn · feather)과 사진 조각도 같은 방식.

## 5. 무게 — 학생당 2KB 안
| 부분 | 한 줄 | 최대 | 합 |
|---|---|---|---|
| `a` 친구 | `"a7":{"k":"d_y53","r":5,"c":9,"m":20355,"h":9,"d":20358,"n":2}` ≈ 62B | 가진 동물 수(보통 3~10 · 넉넉히 20) | ≤ 1.3KB |
| `s` 손님 | `"frog":20351` ≈ 13B | 13 | ≈ 170B |
| `g` 선물 | `"egg":3` ≈ 9B | 9 | ≈ 80B |
- 반 30명 모두 가득 차도 루트에 약 45KB 늘어난다. deco-perf ⑤(학생 문서 크기)에 '동물 20 · 손님 13 · 선물 9' 줄을 더해 PR 마다 잰다.

## 6. 옛 저장본 · 이상한 값
- `decoLife` 가 **없으면 빈 것**으로 읽고, **필드를 만들지 않는다**(`_yardFloorGet` 과 같은 방식) — 쓰다듬기 · 이름 · 손님 중 하나가 처음 일어날 때 만든다. 그래서 **아무것도 안 한 아이의 문서는 한 글자도 안 바뀐다.**
- 읽을 때 모양이 틀린 값(배열 · 숫자 · null · 음수 하트 · 모르는 선물 이름)은 **그 줄만 없는 셈** 치고 지우지 않는다. 모르는 키는 그대로 두고 저장한다(뒤 판이 더한 것을 앞 판이 지우지 않게).
- `v` 가 모르는 번호면 **읽기 전용**(보이기만 하고 쓰지 않음).
- 옛 판은 `decoLife` 를 모르는 필드로 두고 통째 저장 때 그대로 되쓴다(학생 객체를 통째 set). 자리 객체는 바뀐 것이 없다.

## 6-1. 동기화 — 골드 유실과 같은 길을 막는다
골드 유실은 두 길이었다: **M1** 저장 중 서버 값이 `CUR` 을 옛 캐시로 바꿔 치움 · **M2** 통째 저장 뒤 0.5초 동안 남의 변경을 무시해, 다음 통째 저장이 교사가 준 골드를 덮음(#288 열림). 그래서:

| 무엇 | 어떻게 쓰나 | 왜 |
|---|---|---|
| 하트 | `students/<id>` 아래 `update({ 'decoLife/a/a7/h': increment(1), 'decoLife/a/a7/d': 오늘 })` | 통째 저장을 안 부른다 → `_saving` 창(M2)을 열지 않아 **교사 골드를 덮을 기회가 0 늘어난다.** 더하기는 서버가 해서 두 기기가 겹쳐도 합이 맞다 |
| 선물 · 사진 조각 · 스티커 수 | `update({ 'decoLife/g/egg': increment(1) })` | 같은 까닭. 골드 하루 기록(goldDaily)과 같은 방식 |
| 손님 처음 만난 날 · 이름 번호 · 새 친구 줄 · 선 자리 | 그 잎만 `update()` | 다른 칸(골드 · 가방 · 장식)을 건드리지 않는다 |
- 화면은 `CUR.decoLife` 를 같이 고쳐 바로 보이고, 서버 에코가 와서 `CUR` 이 바뀌어도 같은 값이다.
- **잰 것**(`scripts/unit/deco-life-sync-sim.mjs` · 골드 유실 재현기 틀 · 실제 gamedata.js DB + admin.js approveSingle + student.js `_life*` · 무작위 200판 × 학생 12일 쓰다듬기 + 교사 승인 10G × 10):

  | | 잎 쓰기(지금 코드) | 통째 저장(대조군) |
  |---|---|---|
  | 압축판(15초에 몰아) — 골드 유실 | **0판** | 177판 · 5,640G |
  | 실제 간격판(하루 1분 · 승인 12분에 흩어짐) — 골드 유실 | **0판** | 15판 · 150G |
  | 실제 간격판 — 하트 되돌림 | 17판 · 18/2400(0.75%) | 11판 · 12/2400 |
- **교사 기기의 통째 저장(#288 미해결)이 겹칠 때** 무엇을 잃나:
  - 하트: 교사 기기가 옛 사본으로 학생 문서를 덮으면 그 하트가 되돌아간다(위 표 0.75%). 그날 안이면 `d` 도 돌아가 다시 쓰다듬어 되찾지만, 지난날 것은 못 되찾는다.
    **지금 장식 놓기 · 바닥 칠하기도 같은 길에 있다**(교사 통째 저장이 학생 문서를 덮음 = #288). 하트만 따로 0 으로 만들려면 §8 결정 ⑥.
  - 손님: '처음' 기록이 빠지면 다음에 볼 때 다시 '처음'으로 저장된다.
  - 선물 수: 그 순간 누른 1개가 빠질 수 있다.
  - 하트 · 선물 수의 되돌림이 '줄지 않는다' 원칙의 **예외**다 — #288 이 닫히거나 결정 ⑥ 이면 없어진다.
- 처음에 새 노드(`decoLife/<id>`)로 빼지 않은 까닭: Firebase 규칙 확인이 필요하고, 학생 기기 노드 목록(`STUDENT_KNOWN` · gamedata.js — 학교와 나눠 쓰는 파일)도 바뀐다. `students/<id>` 안이면 규칙 · 백업 · 노드 목록이 그대로다. 잰 뒤 다시 묻는다(§8 결정 ⑥).
- 같은 학생이 두 기기에서 동시에 그날 첫 쓰다듬기를 하면 +2 가 될 수 있다(드묾) — 허용한다(줄지 않는 쪽).
- 친구 구경은 쓰기 0(§7).

## 6-2. 교사 화면 · 다른 화면 영향
- `admin.js` · `kiosk.js` 는 `decoLife` 를 읽지도 그리지도 않는다 → **화면 변화 0**. 교사 쪽 통째 저장은 캐시에 있던 `decoLife` 를 그대로 되쓴다(학생 객체를 통째 set — 모르는 필드를 버리지 않음).
- 교사 '수치 초기화' 두 곳은 꾸미기 필드만 비운다 → `decoLife` 한 줄이 필요(§8 결정 ③ · admin 은 내 구역 밖).
- 자동 백업: `students` 노드 안이라 **이미 들어간다**(백업 목록 수정 0).
- 교사 · 키오스크는 루트 전체를 받는다 → 반 전체가 가득 차도 +45KB(§5).
- 교사가 동물 이름 · 하트를 보는 화면은 없다(필요하면 나중에 읽기 전용으로).

## 7. 친구 마당 구경
- 친구 문서는 이미 루트에서 받아 와 있다 → 이름표 · 단계 배지 · 만난 손님은 **읽기만**. 구경에서 쓰다듬으면 💗 반응만 — **친구 문서에 쓰지 않는다**(하트 0 · 저장 0).
- 이름이 고르기 목록이라 친구가 보아도 안전하다(디자인 원칙 — 자유 입력 없음).
