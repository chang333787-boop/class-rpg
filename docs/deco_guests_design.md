# 손님 · 친해지기 · 작은 선물 — 저장 설계 (2026-09-24)

> 쓴 사람: 꾸미기 프로그램 담당. 그림과 표는 디자인의 `docs/deco_guests_art_20260924.md`(#949) — 이 문서는 **같은 이름**을 쓴다.
> 규칙(보스): 저장 구조를 바꾸는 일은 **설계 한 장이 먼저**, 옛 저장본은 그대로 열려야 한다. 이 문서가 승인되기 전에는 코드 0.
> 이 문서가 바꾸는 것: 학생 문서에 **선택 필드 하나(`decoLife`)** + 동물 자리 객체에 **선택 키 하나(`u`)**. 루트 구조 · 다른 필드 · 가격/골드 · gamedata 는 그대로.

## 0. 먼저 — 지금 저장이 어떻게 되나 (코드에서 확인)
| 사실 | 어디 | 이 설계에 주는 뜻 |
|---|---|---|
| 꾸미기 저장 = `students/<id>` **통째 set** | `gamedata.js` `saveStudent` | 새 필드는 따로 쓰기 경로 없이 기존 저장에 실려 간다. 쓰기 수가 늘지 않게 **언제 더럽히나**만 정하면 된다 |
| 꾸미기 저장은 한 번 모아 보낸다(`decoDirty` → `DECO_SAVE_MS` 뒤 1번) | `student.js` `decoDirty` | 하트 · 손님 · 선물도 이 한 줄로만 저장한다 |
| 모든 기기가 **루트 전체**를 `on('value')` 로 받는다 | `DB.init` | 문서가 커지면 **반 전체가 그 값을 치른다** → 학생당 2KB 안(§5) |
| 배열은 `_normalizeArrays` 가 **정해진 필드만** 되살린다(`houseDecorations` 등) | `gamedata.js` | 새 필드엔 **배열을 쓰지 않는다**. 전부 글자 키 객체 |
| Firebase 는 키가 거의 정수인 객체를 배열로 바꿔 돌려준다 | Firebase 동작 | 키는 **글자로 시작**(`a7`, `frog`) — 숫자 키 금지 |
| 선생님 '수치 초기화'는 꾸미기 필드를 비운다(`houseDecorations` · `yardFloor` · `yardFloors` · `indoor`) | `admin.js:784` · `:803` | `decoLife` 도 비워야 짝이 맞다 — **admin 은 내 구역 밖**(§8 결정 ③) |
| 옮기기는 따로 없다 — **치우기 + 다시 놓기**, ↩ 는 자리 객체 사본을 되살린다 | `_decoUndoOne` | 동물의 '누구'를 자리 객체에만 달면 옮길 때 잃는다 → §2 '쉬는 친구' 규칙 |

## 1. 새 필드 — `student.decoLife` (없어도 된다)
```js
decoLife: {
  v: 1,                         // 모양 번호. 모르는 번호면 읽기만 하고 쓰지 않는다
  c: 12,                        // 다음 동물 번호(u = 'a' + c) — 늘기만 한다
  a: {                          // 동물 한 마리(또는 무리 한 자리)마다 한 줄
    a7: { k: 'd_y53', m: 20355, h: 9, d: 20358, n: 2 },
    //     k 종류(장식 id) · m 처음 만난 날 · h 하트 수(늘기만) · d 마지막으로 하트를 준 날 · n 이름 번호(없으면 이름 없음)
  },
  s: { frog: 20351, magpie: 20356 },   // 손님 처음 만난 날 — 13칸이 최대. 스티커 = 이 키가 있음
  g: { egg: 3, wool: 1, acorn: 2 },    // 받은 선물 수 — 늘기만(팔기 · 쓰기 없음)
  p: 4                                 // 사진 조각(여섯이면 한 장 — 장 수 = floor(p/6))
}
```
- **날 = 한국 날짜의 일 번호** `Math.floor((Date.now() + 9*3600000) / 86400000)` — 문자열보다 짧고, 코드의 다른 KST 날짜와 같은 기준.
- 동물 자리 객체에는 **처음 필요할 때만** `u: 'a7'` 를 단다: `{ id: 'd_y53', area: 'yard', row: 5, col: 9, u: 'a7' }`.
  - 필요할 때 = 처음 쓰다듬기 · 이름 고르기. 그 전의 동물은 지금과 글자 하나 다르지 않다.
- **하트는 '한 자리'에 준다.** 닭 3마리(d_y39) · 오리 가족(d_y32)처럼 그림 한 장이 무리인 것은 무리가 한 친구다(카드 하나 · 이름 하나).

## 2. 동물의 '누구' — 쉬는 친구가 돌아온다
옮기기가 '치우기 + 놓기'라, 자리 객체만 보면 치운 순간 그 친구가 사라진다. 그래서:
1. **치우면** 자리 객체만 빠지고 `a.a7` 줄은 남는다 = **쉬는 친구**(가방 속).
2. **같은 종류를 놓으면** 그 종류의 쉬는 친구 중 **가장 최근에 쉬러 간 친구**가 그 자리로 돌아온다(`u` 를 붙여 준다). 옮기기처럼 보인다 — 이름 · 하트 그대로.
   - '가장 최근' = 치울 때 적는 값이 아니라 **줄 순서**로 정한다(치울 때 쓰기를 늘리지 않으려고). 줄이 없으면 새 친구.
3. **↩ 로 되살린 자리**에 `u` 가 있는데 그 `u` 를 이미 다른 자리가 쓰고 있으면, 되살린 쪽의 `u` 를 떼고 2번 규칙으로 다시 짝을 찾는다(한 친구가 두 자리에 서지 않는다).
4. **가진 수보다 친구가 많으면**(선생님 초기화 · 장식 회수 등) 넘치는 친구는 **잠든 친구** — 지우지 않고 보이지도 않는다. 다시 가지면 깨어난다. 하트는 줄지 않는다는 원칙.
5. 친구 줄은 **종류당 가진 수만큼**만 늘어난다(쉬는 친구가 있으면 새 줄을 만들지 않으므로). 그래서 `a` 는 학생이 가진 동물 수를 넘지 않는다.

## 3. 친해지기 — 하트 · 단계
- **하트는 하루에 한 마리당 최대 +1**: 그날 처음 쓰다듬을 때(`d !== 오늘`) `h += 1 · d = 오늘` → `decoDirty()` 한 번. 같은 날 더 쓰다듬으면 💗 반응만(저장 0).
- **하트는 줄지 않는다.** 안 와도 벌 없음.
- 단계는 하트 수로 **그때 계산**한다(저장하지 않음):

  | 단계 | 이름(그림) | 하트 문턱(제안 — §8 결정 ①) |
  |---|---|---|
  | 1 | 처음 만남 `friend_stage1` | 0 |
  | 2 | 알아봄 `friend_stage2` | 3 |
  | 3 | 친구 `friend_stage3` | 8 |
  | 4 | 단짝 `friend_stage4` | 15 |
  | 5 | 가족 `friend_stage5` | 25 |
- 카드의 하트 다섯 칸(`heart_full` · `heart_empty`) = **다음 단계까지 남은 몫**을 다섯으로 나눠 보인다(5단계면 다섯 칸 다 참).
- 단계가 오르는 날: `g.sticker += 1` + 알림 한 번(같은 `decoDirty` 에 실림).

## 4. 손님 · 선물 — 저장은 '처음'과 '수'만
- **손님은 계산한다.** 놓은 것 · 바닥 · 계절 · 때(낮/저녁/밤)를 보고 그날 올 수 있는 손님을 고른다 — 표는 디자인 문서 그대로. 저장 0.
  - 한 번에 최대 둘. 누가 오나 = `hash(학생 id, 날)` 로 고정 → 같은 날 다시 열어도 같은 손님(무작위로 바뀌지 않음).
  - **처음 본 날만** `s[손님] = 오늘` → 스티커 · 알림. 13종 × 한 번 = 평생 쓰기 13번이 끝.
- **선물은 모으기만 한다.** 골드 · 팔기 · 쓰기 0. 가격표 · 경제 값을 건드리지 않는다.
  - 두고 가는 것: 2단계 이상 친구가 그날 `hash(u, 날)` 로 정해진 날에 선물 하나(닭 → egg · 오리 → duck_egg · 양 → wool …). 누르면 `g[선물] += 1` → `decoDirty()`.
  - 안 누른 선물은 그날이 지나면 없어진다(쌓여서 문서가 커지지 않게). **벌이 아니다** — 받은 수는 줄지 않는다.
  - 손님 선물(acorn · feather)과 사진 조각도 같은 방식.

## 5. 무게 — 학생당 2KB 안
| 부분 | 한 줄 | 최대 | 합 |
|---|---|---|---|
| `a` 친구 | `"a7":{"k":"d_y53","m":20355,"h":9,"d":20358,"n":2}` ≈ 50B | 가진 동물 수(보통 3~10 · 넉넉히 20) | ≤ 1KB |
| `s` 손님 | `"frog":20351` ≈ 13B | 13 | ≈ 170B |
| `g` 선물 | `"egg":3` ≈ 9B | 9 | ≈ 80B |
| `u` 자리 키 | `,"u":"a7"` ≈ 9B | 동물 자리 수 | ≤ 180B |
- 반 30명 모두 가득 차도 루트에 약 45KB 늘어난다. deco-perf ⑤(학생 문서 크기)에 '동물 20 · 손님 13 · 선물 9' 줄을 더해 PR 마다 잰다.

## 6. 옛 저장본 · 이상한 값
- `decoLife` 가 **없으면 빈 것**으로 읽고, **필드를 만들지 않는다**(`_yardFloorGet` 과 같은 방식) — 쓰다듬기 · 이름 · 손님 중 하나가 처음 일어날 때 만든다. 그래서 **아무것도 안 한 아이의 문서는 한 글자도 안 바뀐다.**
- 읽을 때 모양이 틀린 값(배열 · 숫자 · null · 음수 하트 · 모르는 선물 이름)은 **그 줄만 없는 셈** 치고 지우지 않는다. 모르는 키는 그대로 두고 저장한다(뒤 판이 더한 것을 앞 판이 지우지 않게).
- `v` 가 모르는 번호면 **읽기 전용**(보이기만 하고 쓰지 않음).
- `u` 가 달린 자리를 옛 판이 읽어도 `u` 는 모르는 키라 그대로 저장된다(옛 판은 자리 객체를 `Object.assign` 으로 옮긴다 — 키를 버리지 않음).

## 7. 친구 마당 구경
- 친구 문서는 이미 루트에서 받아 와 있다 → 이름표 · 단계 배지 · 만난 손님은 **읽기만**. 구경에서 쓰다듬으면 💗 반응만 — **친구 문서에 쓰지 않는다**(하트 0 · 저장 0).
- 이름이 고르기 목록이라 친구가 보아도 안전하다(디자인 원칙 — 자유 입력 없음).

## 8. 보스 결정이 필요한 것
1. **하트 문턱**(§3 표 · 제안 0/3/8/15/25): 매일 쓰다듬으면 5단계까지 25일(수업일 약 5주). 더 느리게/빠르게?
2. **선물 빈도**: 2단계 이상 친구가 며칠에 한 번? 제안 — 2단계 3일 · 3단계 2일 · 4단계 이상 매일에 한 번.
3. **선생님 초기화**: `admin.js` 의 두 초기화에 `s.decoLife = {}` 한 줄씩 — admin 은 내 구역 밖이다. 누가 넣을지. 안 넣으면 초기화 뒤에도 친구 줄이 **잠든 친구**로 남는다(§2-4 · 보이지 않음 · 약 1KB).
4. **이름 번호는 목록 순서에 묶인다**: 디자인 목록 40(동물별 25 + 공통 15)은 **뒤에 더하기만**, 빼거나 순서를 바꾸지 않는다. 뺄 이름은 '안 보임' 표시로. 이 규칙을 디자인 문서에도 한 줄 넣을지.
5. **같은 이름 번호 붙이기**(콩이 2)는 저장하지 않고 그때 계산(처음 만난 날 순서) — 괜찮은지.

## 9. 시험(코드 PR 에서)
- unit: `decoLife` 없음 → 읽기 빈 것 · 쓰기 0 · 필드 안 생김 / 이상한 값(배열 · null · 음수) → 그 줄만 무시 · 지우지 않음 / 모르는 키 보존.
- unit: 하루 +1(같은 날 두 번 쓰다듬기 = 하트 1 · 저장 1) · 날 바뀜 → +1 / 단계 계산 경계(2 · 3 · 7 · 8 …).
- unit: 쉬는 친구 — 치우고 같은 종류 놓기 = 같은 `u`(이름 · 하트 그대로) · ↩ 로 되살린 자리의 `u` 겹침 → 떼고 다시 짝 · 가진 수보다 친구가 많을 때 잠든 친구 · **빈 것도 왕복**(친구 0 · 손님 0 · 선물 0 인 채로 저장 → 읽기 → 같음).
- 하네스: 저장 수 — 쓰다듬기 두 번 = 저장 1 · 손님 첫 만남 = 저장 1 · 다시 열기 = 저장 0 · 친구 구경 = 쓰기 0 · 골드 불변.
- deco-perf ⑤: 문서 크기 줄 추가(§5).
