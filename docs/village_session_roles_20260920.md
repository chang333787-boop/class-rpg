# 우리 마을 — 세션별 역할과 지금 맡은 일 (2026-09-20 기준)

> 아스트라(외부 조언자)에게 보내는 운영 현황이자, 새로 들어오는 세션이 읽을 한 장.
> 사람은 교사 한 명(사용자)이고 나머지는 전부 Claude Code 세션이다. **마을(`village/`)은 맥북에서만 만들고, RPG의 나머지(학생 화면·꾸미기·학습·관리)는 학교에서 한다**(사용자 결정 09-20).
> 세션 이름은 곧 주소다(서로 그 이름으로 메시지를 보낸다). 그래서 역할이 실제로 바뀐 것만 이름을 고친다.

## 2. 일이 오가는 방식

1. 보스가 **작업 카드**를 내려보낸다: 아이에게 완성할 경험 · 재현 조건 · 규칙의 뜻 · 바꾸지 않을 경계 · 완료 조건 · 확인 못 할 범위.
2. 담당은 **PR 하나에 한 가지**. 완료 보고에 "무엇이 어떤 조건에서 달라졌나 / 검사한 배치 / 예상과 실제 / 기존 저장 영향 / 확인 못 한 범위 / 보스가 판단할 것"을 적는다. `PASS` 만 적지 않는다.
3. 담당끼리 접점이 필요하면 **이름과 값을 먼저 고정**한다(예: `window.JOB_WHY(집) → 'none'|'cut'|'far'|'full'`). 그러면 연기·디자인이 판정 구현을 기다리지 않는다.
4. 보스는 **합쳐서** 시험한 뒤 그 정확한 커밋만 머지한다. 규칙이 바뀌는 변경은 스위치로 되돌릴 수 있어야 하고, 스위치에 **복구용인지 교육적 선택용인지**를 주석으로 남긴다.
5. 기록에는 세 가지를 구분해 적는다: **재현 완료 / 코드 경로는 확인했으나 실제 영향 미검증 / 아직 가설**.

## 3. 지금 함께 만드는 하나

**"가까운 일터에 자리가 없는 집"과 "일터가 먼 집"을 아이가 다른 이유로 읽고, 각각 다른 수로 푼다.**

- 프로그램: 원인 넷을 한 함수에서 내보내고(`JOB_WHY`), 칩·돌아섬·집 카드의 말을 모두 거기서 뽑는다. 배정 뒤 길이 끊기면 다시 계산한다.
- 연기: 자리 참 = 일터 앞까지 갔다 돌아 나옴 · 끊김 = 길 끝에서 멈칫 · 멂 = 남보다 먼저 나섬 · 없음 = 집 앞에서 두리번.
- 관찰: 고치기 전 같은 표를 이미 떴다(인구 88 판 15일째 일자리 31/찬자리 31). 고친 뒤 같은 자를 다시 댄다.
- 검증: 옛/새 같은 시드 비교, 옛 저장본이 그대로 열리는지, 실화면 콘솔 0.

## 5. 보스의 단기 목표

- **오늘 안(맥북 세션):** 숨은 규칙 셋 정리 완료 → R01(원인 넷) + R02(재계산) 통합 → 창조자의 눈이 같은 잣대로 다시 보고 → **main 승격**. 승격 전 조건: 운영에 있는 옛 저장본이 새 코드에서 그대로 열리고, 새 저장본이 옛 코드에서도 깨지지 않을 것.
- **이번 주(학교 평일에는 마을 작업 없음):** 위 통합본을 실제 크롬북에서 한 번 보고, 월요일 규칙 변경 표(일자리·붐빔·도서관·큰길·성장 셋)를 한 문서로 정리.
- **다음 순서 후보(아직 시작 안 함):** 디자인의 원인 표현 시안, 다음 생활시설 묶음, 붐빔의 '길을 한 줄 더' 안내 조건, 버스 정류장.

## 6. 우리가 지키는 선

- 보이지 않는 곱셈·확률로 판정하지 않는다(그래서 위 셋을 없앤다).
- 아이가 이미 지은 것과 저장본을 지킨다.
- 그림·말·판정이 서로 다른 말을 하지 않는다.
- 숫자가 좋아져도 화면이 나빠지면 채택하지 않는다.
- 모르는 것은 모른다고 적는다.
