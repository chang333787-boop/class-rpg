## 틱 시간은 무엇을 따라 커지나 — 규칙인가, 사람·마을 크기인가 (09-20 밤 · `feat/village-45` = 02183d1)
보스가 pop167 저장본(사람 120·비 오는 날)에서 틱 중앙 0.7ms/최대 2.0ms 를 봤다(pop100 판은 0.1~0.2ms). 오늘 들어온 규칙(`litter`·`gardenVisit`·`gateSay`) 탓인지 갈랐다.
재는 법: 같은 저장본을 **조건마다 새로 열어**(시각·날씨를 같게) `__tickBench(200)` 로 데운 뒤 `__tickBench(1800)`(시뮬 3분) 전체 시간을 1800 으로 나눈 **틱 평균**. `__tickBench` 의 중앙·95 는 `performance.now()` 눈금이 0.1ms 라 거칠다 — **0.1~0.3ms 차이는 중앙값으로는 못 가른다.** 맥북 · CPU 1×(제한 없음).

- **규칙 탓이 아니다.** 어느 묶음을 꺼도 0.35~0.38 안에서 흔들릴 뿐이다(끈 쪽이 오히려 0.02 높게 나온 것 = 잡음 폭). 오늘 규칙 셋의 몫은 **0.01ms 아래.**
- **사람·마을 크기를 따라 큰다**: 사람 98 → 120(집 68 → 95)에 0.228 → 0.353ms(+55%). 틱마다 도는 것은 `tickFolks`(사람 수에 비례)와 `satTick`·`crowdTick`(집·길에 비례)다.
- **비(우산)**: +0.02~0.03ms — 잡음 폭과 같다. 우산은 틱이 아니라 그리기 쪽 몫이다(아래).
- 보스가 본 0.7ms 는 이 표의 두 배다 — 기기·그 순간의 부하 차이로 보인다(같은 판을 맥에서 재면 중앙 0.3). **비율**(pop88 의 약 1.5배)은 같다.
- 틱 밖(프레임마다 도는 것)도 봤다 — 비 오는 낮 10시, 7초 뒤 `__gfx().일한평균ms`: 전부 켬 1.1 · 오늘 규칙 셋 끔 1.1 · `umbrella` 끔 1.3 · 되풀이 1.0 → 차이 없음. 프레임 8.3ms(120Hz 화면).
- ⚠️ **draw call 107~108** (pop167 · 비 · 사람 120) — 예산 **≤ 110 의 턱밑**이다. 기준선(한 구역 가득 90)에서 +18: 우산 풀·정원 울타리·다듬은 나무·이유 풍선이 하나씩 얹힌 값. 다음 규칙이 draw call 을 더하면 예산을 넘는다 → 새 InstancedMesh 를 더하기 전에 **있는 풀에 얹을 수 있는지** 먼저 볼 것.
- 천장은 어디인가: 사람은 `FOLK_CAP = 120` 에서 멈추므로 `tickFolks` 는 더 안 큰다. 집은 계속 늘 수 있다 — 집 200채 판의 틱은 아직 안 쟀다(`satTick`·`crowdTick` 이 집 수에 곧게 비례한다면 0.6ms 안팎 — 예산 6ms 의 1/10).

## 조사 — 아직 안 한 최적화 후보 (제안, 구현 전)
1. **정지 시 렌더 멈춤**: 지금 루프는 멈춤(⏸)·아무 입력 없음에도 매 프레임 `renderer.render` 한다. 멈춰 있고 카메라·물건이 안 바뀌면 건너뛰면 크롬북 배터리·발열이 준다. 주의: 비·깜빡이는 구역·풍선 사인파가 멈춘 채로도 움직인다 → '멈춤 + 변화 없음'일 때만.
2. **three.js**: 쓰는 심볼은 49종(`Color·Vector3·MeshLambertMaterial·InstancedMesh·BufferGeometry·CanvasTexture·OrthographicCamera·Raycaster…`). 안 쓰는 부분을 덜어내려면 번들러가 필요한데 이 저장소는 **빌드 도구가 없다** → 직접 덜어내기는 위험·비추천. **위험 0 인 대안: 공식 `three.module.min.js`(같은 r160)로 바꾸기** — 원본 약 1,273KB → 약 690KB, gzip 약 256KB → 약 175KB(공식 배포 크기 기준 추정 — 파일을 받아 확인 필요). API 동일, importmap 한 줄.
3. **glb 30개 = 요청 30번**: 한 파일로 묶거나(모델 아틀라스) 첫 화면에 필요한 것(집·나무·사람)만 먼저. 디자인 담당과 같이.
4. `moveInQuiet`·`tryMoveIn`·`syncFolks` 가 부를 때마다 칸 65,536개를 훑는다(15초에 한 번이라 지금은 0.1ms 대). 집 목록을 따로 들고 있으면 없어진다 — 급하지 않다.
