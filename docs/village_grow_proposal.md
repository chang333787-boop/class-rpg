# 밤새 자라는 것 — 제안서 한 장 (2026-09-20 · 주민 연기 담당 · **구현 전**)

> 창조자의 눈 5회: **"어제와 오늘이 똑같다 — 밤새 바뀌는 건 웅덩이뿐."** 🟢 제안: 오늘 심은 나무가 내일 아침 한 뼘 자란다(3단계), 꽃밭은 봉오리 → 활짝.
> 보스: 저장은 '심은 날' 하나 · 저장·청크·그림(디자인)에 걸치니 연기 쪽 밑그림과 비용을 적어 오면 프로그램·디자인과 나눈다. **아이가 다음 날 또 열고 싶게.**
> 기준 코드: `feat/village-45` 8f25ca5(#615 까지).

## 한 줄
**'심은 날'을 곁 키 `grow: { 칸번호: 날 }` 에 *자라는 동안만* 적고(다 자라면 지운다), 모양은 청크를 합칠 때 단계만큼 줄여 그린다(draw call +0).**
옛 저장본·다른 기기는 `grow` 가 없으니 **전부 다 자란 것** — 잃는 것 없음. 저장 형식(v2 · 구역 문자열 · palette)은 한 글자도 안 바뀐다.

## ⓐ '다음 날'은 어느 날인가 — 먼저 정해야 할 것 (보스 결정)
마을의 하루는 **실제 3분**이고, 마을을 닫으면 시계가 멈춘다(`clock.t` 를 저장했다가 이어 간다). 그래서 두 가지가 다르다.

| | 시뮬 하루로 자람 | 실제 날짜로 자람 |
|---|---|---|
| 아이가 보는 것 | 심고 **3~6분 뒤**(밤 한 번 지나) 한 뼘 · 두 밤 뒤 다 자람 — 한 번 열어 둔 동안 다 본다 | 오늘 심고 **내일 학교에서 열면** 자라 있다 |
| '또 열고 싶게' | 약하다 — 오늘 안에 끝난다 | **강하다** — 이게 보스가 말한 것 |
| '밤새'의 뜻 | 마을의 밤(20~6시) 동안 — 창조자의 말 그대로 | 진짜 밤 — 마을 밤과 따로 논다 |
| 저장 값 | `simDay()`(정수) | 날짜 문자열 `'2026-09-21'` 또는 날 번호(1970-01-01 부터 일수) |
| 위험 | 없음 | 기기 시계가 틀리면 이상해진다(과거로 돌리면 도로 작아지지 않게 max 만 쓴다) |

**추천: 둘을 겹친다 — 새싹 → 어린나무는 마을의 밤 한 번(시뮬), 어린나무 → 다 자람은 실제 다음 날.** 오늘 안에 한 번 자라는 걸 보고("밤이 지나니 자랐네"), 다 자란 모습은 내일 열어야 본다. 저장 값은 둘 다 한 칸에 `[시뮬날, 실제날]` 두 정수(아래 비용).

## ⓑ 무엇이 자라나 (처음엔 작게)
| 종류 | 단계 | 단계별 모양(디자인 몫 — 여기선 밑그림) |
|---|---|---|
| 나무 `tree` · 과일나무 `fruit` · 큰나무 `bigtree` | 새싹 → 어린나무 → 다 자람 | 같은 부위를 **크기만** 0.35 → 0.65 → 1(발밑 기준). 과일나무는 다 자라야 열매 |
| 꽃밭 `flower` · 색 꽃밭 `FLOWER_KINDS` | 봉오리 → 활짝 | 꽃 부위만 0.5 크기 + 초록 한 톤(봉오리). 잎은 그대로 |
| (나중에) 덤불 · 다듬은 나무 | — | 1차에선 뺀다 |
- **판정은 안 바뀐다**: 새싹 나무도 필요('쉼' 등)·꾸미기·목표 셈은 다 자란 것과 같다. 아이가 심은 순간부터 쓸모는 그대로 — 자라는 건 **보는 기쁨**만.
- 옮기기(🖐)로 옮긴 나무는 심은 날을 **따라간다**(MAC-KEEP 의 식구 맡기기와 같은 자리에서). 치우고 다시 심으면 새싹부터.

## ⓒ 연기 쪽 밑그림 (내 몫)
1. **아침의 첫 발견** — 해가 뜰 때(6시) 밤새 한 단계 자란 것이 있으면, 그 곁을 지나던 주민 하나가 **멈춰 올려다본다**(ACT-LEAVE 의 돌아봄과 같은 몸짓 · 하루에 몇 번까지). 아이 쪽 아이(작은 사람)면 제자리에서 통통(웅덩이와 같은 높이 줄).
2. **자란 자리 반짝** — 한 단계 자란 순간 그 칸 위에 ✨ 한 번(있는 sparkle 묶음 · draw call +0).
3. **다음 날 처음 열 때(실제 날짜)** — 소식 한 줄: "🌳 어제 심은 나무 3그루가 밤새 자랐어요" + 미니맵 그 자리 반짝(모달·카메라 이동 없음 — 원칙). 소식은 프로그램 담당 장치(`toast`)를 그대로.
4. 새싹은 **밟히지 않는다** — 길 칸이 아니라 걷기와 무관.

## ⓓ 비용
**저장** — 곁 키 하나, 자라는 동안만:
```json
"grow": { "33412": [41, 20352], "33670": [41, 20352] }
```
- 한 칸 약 **20바이트**(`"33412":[41,20352],`). 하루에 새로 심는 나무·꽃밭이 20개면 400바이트, **다 자라면 지운다** → 저장본에 머무는 건 많아야 이틀치 ≈ 1KB. 한 구역 가득 저장본 3.5KB · 예산 8KB 안.
- **v2 에 넣는 법**: `serialize()` 끝에 `grow` 한 키(MAC-TITLE 의 `title`·`titleWas` 와 같은 꼴 — `serialize`·`loadSaved` 감싸기). `SAVE_V` 는 **안 올린다** — 옛 판은 모르는 키를 무시한다(`loadSaved` 는 아는 키만 읽는다). 옛 판이 저장하면 `grow` 가 빠진다 → 그 뒤엔 다 자란 것(잃는 것 없음).
- **옛 저장본**: `grow` 없음 = 전부 다 자람. **다른 기기**: `sync.js` 는 아는 필드만 옮긴다(`meta.houses`·`signs`…) → `grow` 를 서버에 싣지 않으면 다른 기기에선 다 자란 것으로 보인다(안전한 쪽). 싣는 건 `sync.js` + 시험 32건 — 프로그램 담당 몫이고 **없어도 된다**(칭호 `meta.title` 과 같은 줄에 두면 한 번에).
- 칸 번호가 키라 **구역 문자열과 따로 논다** — 구역을 다시 올리지 않아도 된다.

**그리기** — draw call **+0**:
- 청크를 합칠 때(`buildChunk`) 그 칸이 `grow` 에 있으면 부위 행렬에 단계 크기를 곱한다(ACT-DAWN 의 `lit` 한 조각과 같은 꼴 — 한 줄). 삼각형은 그대로(작아질 뿐).
- 다시 합치기: 단계가 바뀌는 순간에만 그 칸의 청크를 `dirtyChunks` 에(시뮬 하루 한 번 · 실제 날짜는 열 때 한 번). 하룻밤 수십 칸이면 청크 몇 개.
- glb 로 그리는 나무(DESIGN-GLB)는 인스턴스 행렬이라 같은 곱셈 — 디자인 담당이 어느 경로인지 확인.

**틱** — `grow` 목록(많아야 수십)만 하루 한 번 훑는다. 판 전체를 훑지 않는다.

## ⓔ 나눔 (보스께)
| 누가 | 무엇 |
|---|---|
| 프로그램 | `grow` 곁 키(`serialize`·`loadSaved`·옮기기·치우기에서 따라가기) · 실제 날짜 읽기 · (선택) `sync.js` |

| 주민 연기(나) | ⓒ 1~2(아침에 올려다보기 · 자란 자리 ✨) · 청크 고리 한 줄(단계 크기 곱하기) |

## 하지 않는 것
- 시들기·죽기·물 주기 같은 **돌봄 부담** — 아이를 벌주는 쪽이 된다(창조자의 원칙: 기본은 평온·기쁨).
- 자라는 데 점수·조건 — 심기만 하면 자란다.
- 자라는 동안 필요·목표 판정을 다르게 하는 것(ⓑ).
