# 터치로 놓기 — 흐름 제안 (2026-09-20 · 맥북 마을 프로그램 담당 · **설계만, 코드 없음**)

> 사용자 09-20: "돌리기 해도 건물별로 미리보기가 안 보이는데 이걸 어떻게 알아?" → #593 이 미리보기를 실제 모양으로 바꿨지만,
> **터치에서는 그 미리보기를 볼 틈이 없다.** 보스가 고르면 그 안으로 구현한다(작은 PR 여럿).

## 1. 지금 — 왜 터치에선 미리보기가 없나 (코드 사실)
| | 마우스 | 터치 |
|---|---|---|
| 놓기 전 | 커서를 올리면 미리보기가 따라다닌다(`pointermove` → `updateGhost`) | **올려 둘 손가락이 없다** — 미리보기가 뜰 계기가 없음 |
| 놓는 순간 | 누르는 순간(`pointerdown` → `paintStart`) | **손가락을 대는 순간 놓인다.** 보고 고를 틈 0 |
| 방향 | 미리보기를 보며 R | 놓기 **전에** 🔄 를 눌러 둬야 한다 — 어느 쪽을 보는지는 카드 그림(#600)과 1.8초 가운데 미리보기(#593 의 임시방편)로만 안다 |
| 틀렸을 때 | ↩ · 오른쪽 단추 | ↩ · 길게 눌러 메뉴(#539)의 🔄·✋ — **놓은 뒤에 고치는 길만 있다** |

큰 건물일수록 아프다: 3×3 광장·3×2 학교는 손가락이 가린 자리에서 어느 칸까지 덮는지 모른 채 놓인다.

## 2. 안 A — 앉히고 · 보고 · 확정 (보스 밑그림을 구체화)
```
카드 고름 ─▶ 판을 톡 ─▶ 미리보기가 그 칸에 '앉는다' + [✓ 놓기] [🔄] [✕]
                          │  미리보기를 끌면 따라온다 · 다른 빈 칸을 톡 하면 그리로 옮겨 앉는다
                          │  🔄 = 앉은 채로 돈다(문 앞 화살표도) · 못 놓는 자리면 ✓ 가 흐리고 까닭 말풍선(#553)
                          ▼
                     ✓ ─▶ 놓임(되돌리기·소리·귀띔은 지금과 같은 길) ─▶ 카드는 그대로 — 다음 톡은 다시 '앉기'
                     ✕ / 같은 카드 다시 톡 / 다른 카드 ─▶ 앉은 것만 사라짐
```
- **어느 물건?** `문이 있는 것`(집·가게·도서관…, #593 의 문 화살표가 뜨는 종류) **또는 자리 4칸 이상**(우물·연못·분수·정자·놀이터·광장·큰길 제외). 
  길·큰길·횡단보도·가로수 열·다리·울타리·돌담·꽃밭·잔디·나무·1×1 꾸밈은 **지금처럼 대는 순간 놓이고 끌면 죽 놓인다**(#580·#607 그대로).
- **마우스는 그대로**(`pointerType === 'mouse'` 는 건너뜀 — 커서 미리보기가 이미 있다). 펜은 터치와 같이.
- 단추 묶음은 #539 길게 누르기 메뉴와 **같은 생김새·같은 자리 규칙**(물건 위, 상단 바에 닿으면 아래로, 화면 밖으로 안 나감 — #570 의 실제 위치 재기). 단추 44px 이상.
- 앉아 있는 동안 판을 끌면(미리보기 밖) 전처럼 판이 움직인다 — 미리보기는 그 칸에 붙어 같이 간다.
- 걷어내는 것: #593 의 '🔄 누르면 화면 가운데 1.8초 미리보기'(앉은 미리보기가 그 일을 한다. 앉은 것이 없을 때 🔄 는 카드 그림만 돈다).
- 구현 꼴: 새 블록 하나, **원래 줄 수정 0** — 캡처 단계 `pointerdown/move/up`(터치·펜 + 해당 종류일 때만 먼저 받아 원래 처리기로 안 넘김) · `setMode`·`rotate`·`updateGhost` 감싸기. 놓는 길은 `canPlace → placeAt → pushUndo({t:'place'})` 그대로라 MAC-SAY-2 귀띔·FIRST5·되돌리기가 그대로 붙는다. 스위치 `VRULES.seatPlace`. draw call 0(미리보기는 있던 것, 단추는 DOM).

## 4. 반대 안
**안 B — 즉시 놓되, 놓자마자 고침 단추.** 지금처럼 대는 순간 놓인다. 놓인 물건 곁에 3초 동안 작은 [🔄][↩] 가 뜬다(#539 와 같은 생김새 · 안 누르면 사라짐 · 모달 아님).
- 좋음: 잘 놓았을 때 **톡 수가 안 는다**(10채 = 10번). 처음 5분 그대로. 구현이 가장 작다(놓은 뒤 `holdRotate` 를 부르는 단추 둘).
- 나쁨: '보고 놓기'가 아니라 '놓고 고치기' — 사용자 지적("어떻게 알아?")에 반만 답한다. 놓는 순간 소리·귀띔(#595)이 먼저 나간 뒤 고치게 된다. 큰 건물이 어디까지 덮는지는 여전히 놓아 봐야 안다. 자리를 옮기려면 결국 ↩ 뒤 다시.

**안 C — 대고 있는 동안 미리보기, 떼면 놓임.** 해당 종류만 `pointerup` 에서 놓는다. 대고 끌면 미리보기가 따라오고, 트레이 위에서 떼면 취소.
- 좋음: 톡 수 그대로, 놓기 전에 본다.
- 나쁨: **미리보기가 손가락 밑에 가린다**(위로 띄우면 '누른 곳 ≠ 놓이는 곳'이 된다). 🔄 는 여전히 미리 눌러야 한다(손가락이 판에 있으므로). 떼는 순간 손이 미끄러지면 엉뚱한 칸.

|---|---|---|---|---|---|
| 지금 | ✕ | ✕ | 10 | — | — |
| **A** | ✅ | ✅ | 20 (ⓐ 로 손 이동↓ · ⓑ 로 11) | 집 단계 문구 손봄 | PR 3개 |

| C | △ 손가락에 가림 | ✕ | 10 | 거의 그대로 | PR 1~2개 |

## 5. 추천 — **A, 단 1-ⓐ(미리보기 다시 톡 = ✓)를 첫 PR 에 같이**
- 사용자 지적의 뿌리는 '놓기 전에 볼 수 없다'이고, 그것을 끝까지 푸는 것은 A 뿐이다. 터치 마을 짓기 게임들이 큰 건물에 쓰는 익숙한 꼴이기도 하다(길은 즉시, 건물은 앉히고 ✓).
- 값은 집 톡 수 2배다. 걱정 2(안 놓고 지나감)와 함께 **실기 없이는 판단이 안 서는 부분** — 그래서 스위치 하나(`VRULES.seatPlace.on`)로 끄면 지금 그대로가 되게 하고, 월요일 크롬북·태블릿에서 아이 손으로 본 뒤 기본값을 정하자고 제안한다.
- PR 순서(하나에 한 가지): ① 앉기 + ✓·✕·🔄 + 다시 톡 = ✓ + 1.8초 가운데 미리보기 걷기 ② 미리보기 끌어 옮기기 + 세 화면 겹침 점검 ③ 처음 5분 문구 · '아직 안 놓았어요' 한마디. (1-ⓑ 줄짓기는 그 뒤, 눈으로 보고.)
