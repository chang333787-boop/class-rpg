# 1. 퀘스트 오류 (최우선)

## 🔴 Q1. 학생 접속만으로 교사의 퀘스트 목록이 사라질 수 있다 — **최우선 확정 버그**

- **원인:** 학생 로그인 시 `DB.ensureDailyQuests()`(student.js:182)와 `autoCloseDailyQuests()`(student.js:187)가 실행되고, 둘 다 **`boardQuests` 배열 전체를 통짜로 덮어쓴다**
  (`gamedata.js:819`, `student.js:10114` — `child('boardQuests').set(db.boardQuests)`).
- **벌어지는 일:** 아침에 학생 여러 명이 거의 동시에 접속 → 각자 **자기 기기의 낡은 목록**으로 전체를 덮어씀 → 그 사이 교사가 추가·수정한 퀘스트가 **소리 없이 사라진다**. `ensureDailyQuests`는 `saveSettings()`로 **설정 전체**도 덮어쓴다(다른 설정 유실 위험).
- **관련:** `boardQuests` 통짜 set이 코드 전체에 **8곳**(admin 6 · gamedata 1 · student 1).
- **수정 방향:** ① 학생 클라이언트에서 **퀘스트 목록 쓰기 제거**(자동 생성·자동 닫기는 교사/관리자 쪽에서만) ② 남기려면 퀘스트 **개별 경로 저장**(`boardQuests/<id>`)으로 전환 ③ `autoDailyLastDate`는 settings 통짜 대신 단일 키 저장.
- **위험도:** 수정 자체는 중간(학생 쪽 호출 제거는 단순), 효과는 매우 큼.

## 🟠 Q2. 자동 일일퀘스트 중복 방지가 "이름" 기준
- `db.boardQuests.find(q => q.name === item.name && q.active !== false)` (gamedata.js:806)
- **결과:** 교사가 같은 이름 퀘스트를 수동으로 올려두면 자동 등록이 **조용히 건너뛰어짐**. 이름만 살짝 바꾸면 반대로 중복 생성.
- **수정:** 자동 생성분은 id 규칙(`bq_auto_<날짜>_<i>`)으로만 판정.

## 🟠 Q3. "어제 만든 일일퀘스트"가 다음날 자동으로 내려간다
- `q.type==='daily' && q.date!==today → active:false` (gamedata.js:793)
- 설계상 의도지만, 교사가 **매일 쓸 생각으로 만든 daily 퀘스트**도 다음날 사라져서 "퀘스트가 없어졌다"로 체감된다. `date` 필드가 없는 레거시 퀘스트는 **즉시 비활성화**된다.
- **수정:** 교사 화면에 "일일퀘스트는 하루만 게시됩니다" 명시 + 반복 퀘스트(매일 자동 재게시) 옵션 제공.

## 🟠 Q4. 키오스크가 같은 판정을 두 곳에서 다르게 한다
- `kiosk.js:156`은 활성 퀘스트 목록(`activeBQIds`)을 넘기고, **`kiosk.js:691`은 `null`을 넘긴다**.
- **결과:** 닫히거나 삭제된 퀘스트가 **표시 로직에선 걸러지고 신청 처리에선 안 걸러질 수 있다** → 화면과 동작 불일치.
- **수정:** 두 호출을 동일 인자로 통일.

## 🟡 Q5. 죽은 "보상 받기" 흐름의 잔재
- `questStatus`가 `pendingRewards` 중 `approved===true`를 **완료로 간주**하는데, 승인 시엔 항목을 **제거**하므로 그런 항목은 새로 생기지 않는다 → 죽은 분기.
- 게다가 수령 함수 `claimRewards`(student.js:1183)는 **호출부 0 = 죽은 코드**.
- **결과:** 옛 데이터에 `approved:true` 대기 항목이 남아 있으면 **영구 "완료"로 보이고 수령도 불가**.
- **수정:** 죽은 분기·함수 정리 + 레거시 데이터 존재 여부 1회 점검.

## 🟡 Q6. 날짜 없는 옛 기록 하나면 그 퀘스트가 영구 완료
- `isQuestDoneToday`: `if (!q.date) return true` (gamedata.js:1236)
- 신규 로그는 전부 `date`를 넣으므로 **신규 발생은 없음**. 다만 **레거시 로그**가 있으면 해당 학생은 그 퀘스트를 영원히 다시 못 한다.
- **수정:** 레거시 점검 후 `!q.date`는 완료로 보지 않도록 변경(또는 마이그레이션으로 date 채움).

## 🟡 Q7. 주 시작 기준 불일치
- 주간 퀘스트 완료 판정 = **일요일 시작**(`weekStartStr`), 활동 집계·주간 키 = **월요일 시작**(`weekKey`, admin 집계).
- **결과:** 일요일에 한 활동이 화면마다 다른 주로 집계.
- **수정:** 주 시작 정의를 한 곳으로 통일.

### 퀘스트 작업 순서 (권장)
`Q1`(가장 큰 실피해) → `Q4`(키오스크 불일치) → `Q2`·`Q3`(자동 생성/게시 규칙 + 교사 안내) → `Q5`·`Q6`(죽은 분기·레거시 점검) → `Q7`(주 기준 통일)

# 2. 교과서 PDF → 학습게임 콘텐츠 변환

> 사용자가 **수학·영어 교과서 PDF**를 제공하면, 그것을 게임 안 학습 콘텐츠로 바꾸는 파이프라인.

## 2-1. 현재 붙일 수 있는 자리 (이미 있는 구조)
| 게임 요소 | 지금 구조 | 교과서 콘텐츠 투입 방식 |
|---|---|---|
| **영어 단어장** | `BASE_WORDS` 500개 + 교사 커스텀 단어 + **단어 세트**(`teacherWordSets`) | 교과서 단원별 단어를 **단원=세트**로 자동 생성 (가장 쉬움) |
| **영어 퀴즈** | 4유형(영→뜻/뜻→영/뜻쓰기/스펠링) | 단원 세트를 그대로 출제원으로 사용 |
| **수학** | ❌ **전용 구조 없음** | 신규 필요: 문제 은행(문항·정답·해설·단원·난이도) |
| **퀘스트** | 게시판 퀘스트(이름·보상·능력치) | "○단원 문제 5개 풀기" 형태 자동 생성 |

## 2-2. 제안 설계
1. **중간 형식(JSON)을 먼저 정한다** — PDF를 직접 코드에 넣지 않고, 항상 아래 형태로 변환:
   - 영어: `{ unit, word, meaning, pos, example }`
   - 수학: `{ unit, type(계산/문장제/도형…), question, answer, choices?, hint, level }`
2. **변환은 대화로** — PDF를 주면 내가 단원별로 읽어 위 JSON을 만들고, 사용자가 검수(오답·오탈자 확인) 후 확정.
3. **주입 방식 2안**
   - **A안(추천·저위험):** JSON을 교사 관리 화면의 **가져오기**로 넣는다 → 코드 배포 불필요, 학급별로 다른 교과서 대응 가능
   - **B안:** `gamedata.js`에 내장 → 배포 필요, 모든 학급 공통
4. **수학 게임화 방식** (택 1, 사용자 결정 필요)
   - 영어 퀴즈와 같은 **문제풀이 모달**(가장 빠름, 기존 코드 재사용)
   - **전투와 결합** — 몬스터 공격 시 문제를 맞히면 데미지 (몰입 크지만 전투 로직 수술 = 고위험)
   - **퀘스트로만** — "수학 익힘책 ○쪽" 같은 오프라인 활동 인증(코드 거의 불필요)

## 2-3. 필요한 것 (사용자)
- PDF (학년·과목·출판사)
- 수학 게임화 방식 선택 (위 3안)
- 단원 범위(1학기 전체? 2학기 예정 단원?)

# 4. 참고: 이번 조사에서 함께 나온 것 (퀘스트 외)

- **리코더 = 미완성 기능** — 학생 진입점이 `"곧 열릴 예정이에요"` 토스트뿐이고, 연습 기록을 **만드는 코드가 어디에도 없다**. 교사 화면(기록 조회·곡 관리·코멘트)과 업적 5개는 완비 → 교사 화면은 영원히 빈 목록, 업적 5개는 영구 미달성. **완성할지 / 제거할지 결정 필요.**
- **"집" 모달에 탭 9개** — 능력치·주간다짐·독서·인테리어·작품·추억·감정·업적·영어단어장이 한 서랍에. 영어 단어장을 아이가 찾기 어려운 주된 이유.
- **단어테스트 전달 방식** — 로그인 10초 후 **닫을 수 없는** 강제 팝업(닫기 버튼 숨김 + 바깥 클릭 차단), 채점이 **완전 일치만 정답**(오타 1글자·유사 표현 오답), 퀴즈가 **3문제 강제판 / 10문제 자발판 두 개 공존**, 하루 1회 제한이 **localStorage**라 기기 바꾸면 또 뜬다.
  *(보상 없음은 의도로 확인 — 제외)*
  → 잘 된 부분은 유지: 틀린 단어 3배 가중치 복습, 같은 범주에서 오답 보기 생성, 발음 듣기.
