# 놓는 방식 설계안 — 기물마다 놓는 법이 다르다 (PLACE-CLASS-1)

> 2026-09-19 · 맥북 주말 보스 · **설계안(구현 전)**. 대상: 🏡 마당 꾸미기 · 🏘️ 우리 마을 둘 다.
> 사용자 지시: "매치해야 되는 방식이 기물별로 다르다. **롤러코스터 타이쿤 방식**으로 해야 한다는 걸 잊지 말고, **바닥 위에 올려도 되는 것과 아닌 것**도 구별해라." + "태블릿이 기본, 마우스는 꽂으면 자동으로."
> 그 게임의 그림은 베끼지 않는다. 가져오는 것은 **층 구조와 놓는 법**이다.

## 1. 지금 (코드로 확인)

| | 🏡 마당 꾸미기 (`student.js`) | 🏘️ 우리 마을 (`village/index.html` 59차+) |
|---|---|---|
| 한 칸에 들어가는 것 | **2층**: 바닥 칠(`yardFloor`) + 물건 1개(`houseDecorations`) | **1층**: `cells[칸]` 에 하나. 길·잔디·꽃밭·자갈도 물건과 **같은 층** |
| 그래서 안 되는 것 | 울타리가 칸을 통째로 차지 → 1칸 화단을 두르면 3×3 을 쓴다 | **길 위에 벤치·가로등 ✗ · 잔디 위에 나무 ✗ · 꽃밭 둘레 울타리는 옆 칸을 먹음** ("여기엔 이미 ○○가 있어요") |
| 바닥을 가리는 규칙 | 물 위 금지(예외 2종+동물) · 벽걸이는 집 안 맨 윗줄 · 우리↔동물 겹침 — **id 를 코드에 적어 둔 예외 3개** | `needRoad`(길에 붙어야 함) · `special`(마을에 하나) 뿐. 바닥 종류는 안 본다 |
| 놓는 법 | 전부 같다: 카드 고르고 칸을 누름(끌면 연달아) | 전부 같다: 고르고 칸을 누름/끌기, R 돌리기 |

→ 두 게임 모두 **"기물의 종류가 놓는 법을 정한다"는 개념이 없다.** 예외를 id 로 하나씩 코드에 적는 방식은 장식이 91종·47종을 넘어가는 지금 더는 못 버틴다.

## 2. 목표 — 층 5개와 놓는 법 6가지

한 칸은 아래 층을 **동시에** 가질 수 있다(RCT 의 땅·길·길 위 물건·조경·담과 같은 꼴).

| 층 | 무엇 | 한 칸에 | 예 |
|---|---|---|---|
| **① 땅** | 칸을 덮는 바닥 | 1 | 풀·흙·모래·자갈·물·**꽃밭(칸을 덮는 식물)**·잔디 무늬·광장 포장 |
| **② 길** | 걸어 다니는 바닥 | 1 (땅 위에 깔림) | 길·큰길·돌길·횡단보도·다리 |
| **③ 물건** | 서 있는 것·건물 | 1 (여러 칸 차지 가능) | 나무·화분·바위·우물·집·가게·분수 |
| **④ 길가 물건** | 길 칸의 가장자리에 붙는 것 — 걷는 걸 막지 않는다 | 길 칸마다 1 | 벤치·가로등·휴지통·우체통·표지판 |
| **⑤ 테두리** | 칸과 칸 **사이** 선 위 | 변마다 1 (최대 4) | 울타리·돌담·산울타리·**문** |

따로 움직이는 것: 🐔 동물·주민(칸을 차지하지 않고 돌아다님), 🖼️ 벽걸이(집 안 벽 줄).

### 놓는 법 — 기물의 `place` 값이 정한다

| `place` | 터치(기본) | 마우스(꽂으면 자동으로 덤) |
|---|---|---|
| `ground` 땅 · `path` 길 | **끌어서 칠하기.** 같은 층의 앞엣것을 바꾼다(물건은 안 건드림) | 누른 채 끌기 · 오른쪽 끌기 = 지우며 칠하기 |
| `object` 물건 | **누르면 바로 놓임**, ↩ 로 취소. 2칸 이상은 끄는 동안 손가락 **위쪽**에 미리보기 | 커서 따라다니는 미리보기(못 놓는 자리 빨강) · 오른쪽 클릭 = 치우기 |
| `roadside` 길가 물건 | **길 칸을 누르면** 가장 가까운 길가에 붙고 **길 방향으로 저절로 돌아선다.** 길이 아니면 "길 위에 놓는 거예요" | 같음 + 미리보기가 붙을 변을 보여 줌 |
| `edge` 테두리 | **칸 경계를 따라 끌면** 그 선에 놓인다 · **네모로 끌면 둘레에 두른다**(손가락으로 변을 겨누게 하지 않는다) · 놓인 조각을 누르면 **문으로 바뀜** | 커서가 가까운 변을 밝혀 줌 · 한 변씩 클릭도 됨 |
| `wallhang` 벽걸이 | 집 안 벽 줄만 밝아지고 거기만 놓임 | 같음 |
| `animal` 동물 | 누른 자리에 풀어 놓음(살 수 있는 땅만 밝아짐) | 같음 |

공통: 한 손가락 = 든 도구, **두 손가락 = 언제나 이동·확대**, 단추 44px 이상, hover 에만 있는 기능 0. 입력 종류는 Pointer Events 의 `pointerType` 으로 그때그때 판단(모드 단추 없음).

## 3. "바닥 위에 올려도 되는 것 / 아닌 것" — `on` 표

각 기물에 **올라설 수 있는 땅·길의 목록** `on` 을 둔다. 못 놓을 때는 **이유를 아이 말로** 알려 준다(지금 마당 꾸미기의 "🌊 물 위에는 놓을 수 없어요" 방식 그대로 일반화).

| 기물 무리 | 풀 | 흙 | 모래·자갈 | 꽃밭 | 포장·광장 | 길 | 물 | 안 될 때 말 |
|---|---|---|---|---|---|---|---|---|
| 나무·덤불 | ✅ | ✅ | ✅ | ✅(꽃밭이 밑동을 두름) | ❌ | ❌ | ❌ | "나무는 흙이 있어야 자라요" |
| 꽃 포인트(화분 아님) | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ | |
| 화분·조각상·분수 | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | "꽃밭을 밟아요 — 옆 칸에 놓아요" |
| 벤치·가로등·휴지통 (`roadside`) | — | — | — | — | ✅ | ✅ | ❌ | "길 위에 놓는 거예요" |
| 집·가게 등 건물 | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | (+ `needRoad`: 길에 붙어야) |
| 연잎·갈대·오리 | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ | "물에 사는 거예요" |
| 다리 | ❌ | ❌ | ❌ | ❌ | ❌ | — | ✅ | 길의 한 종류로 물 위에만 |
| 울타리·담 (`edge`) | 어떤 바닥이든 ✅ — 칸을 차지하지 않으니까 | | | | | | 물가까지 | |

※ 위 표는 **초안**이다. 두 디자인 담당이 자기 게임의 전 종류(마당 91 · 마을 47)에 `place` 와 `on` 을 채운 **전수표**를 만든다. 규칙은 코드 속 id 목록이 아니라 **기물 표의 필드**로 산다(`DECO_WATER_OK`·`DECO_WALL` 같은 예외 목록은 필드로 흡수).

## 4. 저장 — 어떻게 담나 (가장 조심할 곳)

### 🏡 마당 꾸미기 — 덧붙이기만 한다
- 땅: 지금 `yardFloor`/`yardFloors` 그대로. **칸을 덮는 꽃밭은 바닥 타일의 한 종류**로 들어간다(#432 방향) → 저장 변화 0.
- 물건·동물·벽걸이: 지금 `houseDecorations` 항목 그대로.
- **테두리(새로)**: 같은 목록에 항목을 더하되 변을 가리키는 선택 필드 하나 — `{id, area, row, col, e:'n'|'w'}`(칸의 북쪽·서쪽 변만 쓰면 중복이 없다). `e` 가 없는 항목은 지금과 100% 같다.
  - ⚠️ 옛 캐시 JS 를 든 기기는 `e` 항목을 '칸을 차지한 장식'으로 그린다 → **원격 강제 새로고침과 함께** 내고, 첫 주는 새 울타리를 상점에 천천히 연다. 지금 칸 울타리(`d_y70`)는 **그대로 둔다**(아이들 마당이 안 바뀜) — 테두리 울타리는 새 물건.
- 길가 물건: 물건 항목 + 선택 필드 `side`. 없으면 지금과 같다.

### 🏘️ 우리 마을 — 저장 형식 v3, **지금이 제일 싼 때**
- v2 는 구역(32×32)마다 '칸당 종류 하나'의 문자열 1개다. 층이 생기면 **구역마다 층별 문자열**이 된다: `plots/<px_py>` = `{ g:'땅', p:'길', o:'물건', s:'길가', e:'테두리' }`. 빈 층은 키를 안 둔다(대부분의 구역은 g·p·o 셋).
- v2 → v3 는 **읽을 때 한 번** 가른다: 길 종류는 `p`, 잔디·꽃밭·자갈·광장·연못은 `g`, 나머지는 `o`. 원문은 `.backup` 에(지금 v1→v2 와 같은 예의).
- ⏰ **서버 저장(#214)이 아직 안 켜졌다.** 규칙을 게시하고 나면 서버 데이터·`.validate` 규칙·백업/복원 스크립트·교사 탭까지 v2 에 묶인다. **v3 를 서버 저장보다 먼저 정하면 옮길 데이터가 기기 localStorage 뿐**이다. → 월요일 학교 보스와 맞출 1순위.
- 주민 길찾기·필요 판정은 `p`(길) 층만 보면 되므로 오히려 단순해진다. 길가 물건은 걷기를 막지 않는다.

## 6. 이것이 두 게임의 방향과 맞는가

- 🏘️ 마을(시뮬레이션 세상): 층이 생겨야 **"길에 휴지통이 없다 → 쓰레기가 쌓인다"**, **"횡단보도가 있다 → 언젠가 자동차"** 같은 자연스러운 확장이 들어설 자리가 생긴다. 길가 물건·테두리는 그 자체가 사회의 요소다(공공 시설·경계·문).
- 🏡 마당 꾸미기(미적 즐거움): 층이 생겨야 **바닥 + 울타리 + 나무 + 벤치를 겹쳐 '한 장소'**를 지을 수 있다. 사진 속 그 게임의 화단(폭 1칸에 흰 울타리·덤불·나무·벤치)이 아름다운 이유가 이것이다.
