## ① 무엇이 문제였나
비율고정은 `#s-game`을 **2560px 기준으로 깔고** `innerWidth/2560`만큼 줄인다. 화면이 좁을수록 배율이 뚝 떨어진다.
#200에서 **701px 0.274 · 768px 0.300**을 실측했다. 폰(0.146)만큼은 아니어도 **작은 태블릿에서도 글자를 못 읽는다.**

## ② 어떻게 고쳤나 — 하한 방식
버튼이 보이는 폭을 1440으로 올리는 방식은 **택하지 않았다**(보스 판단). 전자칠판·큰 모니터에서 쓰는 기능인데
노트북 1280px에서 버튼까지 사라지면 안 된다. 대신 **계산한 배율이 하한보다 작으면 적용하지 않는다.**

```
const SCALE_MIN_RATIO = 0.6;
const SCALE_MIN_RATIO_WIDTH = Math.ceil(SCALE_BASE_WIDTH * SCALE_MIN_RATIO);   // 1536px
```
두 값은 상수로 뒀다(나중에 조정 가능하게). 2560 × 0.6 = **1536px 이상에서만 실제로 걸린다.**

## ③ 아무 일도 안 일어나면 고장으로 느낀다 → 한 번 알린다
버튼은 701px 이상에서 그대로 보인다. 하한에 걸려 적용이 안 될 때 **토스트 한 번**:
`이 화면에서는 화면 맞춤이 적용되지 않아요`

`applyScale()`은 `resize`마다 불리므로 `_scaleBlockedNoticed` 플래그로 **한 번만** 띄운다.
`toggleScaleMode()`에서 플래그를 되돌려, 학생이 **누를 때마다** 결과를 받는다. 끌 때는 뜨지 않는다.
