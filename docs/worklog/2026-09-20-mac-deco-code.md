## 3. 하네스 (이 PR)

- **가짜 통과 셋을 막았다**
  ① 프로필 폴더 고정 → 동시 실행 시 `SingletonLock` 으로 못 뜸 → `mkdtemp`(끝나면 지움).
  ② 출력이 없어도 `=false` 가 없으니 통과로 읽힘 → **끝 표식(`걸린시간_초=`)이 없으면 exit 1**.
  ③ (찾다가 나온 것) 맥 크롬은 검사가 끝나도 **스스로 안 끝난다** — main 의 `run.mjs` 는 매번 노드 타임아웃(120초)에 죽인 뒤에야 `--dump-dom` 출력을 받았다(늘 2분·가끔은 못 받음). → 페이지가 끝나는 순간 **결과를 이 서버로 POST**(`/__done`)하고 바로 브라우저를 끈다. **한 번 120초+ → 3.5초.**
  덤: 바깥 스크립트(Firebase SDK 2·Chart.js)는 한 번만 받아 기기 임시 폴더(`rpg_harness_ext_cache`)에서 내준다(새 프로필이라 브라우저 캐시가 없다 · 못 받으면 원래 주소 그대로).
- `check.mjs`(새): 틀린 줄(`=false`·`"맞나":false`·`ERR`·`안눌리는단추_*≠"없음"`·출력 짧음)을 세어 exit 코드로. 틀리면 한 번 더 — 두 번 다 틀리면 FAIL, 두 번째만 맞으면 **REVIEW(흔들림 — 줄 이름이 찍힌다)**. 브라우저 없으면 SKIP.
- `precheck.mjs`: `deco-harness` — **base 대비 꾸미기 파일을 고친 PR 이면 저절로**, `--deco` 강제 · `--no-deco` 끔.
- `deco-save-real-sdk/run.mjs`: 고유 프로필 + 맥 크롬 지원(전엔 엣지 경로 고정이라 맥에서 못 돌았다). ⚠️ 이쪽은 아직 `--dump-dom` 방식이라 맥에서는 케이스마다 타임아웃까지 기다린다 — 같은 POST 방식으로 바꾸면 된다(다음 사람 몫). `teacherEdit` 는 지금도 🔴 `GOLD_REVERTED`(#288 그대로 — 관찰만).
- **`구경뒤_내자리_그대로` 흔들림 — 검사 쪽 문제로 판단(솔직히: 현장을 잡지는 못했다)**
  · 내가 본 것: 같은 증상 1회(폰 집 안 브랜치에서 4회 중 1회) + 같은 계열로 보이는 `핀치중_캔버스그대로=false` 1회.
  · 추정 원인: `openInteriorFullscreen()` 은 rAF 두 번 뒤에 `renderHouseDeco()+_decoViewRestore()` 를 부른다. 헤드리스 가상 시간에서는 rAF 가 몇 초씩 늦는다(직접 쟀다 — 3초 넘게 안 돌았다). 그 콜백이 **다음 시험의 비교 사이 0.1초**에 끼어들면 배율·자리가 바뀐다.
  · 계측판(끼어든 함수 이름을 적게 한 옛 검사)을 28회 돌렸지만 **재현이 안 돼 현장은 못 잡았다.** 그래서 추정에 기대지 않게 고쳤다 — ⑭ 는 그린 **직후 같은 틱**에 비교한다(자바스크립트는 한 줄기라 그 사이엔 아무것도 못 끼어든다). **이제 이 줄이 false 면 `_renderFriendCanvas` 자체가 내 자리를 바꾼 것 = 진짜 버그다.** 연 뒤에는 `rafSettle()` 로 그 rAF 가 실제로 돌 때까지 기다린다.
  · 결과: **40회(순차 20 + 4개 동시 × 5판) 전부 107줄 · 틀린 줄 0 · 103초.**
  · 실제 아이 화면: 실제 브라우저는 연 직후 2프레임 안에 그 rAF 가 돈다 → 구경 갔다 와서 자리가 틀어지는 길은 못 찾았다. 다만 **닫힌 뒤에 그 콜백이 도는 경우**(탭이 가려져 rAF 가 멈춘 사이 닫기)는 막혀 있지 않다 — `if (!_ifMode) return;` 한 줄. 다음 student.js PR 에 넣을 것.

- **그리기 순서**: 지금은 발밑 줄(`_decoFootRow`) 오름차순 한 번. 테두리는 '칸의 위 변'과 '아래 변'이 앞뒤가 다르다 — 위 변은 그 줄 물건 **뒤**, 아래 변은 **앞**에 그려야 한다(좌·우 변은 그 줄과 같은 깊이). 한 줄을 [위 변 → 물건 → 아래 변]으로 세 번 나눠 그려야 하고, 동물 DOM 층도 같은 규칙으로 `z-index` 를 0.5 단위로 써야 한다.
- **동물 우리 판정**: 지금 `_penAt` 은 '우리 장식의 footprint 안쪽'이다. 테두리로 두른 닫힌 영역을 우리로 보려면 **닫힘 판정(flood fill)** 이 필요하다 — 장식을 놓고 치울 때만 다시 계산해 캐시(걸음마다 계산 금지). 열린 울타리는 우리가 아니다 → 아이가 한 칸 틈을 남기면 동물이 새는 게 '말이 되는' 동작인지 결정 필요.
- **되돌리기**: 네모로 끌어 두른 것은 한 단계(`stroke`)로 — 지금 틀 그대로 된다. 다만 기록 비교가 `id·area·row·col·sp` 라서 **변 필드(`e`)를 비교에 넣어야** 같은 칸의 다른 변을 잘못 지우지 않는다(`_decoUndoOne`).
- **옛 캐시 JS**: `e` 가 붙은 항목을 옛 JS 는 **칸 장식으로** 그리고, 그 칸을 '찼다'고 본다. 더 나쁜 것: 옛 JS 가 그 상태로 통짜 저장을 해도 필드는 보존되지만, 옛 화면에서 아이가 그 '칸 장식'을 눌러 치우면 테두리가 사라진다. → 테두리 항목은 **다른 목록(`houseEdges`)에** 두는 쪽이 안전하다(옛 JS 는 모르는 필드를 그대로 되저장한다 — 통짜 set 이라 CUR 에 실려 있으면 보존됨. 단 `_normalizeArrays` 가 모르는 배열을 어떻게 다루는지 먼저 확인).
- 가진 개수: 지금은 '놓인 수'를 `houseDecorations` 에서 센다 — 다른 목록에 두면 **세는 곳 5군데**(`_decoPlace`·`_decoStrokeApply`·`_decoPickAt`·`_decoUndoOne`·`renderDecoInv`/`_decoRenderQuick`)를 한 함수로 모으는 정리가 먼저다.
