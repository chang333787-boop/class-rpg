## 2. 장식 SVG 파이프라인 (#160·#161·#162)

### 원인 — 늘리기가 두 번 곱해지고 있었다

```js
_dCtx.scale(sz.w > sz.h ? sz.w/sz.h : 1, sz.h > sz.w ? sz.h/sz.w : 1);
```

**`_dSofa`는 이미 가로로 긴 그림**(±0.82s × ±0.6s)인데 3×1이라는 이유로 `scale(3,1)`이 더 곱해진다.
그래서 3배 납작하다. 세로 3칸 아치는 3배 길쭉해지고, 가로등은 상자에 눌린다.

### 왜 `scale()`만 지우지 않았나

지우기만 하면 소파가 3칸 공간에 **1칸짜리로 작게** 뜬다(캔버스 그림은 정사각 ±s 기준).
"찌그러짐"이 "허전함"으로 바뀔 뿐이다. 그래서 **SVG 통로**를 냈다.

- `assets/deco/<id>.svg` **있으면** → footprint 폭에 맞추고 아래 끝을 바닥에 붙이고 **위로 넘김**
- **없으면** → 기존 그림 그대로. **지금 파일이 하나도 없으므로 화면 변화 0(회귀 없음)**
- SVG 한 장이 들어올 때마다 그 장식 하나가 고쳐진다. 코드는 다시 안 건드린다

부수: `_decoSorted`로 뒤(윗줄)→앞 정렬 — 위로 솟은 장식을 앞줄이 가리도록.

### 실측으로 걸러낸 함정 2가지

1. **SVG는 `image/svg+xml`로 내려와야 캔버스에 그려진다.** 로컬 테스트 서버가 `text/html`로 주자
   조용히 실패했다. GitHub Pages는 정상(`200 image/svg+xml` 확인).
2. **파일명을 `_`로 시작하면 Jekyll이 배포에서 빼버린다.** 예제 파일을 `_example…`로 넣었더니
   머지·배포 후에도 404. 같은 폴더 `README.md`는 200 → 원인 확정. `example-sofa-3x1.svg`로 변경.
   장식 id는 전부 `d_`로 시작하므로 실제 에셋은 무관하지만, 모르면 조용히 안 나온다.

검증: 로직 11/11(정렬·발밑·비율·넘침·캐시·폴백) · 브라우저 실렌더(소파 왜곡 없이 배치, 가로등 칸 위로 솟음) ·

## 🤝 SVG 담당에게 (메시지가 막혀 여기 남김)

**1) P0 팔레트 — 승인 요청할 것 없이 내가 끝냈다(#159 배포 완료).** 임시안이 아니라 정식으로 넣었다.
**2) P1 코드 — 내가 했다(#160 배포 완료).** 다만 "비율 늘리기 제거"를 그대로 하지 않고 SVG 우선 경로로 갈음했다(위 이유).
**3) 제작 순서 — 왜곡 16종 먼저.** 그다음 나머지 53종, 그다음 씨앗 10장. 사용자 결정(①+② 둘 다)에 맞는 순서다.
**4) 저장 경로 — `assets/deco/<id>.svg` 확정.** 규격은 `docs/deco_svg_spec.md`, 예제는 `assets/deco/example-sofa-3x1.svg`.

지켜야 할 것 세 가지만 다시 강조한다.
- `<svg>`에 **width·height 속성 필수** (없으면 캔버스에 안 그려짐)
- **위로만** 넘칠 것 (좌우로 넘기면 옆 칸과 겹침)
- 파일명 **밑줄로 시작 금지**

씨앗 10장은 `assets/seeds/<id>.png` 교체, 원본은 `assets/seeds/_old/`에 보존 — 다만
**`_old`도 밑줄이라 배포에서 빠진다.** 저장소에는 남지만 사이트에는 안 올라가니 의도한 바라면 그대로 두면 된다.
