## ② #198 좁은 화면 서랍 메뉴 (NARROW-1)

교사가 화면을 좁히면 왼쪽 메뉴가 **본문을 밀어냈다.** 숨기는 규칙(`.sidebar{display:none}`)이
`admin.css` 17번째 줄에 있긴 했는데 **도달하지 않는 죽은 줄**이었다.

- 죽은 줄은 지우고 **왜 지웠는지 주석을 남겼다.** 그냥 지우면 다음 사람이 "숨기는 규칙이 없네" 하고 다시 넣는다.
- 새 규칙은 전부 `@media(max-width:768px)` 안에, **파일 맨 끝 `[NARROW-1]` 블록**에 모아 뒀다.
  중간에 끼워 넣으면 위쪽 규칙과 우선순위 다툼이 난다.

**여기서 배운 것 — `@media`는 명시도를 올리지 않는다.** 같은 명시도면 **뒤에 오는 규칙이 이긴다.**
그래서 "미디어쿼리 안이니까 이기겠지"는 틀리다. 파일 끝에 두는 것이 사실상의 해법이다.

## ③ #201 승급 대기 카드의 `Lv.undefined` (PROMO-LV)

승급 대기 카드에 `Lv.undefined → undefined`가 찍혔다. 승급 요청 레코드(`r`)에 `level`이 없는 경우가 있었고,
카드는 `r.level`만 봤다.

```js
const lv = (r.level != null) ? r.level : s.level;   // 요청에 없으면 학생 현재 레벨
...
${lv != null ? `Lv.${lv} ` : ''}승급                 // 그래도 없으면 글자를 아예 뺀다
```

`||`가 아니라 `!= null`을 쓴 이유: **레벨 0**이 언젠가 생기면 `||`는 그것도 없는 값으로 친다.
그리고 마지막에 한 겹 더 둔 이유: 둘 다 없을 때 `Lv.` 만 덩그러니 남기지 않기 위해서다.
**모르는 값은 "undefined"라고 쓰지 말고 그 자리를 비운다** — 교사 화면에서 읽는 사람이 판단할 수 있어야 한다.

## ④ #203 손가락으로 누를 때만 44px (TOUCH-44)

버튼이 작아 아이들이 못 누른다는 지적. 전부 키우면 **마우스 화면이 헐거워진다.**
→ `@media (pointer: coarse)` — **손가락 기기에서만** 44px로 키운다. 마우스는 그대로다.

`student.css`·`admin.css` **맨 끝 `[TOUCH-44]` 블록** 한 곳에 모았다(②와 같은 이유).

**막혔던 자리 — `!important` 하나에 두 번 속았다.**
`.mtab`이 안 커지길래 처음엔 브라우저 캐시로 봤다(그것도 사실이었다). 캐시를 지워도 안 커졌다.
진짜 원인은 **`student.css`의 태블릿 구간(768~1024px)에 있는 `.mtab{padding:.5rem 1rem!important}`** 였다.
`!important`는 `!important`로만 넘는다. 그래서 `[TOUCH-44]`의 `.mtab`에도 `!important`를 붙였고,
**왜 붙였는지 주석에 적었다.**

→ **"안 먹는다"를 캐시로 결론짓지 말 것.** `getComputedStyle`로 실제 값을 찍어 보면 어느 규칙이 이겼는지 바로 나온다.

상단 두 버튼(`🖥️`·`🔍`)은 **인라인 `style`이라 클래스를 줄 수 없어** 이번에 못 잡고 #206으로 미뤘다.

## ⑤ #206 쉬운 말로 바꾸기 (WORDS-1)

학생 화면의 어려운 말을 바꿨다. 인벤토리→**가방** · 포트폴리오→**내 기록** · 데스크탑→**넓게 보기** ·
비율고정→**화면 맞춤** · 인테리어→**꾸미기** · `📱 모바일`→**좁게 보기**.
문장 속 `EXP`는 **경험치**로, 숫자 표시(`1240 / 5020 EXP`, `+30EXP`)는 그대로 뒀다.
상단 바에 `경험치(EXP)`를 **한 번만** 병기했다.

**바꾸지 않은 것 하나 — 보상 칭호 `'인테리어'`(`gamedata.js`).**
`s.titles`는 **문자열 배열**로 저장되고(`AchievementUtils.checkNew`) 이미 받은 학생 데이터 안에 그 문자열이 들어 있다.
이름만 바꾸면 **옛 칭호가 남은 채 새 칭호가 하나 더 붙는다.** 학생 데이터 마이그레이션이 같이 가야 하는 일이다.
코드 옆에 `[WORDS-1]` 주석으로 이유를 남겼다.

반면 **업적 이름은 바꿔도 된다.** 업적은 `a.id`로 저장된다(`achievements: ['ach_meta_port', ...]`) —
`name`은 표시 전용이다. **"이름이 화면에만 쓰이는가, 데이터에 저장되는가"가 갈림길이다.**

주석은 **코드 영역을 가리키는 것**(식별자가 `inventory`·`_ifMode` 그대로)은 두고,
**라벨을 그대로 인용한 주석**만 함께 고쳤다. 안 그러면 주석이 화면과 어긋난 채 굳는다.

**라벨 하나에도 실측이 필요했다.** `경험치(EXP)`를 431px에 넣으니 EXP 바가 99px → **41px**로 눌렸다.
숨김 기준을 431px이 아니라 **700px**로 잡았다 — `[HUDBTN-1]`이 상단 두 버튼을 빼는 자리와 같은 곳이다.

#203에서 미룬 상단 두 버튼 44px도 여기서 잡았다. 인라인 `style`을 `.hud-mini-btn`으로 빼고
`[TOUCH-44]`에 넣었다. **인라인 값을 그대로 옮겼는지 머지 전 원본과 대조해 확인**했다(마우스 78×29 → 81×29, HUD 높이 62px 그대로).

## ⑥ 촬영 도구 함정 2건 — **캡처를 근거로 판단하기 전에 읽을 것**

오늘 P0로 올라온 화면 문제 중 **여러 건이 실제 버그가 아니라 촬영 도구 문제**였다.
캡처는 증거처럼 보이기 때문에 이 함정은 특히 비싸다.

**(1) 등장 애니메이션 중간을 찍으면 "빈 화면"이 된다.**
모달이 뜨는 애니메이션(투명도·이동) 도중에 찍히면 내용이 흐리거나 아예 안 보인다.
이걸 근거로 **"화면이 비어 있다" P0가 6건** 올라왔고, 실제로는 전부 정상이었다.
→ 찍기 전에 **애니메이션을 끄거나**(`* { animation:none!important; transition:none!important }`)
   **`animationend`를 기다린다.** "잠깐 기다렸다 찍기"는 기기가 느리면 또 어긋난다.

**(2) 헤드리스의 `--window-size`는 CSS 뷰포트가 아니다.**
`--window-size=375`로 찍으면 **이미지는 375px인데 페이지는 492px로 배치**되고 오른쪽 24%가 잘려 나간다(이 PC 실측).
492px 배치를 375px로 자르면 오른쪽 열의 숫자가 정확히 잘린다 — 그래서
**실재하지 않는 P0-3(능력치 값 잘림)**이 만들어졌다. 실제 코드는 375·390·768px 어디서도 넘치지 않았다.
자세한 실측과 대책은 [2026-09-10-ui375.md](2026-09-10-ui375.md) ③에 있다.
→ **iframe을 목표 폭으로 두고 찍거나**(iframe은 자기 폭이 곧 CSS 뷰포트라 미디어쿼리도 제대로 걸린다)
   **CDP로 뷰포트를 직접 지정**한다.

**그래서 규칙:** 캡처로 올라온 화면 버그는 **먼저 코드로 재현해 본다.**
`getComputedStyle`·`getBoundingClientRect`·`scrollWidth` vs `clientWidth`는 거짓말을 하지 않는다.
재현이 안 되면 **촬영 조건부터 묻는다** — 없는 버그를 고치면 멀쩡한 코드가 상한다.
