## 무엇이 잘못됐나
`speechSynthesis.getVoices()`는 **비동기로 채워진다**. 브라우저가 목록을 준비하기 전에는 빈 배열을 돌려준다.
`hasVoiceFor()`는 이 빈 배열을 보고 "음성이 없다"고 단정했다. 그래서 **페이지를 열자마자 받아쓰기 문항에 들어가면
"이 기기에서는 한국어 소리가 나오지 않아요 · 이 문제 건너뛰기"가 잘못 떴다.** 잠시 뒤 목록이 채워지면 정상으로 돌아오지만,
학생은 이미 안내를 보고 문제를 건너뛴 뒤다. 크롬북처럼 느린 기기에서 더 잘 난다.

하네스에서 재현: 로드 직후 받아쓰기 100문항을 훑으면 전부 안내 화면 → 몇 초 뒤 같은 검사를 하면 전부 정상.

## 고친 것
1. `hasVoiceFor()` — 목록이 **비어 있으면 '없다'가 아니라 '모른다'**로 본다(`if (!vs.length) return true;`). 잘못된 안내보다 소리 버튼을 보여 주고 시도하는 편이 낫다.
2. `onvoiceschanged` — 목록이 늦게 왔을 때 **열려 있는 듣기 문항을 한 번 다시 그린다**(보스 제안). 안내가 떠 있었다면 소리 버튼으로 바뀌고, 정말 음성이 없는 기기라면 그대로 안내가 남는다. `STUDY_SESSION`·`study-body`가 있을 때만 동작하고 try/catch로 감쌌다.

## 교훈
브라우저가 비동기로 채우는 목록(`getVoices`·폰트·미디어 트랙)은 **"비어 있음 = 없음"이 아니다.** 사용자에게 단정적인 안내를 띄우기 전에 "아직 모른다" 상태를 따로 두어야 한다.
