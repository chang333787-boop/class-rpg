# 프로토타입 둘 — 고장 · 정치 (폐기 가능 · 작업 지시 정본)

> 2026-09-20 밤 · 사용자 확정(외부 조언자 3차). **본편 완성도를 높이는 작업과 구분한다.**
> 이것은 **버릴 셈으로 만드는 시험**이다. 목적은 "된다/안 된다"를 알아내는 것이지 예쁘게 만드는 것이 아니다.

## 0. 두 질문

| 프로토타입 | 답할 질문 하나 |
|---|---|
| **고장** | 마을을 작게 묶어 보여 줘도, **아이가 물건이 어디서 와서 어디에 쓰이는지 따라가 문제를 고칠 수 있는가** |
| **정치** | **같은 결정이 사람마다 다른 결과를 낳는 것**을 기존 세계에서 비교해 보일 수 있는가 |

이 두 답이 나오면 프로토타입은 끝이고, 본편에 무엇을 가져갈지 판단한다.

## 1. 공통 규칙

- 기존 그래픽·색·건물·주민을 **재사용**한다. 새 건물 묶음·완성형 줌 애니메이션 금지.
- **본편과 분리된 진입 경로와 시험 저장 공간.** 기존 저장본과 본편 규칙을 바꾸지 않는다.
- 줌 대신 **화면 전환 버튼**으로 충분하다.
- 계산은 실제 상태가 하고, 주민·운반은 그 결과를 **연기만** 한다.
- 실제 학생이 확인하지 않은 것을 '학습 검증 완료'로 적지 않는다.
- 범위를 늘려야 할 것 같으면 **먼저 범위 안에서 단순화**한다. 정말 새 기능이 필요하면 까닭과 선택지를 보스에게 보고한다.
- **⚠ '줌 단계 = 단위 단계'는 아직 가설이다.** 화면에서 마을을 작은 모형으로 묶는 것과, 내부 계산을 마을 단위로 바꾸는 것은 **별개의 결정**이다. 이번 시험에서 계산 단위를 바꾸지 않는다.

## 2. 고장 프로토타입

### 2-1 시험 세계 (고정)
마을 둘을 미리 배치한다. **아이가 마을을 새로 만드는 기능은 만들지 않는다.**

| 구성 | 역할 |
|---|---|
| 마을 A | 밭에서 **상품 한 종류**를 생산 |
| 마을 B | 가게가 받아 주민에게 공급 |
| 마을 사이 연결 | A → B 운반(단방향) |

돈·가격·양방향 교환·여러 상품 금지. 기존 흐름(#745~#752)을 **재사용**한다. 정상 상태에서 공급이 끊기지 않도록 생산량·사용량을 정하고 **쓴 값과 단위를 시험 설정에 적는다.**

### 2-2 화면 셋
- **고장**: 마을 A·B를 작은 모형으로 · 연결 · 운반 중인 물건 · 마을을 누르면 들어감 · 연결을 놓고·끊고·다시 잇기
- **마을 A**: 밭과 출발지 보관량 · 생산 중단/재개 시험 · 고장으로 돌아가기
- **마을 B**: 가게 재고와 쓰는 모습 · 가게를 누르면 **공급 출처와 상태** · '공급 경로 보기' → 고장에서 그 연결 강조 · 고장으로 돌아가기

세 화면은 **하나의 같은 시험 상태**를 읽는다. 화면을 바꿀 때 마을을 새로 만들거나 재고를 초기화하지 않는다. **화면을 바꿔도 같은 시간이 흐른다.**

### 2-3 원인 셋을 구분
| 상태 | 실제 조건 | 반드시 보일 것 |
|---|---|---|
| 공급원 없음 | 연결할 생산 시설이 없음 | 어디서 받아야 하는지 |
| 연결 단절 | 공급원은 있는데 운송 연결이 끊김 | 끊긴 연결 강조 + 출발지 재고 |
| 운송 중 | 이어져 있고 물건이 가는 중 | 이동과 도착 대기 |

가게가 비었다는 이유만으로 같은 경고를 띄우지 않는다. '시설은 있는데 아직 생산 전'은 기존 상태로 설명한다.

### 2-4 끊겼을 때 물건 — **구현 전에 설계 한 장**
생산한 물건을 어디에 두나 · 출발·도착 때 어느 재고가 변하나 · 운반 중 끊기면 기다리나 돌아가나 · 생산 시설을 없애면 남은 재고는 · 저장·복원 때 운반 중 물건은. 기존 흐름에 일관된 처리가 있으면 그대로 쓴다.
**물건이 설명 없이 생기거나 사라지는 구현은 통과시키지 않는다.**

### 2-5 완료 시험 (각각 초기 상태에서)
- **A 정상 공급**: 잇는다 → 생산·출발·도착·사용 → 화면을 오가도 상태가 이어진다
- **B 연결 단절**: 끊는다 → 재고·운반 중 물건이 규칙대로 → 까닭이 '연결 단절'로 → 다시 잇는다 → 정해진 운송 시간 뒤 회복
- **C 공급원 제거**: 밭을 없앤다 → 남은 물건 처리·공급 중단 → **연결 단절과 다른 설명** → 복구 → 다시 공급
- **D 저장·복원**: 운반 중에 저장 → 다시 열기 → 재고·운반·시간이 정한 대로 이어짐

통과는 **구현 완료**로만 기록한다.

## 3. 정치 프로토타입 (주민자치 하나)

> 두 동네가 공공시설 하나를 함께 쓴다. 놓을 자리가 둘이고, 자리에 따라 가까워지는 주민과 멀어지는 주민이 갈린다. 이유를 듣고 정한 뒤 결과를 본다.

- 시설은 **접근성 차이가 분명한 기존 시설** 하나(새 건물 만들지 않는다). 두 동네 주민 수는 **같게** 시작(수가 많아 자동으로 정해지지 않게).
- 화면: 두 동네와 주민 · 후보지 A/B · 각 안의 이용 경로·접근 상태 · 두 동네의 **짧은 의견 카드(이유)** · [A안 미리 보기] [B안 미리 보기] [결정 적용] [다시 살펴보기].
- **미리 보기는 세계를 바꾸지 않는다.** 적용을 눌러야 실제로 바뀐다.
- 토의·투표는 **교실에서** 한다. 온라인 투표·채팅·AI 발언 생성·대표 선출 만들지 않는다.
- **승패로 처리하지 않는다**: 정답 후보지 없음 · 만족도 총점 판정 없음 · 가까워진 주민과 **남은 불편**을 함께 보여 줌 · 초기 상태로 되돌리기.
- 되돌아보기 세 질문: ① 어떤 이유로 이 자리를 골랐나요 ② 누구의 이용이 편해졌고 누구의 불편이 남았나요 ③ 결정 과정이나 결과에서 다시 살펴볼 점은.
- 완료 시험: 두 안을 미리 본다 → 접근성 차이가 **실제 판정과 일치** → 하나를 적용 → 미리 본 결과와 **같은지** → 초기로 되돌려 다른 안 적용 → **앞 실행의 흔적이 남지 않는지**.
- 이 시험의 목적은 **공동 결정의 결과를 기존 세계에서 표현할 수 있는가**다. 민주주의 학습 효과를 검증했다고 보고하지 않는다.

## 4. 다른 정치 상황은 **설계 카드만** (구현 금지)
학급 · 학교 · 주민자치 · 지방자치 · 나라 · 국제 협력. 각 한 장 이내로 **문제 · 참여자 · 결정 권한 · 적용 범위 · 화면 변화**. 이름만 바꾼 같은 판으로 쓰지 말 것 — **누가 어떤 권한으로 정하는지**가 달라야 한다. 시위는 이번 구현에서 제외(불만이 차면 터지는 재난·인원이 많으면 이기는 장치로 만들지 않는다). 학년·성취기준 대응은 원문 확인 전까지 **미검증**으로 표시.

## 5. 담당
| 담당 | 이번 작업 | 산출물 |
|---|---|---|
| 보스 | 범위 고정 · 공통 상태와 완료 기준 확정 · 통합 판단 | 작업표 · 통합 실행본 |
| 프로그램 | 두 마을의 흐름 연결 · 화면 왕복 · 정치 미리 보기/적용 | 실행 가능한 프로토타입 |
| 디자인(도우미 가능) | 기존 자산으로 마을 모형 · 재고 · 연결 상태 · 후보지 구별 | 상태별 최소 표현 |
| 주민 연기 | 운반·이용 장면 | 실제 상태에 연결된 연기 |
| 창조자의 눈 | 공급 원인 찾기 · 후보지 비교의 설명 경로 관찰 | 사실 / 해석 / 가설을 나눈 기록 |
| 검증 | 수량·시간·저장 · 미리 보기와 실제 결과 | 시험별 예상과 실제 |
| 교육과정 조언 | 정치 상황 카드의 역할·권한 구분 | 가르칠 수 있는 것과 한계 |

프로그램이 상태와 전환 조건을 쓰면 **보스가 검토해 같은 정의를 전 담당에 배포**한다. 각 담당이 원인을 따로 추측하는 로직을 만들지 않는다. 디자인 완성을 기다리며 구현을 멈추지 않는다.
