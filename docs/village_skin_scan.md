## 한 줄

**생각보다 가깝다.** 건물 모양(`parts`)이 이미 **순수 데이터**이고, 판 파일은 **`K` 표가 만들어진 뒤·트레이가 짜이기 전**에 읽힌다 — 즉 **새 종류를 끼워 넣을 자리가 이미 있다.** 색·계절·해금·칭호도 전부 상수 표라 칸으로 빼기 쉽다. 남는 벽은 '그림을 누가 그리나'(디자인)와 '저장본을 판 밖으로 가져갔을 때'다.

## 0. 지금 판 파일이 **이미** 바꾸는 것

`id` · `이름` · `교과` · `질문` · `되돌아보기` · `현상` · `변수` · **`시작`(시작 땅 저장본)** · **`규칙`(VRULES 덮기)** · **`건물`(쓸 종류 고르기)** · `목표`.

→ 농촌 판에 필요한 것 가운데 **시작 땅 · 규칙 · 건물 고르기 · 판 카드 질문은 오늘도 된다.** 못 하는 것은 **색·계절·하늘·새 종류·해금·칭호**다.

## 1. 못 바꾸는 것 — 하나씩

| # | 무엇 | 지금 어디에 박혀 있나 | (a) 빼기 쉬운가 | (b) 기존 판 영향 | (c) 예상 줄 수 |
|---|---|---|---|---|---|
| ① | **풀색 · 바닥색** | `SEASONS[4]` 의 `grass` · `ground` 를 틱마다 `plotMat.color` · `groundCol` 에 부드럽게 섞는다 | ○ 쉽다 — 판이 `SEASONS` 를 덮거나 고정색 칸 하나 | 칸이 없으면 그대로 — **0** | ~10 |
| ② | **계절 고정** | `seasonIdx()` = `simDay()` 기반(28일마다) | ○ 쉽다 — `계절:"여름"` 이면 그 값을 돌려준다 | 0 | ~6 |
| ③ | **하늘 · 안개 · 빛** | `scene.background`·`scene.fog` 는 `P.sky`, 낮 하늘은 `SKY_DAY`(계절), 해 `DirectionalLight`·`HemisphereLight` 는 고정 색·세기 | △ 중간 — **밤낮 보간과 얽혀 있다**(하루에 걸쳐 lerp) | 0(칸 없으면) | ~12 |
| ④ | **나무 종류 · 바깥 숲** | 판 밖 장식 숲(`forestLeaves`)은 잎 색만 계절로 바뀐다. 종류·밀도는 코드 | △ 중간 — 색만이면 ①과 같고, **종류를 바꾸려면 새 종류(⑥)가 먼저** | 0 | 색만 ~4 |
| ⑤ | **마을 이름(칭호)** | `TITLES` 배열(코드) · 조건 함수가 딸려 있다 | ○ 쉽다 — 판이 목록을 덮는다. 단 **조건이 함수**라 판 파일은 '이름·아이콘'만 갈아끼우는 쪽이 안전 | 0 | ~8 |
| ⑥ | **새 건물 종류**(밭 · 헛간) | `K` 표. **그런데 `parts` 가 순수 데이터다**: `{ g:'box'\|'cyl'\|'cone'\|'half'\|'sph', c:색, s:[x,y,z], p:[x,y,z] }` | ○ **생각보다 쉽다** — JSON 으로 그대로 쓸 수 있다. 색만 `P` 의 이름(문자열 → 숫자)으로 바꿔 주면 된다 | 0(그 판에서만 `K` 에 더한다) | ~25 |
| ⑦ | **해금 표** | `UNLOCKS` 배열(인구 문턱 → 종류) · `LOCK_POP` 이 여기서 파생 | ○ 쉽다 — 판이 표를 덮고 `LOCK_POP` 을 다시 만든다 | 0 | ~8 |
| ⑧ | **시작 땅**(저장본) | **이미 된다**(`시작` 칸) | ✓ | — | 0 |
| ⑨ | **건물 목록 고르기** | **이미 된다**(`건물` 칸 · 목록 밖은 트레이에서 빠지고 놓기도 막힌다) | ✓ | — | 0 |

## 2. 왜 ⑥이 생각보다 쉬운가 (핵심)

```js
road: { nm:'길', ic:'⬜', grp:'바닥', w:1, h:1, g:1, road:true, cap:1100, parts:[
  { g:'box', c:P.pave,   s:[CS,.16,CS],         p:[0,.08,0] },
  { g:'box', c:P.paveIn, s:[CS*.74,.04,CS*.74], p:[0,.17,0] } ] },
```

- **모양이 데이터다.** 상자·원기둥·원뿔·반구·구 다섯 가지 조합. 밭(낮은 상자 + 고랑 줄) · 헛간(상자 + 지붕 반구/원뿔)은 이 다섯으로 충분히 만들 수 있다.
- **판 파일이 읽히는 시점이 맞다.** `[MAC-STAGE]` 의 판 로드는 `await fetch` 로 module 최상위에서 일어나는데, 그 자리가 **`K` 표(326줄)가 이미 만들어진 뒤 · 트레이(`buildTray`)와 해금(`UNLOCKS`)이 쓰이기 전**이다. `stageApplyEarly(def)` 가 이미 `건물` 칸으로 `ORDER` 를 손보고 있다 — **같은 자리에서 `K[새이름] = {...}` 을 더하면 된다.**
- 나머지 칸(`nm`·`ic`·`grp`·`w`·`h`·`cap`·`need`·`jobs`·`needRoad`)도 전부 데이터다. 즉 **밭이 '놀이'를 채우게 하거나 헛간에 일자리 2를 주는 것까지 판 파일로 된다.**

**그래서 완료 시험(`farm.json`)에 실제로 필요한 것은 ①(들판 바닥색)과 ⑥(밭·헛간) 둘뿐이다.** 풍차는 이미 있고(`windmill`), 시작 땅·질문·목표·규칙은 오늘도 된다.

## 3. 조심할 것 (조사에서 드러난 것)

1. **저장본을 판 밖으로 가져갈 때.** 저장본은 `palette`(종류 이름 목록)로 칸을 적는다. 판에서만 있는 종류(`밭`)가 적힌 저장본을 **기본 마을로 가져오면** 그 종류를 모른다. 지금도 저장 키가 판마다 달라 섞이지는 않지만, **파일 내보내기/가져오기**로는 건너갈 수 있다 → 가져오기에서 **모르는 종류는 빈 칸으로 두고 한 줄 말하기**가 필요하다(그 판에서만 쓰는 것이라고).
2. **그림은 누가 그리나.** `parts` 로 만든 밭·헛간이 지금 마을의 그림 결과 어울리는지는 **디자인 담당의 눈**이 필요하다. 조사자(나)가 대충 쌓으면 '모양은 되는데 마을이 아니게' 된다.
3. **계절과 고정색의 충돌.** ①을 고정색으로 주면 ②(계절)가 돌 때 색이 도로 섞인다 — **둘을 한 칸으로 묶는 편이 안전하다**(`모습: { 계절:"여름", 풀:"#..", 바닥:"#.." }`).
4. **해금을 덮으면 목표와 어긋날 수 있다.** ⑦을 판이 덮을 때 그 판의 `목표` 가 잠긴 종류를 요구하지 않는지 **판 검사(stages.mjs)에서 확인**해야 한다(지금 검사에 없는 항목 — 한 줄 추가 필요).
5. **`건물` 칸과 새 종류의 순서.** `건물` 목록은 `K` 에 있는 것만 남긴다(`def.건물.filter(k => K[k])`). 새 종류를 더하는 일이 **그보다 먼저** 일어나야 한다.

## 4. 가장 값싼 순서 (제안)

| 순서 | 무엇 | 줄 수 | 왜 이 순서인가 |
|---|---|---|---|
| **1** | **`모습` 칸 하나** — 계절 고정 + 풀색 + 바닥색(①②를 묶어서) | ~14 | 가장 싸고, 농촌·도시가 **첫눈에 달라 보이는 것**이 색이다. 충돌(조심할 것 3)도 묶으면 사라진다 |
| **2** | **`건물정의` 칸** — 판이 `K` 에 새 종류를 더한다(⑥) | ~25 | 완료 시험의 나머지 절반. 1 과 2 만 있으면 **`farm.json` 이 실제로 열린다** |
| **3** | 하늘·안개·빛(③) | ~12 | 색이 바뀐 뒤에야 하늘이 어색해 보인다 — 1·2 를 보고 판단 |
| **4** | 해금 표(⑦) · 칭호(⑤) | ~16 | 수업 판에서 '무엇부터 열리나'를 다룰 때 필요. 급하지 않다 |
| **5** | 바깥 숲 종류(④) | ~4~ | 3 을 하고 나서 |

**1 + 2 만으로 완료 시험이 된다**(예상 ~40줄 · `index.html` 은 고치지만 **`farm.json` 을 여는 쪽에서는 수정 0**).

### 첫 삽으로 제안하는 칸 모양

```json
{
  "모습": { "계절": "여름", "풀": "#c8d98a", "바닥": "#d9c98a" },
  "건물정의": {
    "field": { "nm": "밭", "ic": "🌾", "grp": "바닥", "w": 2, "h": 2, "cap": 200,
      "parts": [ { "g": "box", "c": "sand", "s": [2, 0.12, 2], "p": [0, 0.06, 0] } ] },
    "barn":  { "nm": "헛간", "ic": "🏚️", "grp": "건물", "w": 2, "h": 2, "jobs": 2, "needRoad": true,
      "parts": [ { "g": "box", "c": "wood", "s": [1.8, 1.2, 1.8], "p": [0, 0.6, 0] },
                 { "g": "half", "c": "red", "s": [1.9, 0.9, 1.9], "p": [0, 1.2, 0] } ] }
  }
}
```

- 색은 **`P` 의 이름**(`"wood"`·`"sand"`·`"red"`)이나 `#rrggbb` 둘 다 받게 하면 판 쓰는 사람이 편하다.
- 크기는 칸 단위(`CS` 곱은 코드가 한다) — 판 파일에 코드 상수를 쓰게 하지 않는다.

## 5. 이 조사가 확인 못 한 것

- **성능**: 새 종류가 청크 합치기(`parts` → 인스턴스)에 들어갈 때 비용은 기존 종류와 같을 것으로 보이지만 **안 쟀다**.
- **`grp`(트레이 묶음)가 새 이름이면** 트레이 탭이 어떻게 되는지 안 봤다 — 기존 묶음('바닥'·'건물'·'꾸밈'…) 중 하나를 쓰게 하는 편이 안전해 보인다.
- **판 검사(stages.mjs)** 에 새 칸(`모습`·`건물정의`)의 검사를 어떻게 넣을지는 구현 때 정한다(해금·목표 어긋남 확인 포함).
- 이 문서는 **읽기만** 했다. `index.html` 수정 0 · 운영 DB 접촉 0.
