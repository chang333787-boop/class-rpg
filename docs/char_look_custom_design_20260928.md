# 캐릭터 머리·얼굴·피부 따로 고르기 — 설계 (CHAR-LOOK-1 · 2026-09-28)

> **상태: 설계만. 구현 전 사용자 승인 필요** (학생 저장 구조에 새 필드 — CLAUDE.md §6 고위험).
> 앞선 작업: CHAR-DRESS-FIT-1(겹침 규칙·어깨·위팔) · CHAR-IDLE-1(숨쉬기·깜빡임) · SHOP-TRYON-1 · CHAR-AURA-1 — PR #1117.

## 1. 지금 구조 (조사 결과)

| 항목 | 현재 |
|---|---|
| 저장 | `students/<id>.charType` = 1~4 (정수 하나) |
| 정하는 곳 | 학생 첫 로그인 `s-charsel` 화면(`selChar`·`confirmChar`, student.js 165~180) · 교사 학생 추가(admin.js 952) |
| 쓰는 곳 | `buildCharDoll`(base_N.svg 한 장) · 옛 그림 `buildCharSVG`(폴백) · `Utils.charEmoji`(HUD 이모지) |
| 저장 방식 | `DB.saveStudent` 가 학생 객체를 **통째로 set** → 새 필드도 그대로 저장됨(규칙이 필드를 막는지 확인 필요) |
| base 한 장에 묶인 것 | 피부색 · 머리 모양 · 머리색 · 눈동자색 · 입(여/남) · 옷(기본 셔츠·바지·신발) |

즉 charType 하나가 **피부·머리 모양·머리색·눈색**을 한꺼번에 정한다. 4가지 조합만 있다.

## 2. 목표 (메이플 수준의 '나만의 캐릭터')

- 피부 4~5 · 머리 모양 6~8 · 머리색 8 · 눈 모양 3~4 · 눈색 5 를 **따로** 고른다.
- 이미 쓰는 charType 학생은 **아무것도 안 해도 지금 모습 그대로**.
- 모자 규칙(hair-top/hair-cap/full-helm)·깜빡임·숨쉬기는 그대로 동작.

## 3. 저장 — `look` 필드 하나 더 (마이그레이션 없음)

```js
student.look = { skin: 's2', hair: 'long', hairColor: 'purple', eyes: 'round', eyeColor: 'violet' }   // 없으면 charType 에서 유도
```

- **읽기**: `lookOf(s) = s.look || LOOK_FROM_CHARTYPE[s.charType || 1]` — 옛 데이터는 절대 안 건드린다.
- **쓰기**: 학생이 '모습 바꾸기'에서 확정할 때만 `CUR.look = {...}` 후 `DB.saveStudent`. charType 은 그대로 둔다(옛 코드·교사 화면·이모지 호환).
- 값은 **문자열 키만**(자유 입력 없음) · 모르는 키면 기본값으로 그림 → 데이터가 코드보다 앞서도 안 깨짐.
- ⚠️ 확인할 것: RTDB 규칙이 `students/<id>` 아래 새 키를 막지 않는지(규칙 파일은 이 저장소에 없음 — 콘솔에서 읽기만). `_normalizeArrays`·`_migrate` 는 **손대지 않는다**(look 은 객체라 배열 정규화 대상 아님).

## 4. 그림 — base 를 층으로 나누기

지금 `base_N.svg` 한 장 → 아래 층으로 쪼갠다(모두 120×160 같은 좌표).

| 층 | 파일 | 색 바꾸는 법 |
|---|---|---|
| 몸(피부) | `body_skin.svg` 한 장 | 피부색은 `fill="var(--skin)"` 자리표시 → 합성 때 문자열 치환(`#SKIN#`) |
| 기본 옷 | `outfit_basic.svg` | 고정 |
| 얼굴 | `face_<eyes>.svg` | 눈동자 `#EYE#` 치환 · 눈꺼풀(blink)도 `#SKIN#` |
| 머리 | `hair_<style>.svg` (hair-bottom · hair-mid · hair-top · hair-cap 네 묶음 그대로) | `#HAIR#`·`#HAIR_HI#`(밝은 줄) 치환 |

- 색은 **파일을 늘리지 않고 치환**으로 — 머리 8모양 × 8색이 64장이 아니라 8장.
- 합성 순서는 지금과 같다: 몸 → 기본옷 → (옷 장비) → 신발 → 장갑 → 얼굴 → 머리(모자 규칙) → 모자 → 무기 → 손가락.
  단, 지금 base 안에서 얼굴이 옷보다 **먼저** 그려지는 부분(목·머리 뒤 머리카락)은 층 순서표로 명시한다.
- 옛 4장은 새 층으로 **정확히 같은 그림**이 나오게 먼저 쪼갠 뒤(비교판 픽셀 차 0 목표) 새 모양을 더한다.

## 5. 화면

- 캐릭터 카드에 [✂️ 모습 바꾸기] → 큰 미리보기 + 칸별 칩(피부·머리·머리색·눈·눈색) → [이대로 할래요]. SHOP-TRYON 과 같은 '지금 ↔ 바꾼 뒤' 나란히.
- 첫 로그인 `s-charsel` 은 지금 4장 고르기 유지(빠른 시작) + "나중에 모습 바꾸기에서 더 꾸밀 수 있어요".
- 교사 화면은 이번 범위 밖(학생 목록 이모지는 charType 그대로).
- 바꾸기 비용: 기본 무료(학습 흐름 방해 금지). 판마다 켜는 '미용실 골드' 옵션은 나중(케이스별로 열어 두기).

## 6. 단계 (한 PR 씩)

1. **LOOK-0 층 쪼개기** — base 4장 → 층 파일 + 치환 합성. 저장 무변경. 비교판 옛/새 픽셀 차 0 확인. (저위험)
2. **LOOK-1 새 모양 추가** — 머리 4모양·눈 2모양·색 표. 저장 무변경(하니스에서만 look 주입해 확인).
3. **LOOK-2 모습 바꾸기 화면 + look 저장** — ⚠️ 여기서 처음 저장 구조가 바뀜 → **사용자 승인 후**. 규칙 확인·연습반 계정으로만 실저장 확인.
4. **LOOK-3 모자 규칙 재검** — 새 머리 모양마다 hair-cap(모자 아래 앞머리·옆머리) 그리기 · char-combo-check 에 look 조합 추가.

## 7. 위험과 막는 법

| 위험 | 막는 법 |
|---|---|
| 옛 학생 모습이 바뀜 | look 없으면 charType 표로 유도 · LOOK-0 픽셀 차 0 |
| 저장 경쟁(onDataChange 가 CUR 교체) | 기존 saveStudent 경로만 사용 · 새 쓰기 경로 안 만듦 |
| 규칙이 새 키 거부 | LOOK-2 전에 규칙 읽기 · 거부면 규칙 변경은 별도 승인 |
| 크롬북 성능 | 층이 늘어도 SVG 문자열 합성 1회 · 치환은 문자열 replace — 지금과 같은 비용대 |
