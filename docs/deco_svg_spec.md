# 장식 SVG 규격 (DECO-SVG-1)

- 작성: 2026-09-04 · 기준 코드: `student.js` `_drawDecoSVG` / `_decoImg`
- 대상: 마당·집 안 장식 69종. SVG 제작 담당(SVG 세션)과 배치 코드(보스) 사이의 계약.

## 왜 필요한가 — 지금 무엇이 잘못됐나

배치 루프가 비정사각 장식을 **비율을 억지로 늘려서** 그리고 있었다.

```js
_dCtx.scale(sz.w > sz.h ? sz.w/sz.h : 1, sz.h > sz.w ? sz.h/sz.w : 1);
```

`_dSofa`는 **이미 가로로 긴 그림**(±0.82s 폭 × ±0.6s 높이)인데, 3×1 소파라는 이유로
`scale(3, 1)`이 한 번 더 곱해진다. 결과가 3배 납작한 소파다. 세로 3칸 장미 아치는 3배 길쭉해진다.
가로등·허수아비처럼 **위로 솟아야 하는 것**도 footprint 상자 안에 눌려 담긴다.

## 어떻게 고치는가 — 데이터가 코드를 이긴다

`assets/deco/<id>.svg` 가 **있으면** 그 그림을 쓰고, **없으면** 기존 캔버스 그림을 그대로 쓴다.
즉 **SVG를 한 장 만들 때마다 그 장식 하나가 고쳐진다.** 코드를 다시 건드릴 필요가 없고,
아직 그림이 없는 장식은 지금 모습 그대로다(이번 변경으로 아무것도 안 바뀜).

배치 규칙은 세 줄이다.

```js
const w = bw;                    // 폭 = footprint 폭 (땅에 닿는 넓이)
const h = w * (nh / nw);         // 높이 = 비율 그대로. 절대 늘이지 않는다
drawImage(img, px, py + bh - h, w, h);   // 아래 끝을 footprint 바닥에 붙인다
```

## 제작 규격 (지켜야 할 것)

| 항목 | 규칙 |
|---|---|
| 경로·이름 | `assets/deco/<장식 id>.svg` — id는 `gamedata.js`의 `decorations[].id` 그대로 (`d_i8`, `d_y21` …) |
| **밑줄 금지** | 파일명을 `_`로 시작하면 **Jekyll이 배포에서 제외해 404**가 된다(2026-09-04 실측 확인). 장식 id는 전부 `d_`로 시작하므로 정상 파일은 문제없다 |
| **width/height 속성** | **필수.** `<svg width="300" height="150" viewBox="0 0 300 150">`. 이게 없으면 브라우저가 크기를 모르고, 캔버스에 **아무것도 안 그려진다** |
| viewBox 폭 | footprint 가로 칸수에 비례. 3×1이면 폭:높이 기준을 3칸으로 잡는다 |
| viewBox 높이 | footprint 높이 + **위로 필요한 만큼**. 가로등처럼 1×1인데 위로 솟는 것은 높이를 크게 잡으면 된다 |
| 원점·바닥선 | 그림의 **맨 아래가 땅에 닿는 선**이다. 그림자·다리를 viewBox 아래쪽 끝에 맞춘다 |
| 넘침 | **위로만** 넘친다. 좌우로 넘기면 옆 칸 장식과 겹친다 — 폭은 footprint 안에서 끝내라 |
| 그림체 | 두꺼운 외곽선 + 셀셰이딩 + 하이라이트 (기존 캐릭터·에셋과 같은 결) |
| 축소 검증 | 실제 셀은 일반 모드에서 **17~30px**. 24px·38px로 줄여 보고 형태가 남는지 확인할 것 |

### 납품 규격 (SVG 담당 제안 — 코드에서 그대로 맞음, 2026-09-04 검증)

단위 셀 = 100으로 두고 **viewBox = (w×100) × ((h+1)×100)**. 아래 h칸이 footprint, 맨 위 1칸이 여유.

| footprint | viewBox | 화면 배치 결과 |
|---|---|---|
| 3×1 소파 | `0 0 300 200` | `drawImage(px, py−C, 3C, 2C)` |
| 3×2 헛간 | `0 0 300 300` | `drawImage(px, py−C, 3C, 3C)` |
| 1×1 가로등 | `0 0 100 200` | `drawImage(px, py−C, C, 2C)` |

배치 코드는 **비율만 보고** 계산하므로(`h = w × nh/nw`, 아래 끝을 바닥에 정렬),
위 규격이 자동으로 "위로 정확히 1칸 넘침"이 된다. 코드 수정 없이 맞는다.

**여유 1칸에 묶이지 않아도 된다.** 더 높이 솟는 것(큰 나무 등)은 viewBox 높이를
`(h+2)×100`처럼 키우면 그만큼 위로 넘친다. 규칙은 하나뿐 — **아래 h칸이 footprint, 맨 아래가 땅**.

## 두 종류 — '서 있는 물건' 과 '칸을 덮는 것' (2026-09-20 추가)

놀이판에서 1×1 꽃 장식을 3×3 으로 깔아 보니 **꽃밭이 아니라 꽃다발 9개**로 보였다(칸 사이에 풀이 남는다).
그림이 작아서가 아니라 **그리는 방식**이 '서 있는 물건'이었기 때문이다. 그릴 때 먼저 어느 쪽인지 정한다.

| | **서 있는 물건** (나무·벤치·동물·집·꽃다발) | **칸을 덮는 것** (꽃밭·잔디 무늬·길·화단 바닥) |
|---|---|---|
| 어디에 넣나 | `assets/deco/<id>.svg` (장식) | **`assets/floor/tile_<이름>[_a~_d].svg` (바닥 타일)** 이 기본. 장식으로 넣는 것은 길처럼 '조각'일 때만 |
| viewBox | (w×100) × ((h+1)×100), 위로 넘침 | **100×100 정사각**, 넘침 없음 |
| 칸 채움 | 폭 3~(폭−3) 안, 아래쪽에 모음 | **네 변까지 바탕을 꽉 채운다**(바탕 `rect` 100×100) |
| 그림자 | 발밑 타원 .26 + 오른아래 쐐기 .16 — **쐐기도 칸 안에서 끝낸다** | **없음** (땅 자체라 그림자를 드리우지 않는다) |
| 외곽선 | 덩어리 `#2b2118` 2.5 / 작은 부분 1.8 | **칸 끝에 선·테두리 금지** — 이어 붙이면 줄이 생긴다. 안쪽 무늬에만 1.1~1.6 |
| 칸 경계 | 좌우로 1px 도 안 나감 | 무늬(꽃·돌)는 **칸 끝 12 안쪽**에만. 끝에 걸치면 옆 칸에서 잘린다 |
| 변형 | 없음 | 2~4장(`_a`~`_d`) — 같은 그림이 되풀이돼 보이지 않게. 바탕색은 변형끼리 같게 |
| 테두리(벽돌·돌) | — | 바탕 그림에 넣지 않는다. **바깥쪽 변에만** 보여야 하므로 물가(`shore_*`)처럼 **가장자리 조각 12장**(n·e·s·w + in 4 + out 4)을 따로 그려 코드가 덧그린다 |
| 놓는 법 | 하나씩 놓기(개수 차감) | 끌어서 칠하기, 위에 서 있는 물건을 또 놓을 수 있다 |

#### 칸을 덮는 식물 — 멀리서 보이는 것은 '색 덩어리의 크기'다 (2026-09-20, 꽃밭을 다섯 번 고쳐 그리며 배운 것)

아이는 마당을 **칸 12~23px** 거리에서 본다. 그 거리에서 꽃 한 송이는 2~3px 이라 **개별 꽃은 어차피 안 보이고, 보이는 것은 색이 이어진 면의 크기**다. 고대비의 작은 동그라미를 고르게 뿌리면 "환공포증"·"징그럽다"가 된다(실제 사용자 반응).

| 하지 말 것 | 할 것 |
|---|---|
| 칸당 꽃 수를 채우기(25~40송이) — 작은 점이 빽빽 | **큰 꽃, 적은 수.** 꽃이 **서로 닿아 이어진 색 면**이 되게(칸 하나 ≈ 한 색) |
| 한 칸에 여러 색을 흩뿌리기(색종이) | **주색 하나 + 같은 계열의 옅은 곁색.** 색 변형은 '밭마다 주색이 다른 것' — 한 파일 + 주소 뒤 `#색`(`:target`) |
| 꽃마다 검은 외곽선 · 가운데 점 · 흰 하이라이트 점 | 외곽선 없이 **같은 색의 어두운 면**으로 입체. 하이라이트는 크고 연하게 하나 |
| 짙은 잎 위에 밝은 꽃(명암 차 큼) | 잎은 풀밭과 비슷한 밝기(`#3f7a30`~`#529640`) — 눈이 쉴 데 |
| 같은 크기·같은 모양을 등간격으로 | 크기·기울기를 흩트리고, **변형끼리 무리의 위치를 다르게**(넓게 깔았을 때 벽지가 안 되게) |
| 덩어리를 칸 가운데에만(넓게 깔면 초록 틈이 격자로) | 덩어리가 **칸 끝에 걸치게** — 걸친 부분은 모든 변형이 같게 그려 옆 칸과 맞물린다 |

**검사:** 칸 12px(배율 0.5)로 줄여서 **점박이로 보이면 실패, 색 덩어리가 있는 밭으로 보이면 통과.** 조건을 채웠는가보다 **"이게 예쁜가"**를 먼저 묻는다. 드문드문 피는 들꽃처럼 점이 남는 것이 성격인 종류는 **융단이 아니라 포인트 바닥**으로 쓴다.

기존 꽃다발형 1×1 꽃(d_y1·d_y2·d_y41~d_y44 …)은 **포인트용으로 그대로 둔다** — 아이들이 이미 갖고 있다.

### 무게 (2026-09-20 추가)

꾸미기를 열면 SVG 를 낱개로 50장 넘게 받는다. 새 그림은 **파일당 5KB 이하**(지금 평균)로 한다.

- 좌표는 **소수 둘째 자리까지**(`26.599999999` 금지 — 스크립트로 뽑았으면 반올림해서 쓴다).
- 같은 모양이 되풀이되면 `<defs>` + `<use>`. 색만 다르면 `<use fill="…">` 로 물려준다.
- 점이 많은 곡선 대신 원·타원·짧은 `q` 곡선. PR 본문에 **파일별 바이트**를 적는다.

### 예시 — 3×1 소파

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="300" height="150" viewBox="0 0 300 150">
  <!-- 바닥선 y=150. 그림자·다리를 여기 맞춘다 -->
  <ellipse cx="150" cy="142" rx="128" ry="9" fill="rgba(0,0,0,.20)"/>
  ...
</svg>
```

### 예시 — 1×1인데 위로 솟는 가로등

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="100" height="260" viewBox="0 0 100 260">
  <!-- 폭은 1칸, 높이는 2.6칸 → 칸 위로 1.6칸 솟는다 -->
</svg>
```

## 배치 코드가 이미 해 둔 것

- **뒤→앞 정렬**: **발밑 줄**(`row + 높이 − 1`) 오름차순으로 그린다(`_decoSorted`/`_decoFootRow`).
  시작 줄이 아니라 발밑이 기준이다 — 세로 3칸 아치를 2줄에 놓으면 발밑은 4줄이고,
  3줄에 있는 장식보다 **나중에**(앞쪽에) 그려져야 한다.
- **캐시**: id마다 한 번만 불러온다. 파일이 없으면 다시 시도하지 않는다(404 반복 없음).
- **비동기 안전**: 그림이 늦게 도착하면 `_drawDeco()`로 한 번 다시 그린다.
- **폴백**: 파일이 없거나 크기를 못 읽으면 기존 캔버스 그림으로 되돌아간다.

## 확인된 것 (2026-09-04)

- 로직 테스트 11/11 — 정렬·발밑 정렬·비율 유지·위로 넘침·캐시·폴백
- 브라우저 실렌더 — 3×1 소파 SVG가 늘어남 없이 붙고, 1×1 가로등이 칸 위로 솟음
- SVG는 서버가 `image/svg+xml`로 내려줘야 캔버스에 그려진다.
- **밑줄로 시작하는 파일은 Jekyll이 빼버린다** — `_example…`이 404가 나서 확인함. 이름을 `d_`로 시작하는 장식 id로 쓰면 문제없다.
  (로컬 테스트 서버가 `text/html`로 주면 조용히 실패하니 주의)
