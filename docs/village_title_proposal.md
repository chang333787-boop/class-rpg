# 마을 칭호 — 제안 한 장 (구현 전 · 2026-09-20 맥북 마을 프로그램 담당)

> 방향(보스 09-20): 사회시뮬의 가치 6 = **복수의 정답, 등급이 아니라 칭호, 20명이면 서로 다른 마을 20개.**
> ⭐ 마을 별(#528)은 '더 높은 등급'을 여는 게 아니라 **그 마을이 어떤 마을인지 말해 주는 이름**으로 이어진다. 점수·순위는 없다.
> 앞선 메모: `docs/village_engine_gap_20260920.md` §C-3(자동으로 하나를 붙이는 안) — 이 문서가 그것을 **아이가 고르는 안**으로 고쳐 쓴다.

## 1. 한 줄
아이가 지은 것을 세어 **"너희 마을은 이런 마을 같아"** 하고 후보 두세 개를 보여 주고, **아이가 하나를 고른다.** 고른 칭호는 마을 이름 곁과 마을 어귀 간판에 선다.

## 2. 지킬 것
| | |
|---|---|
| 등급이 아니다 | 칭호끼리 위아래가 없다. 칭호가 **여는 것·주는 것은 없다**(해금·보상·이사 속도 0). 있으면 "가장 이득인 칭호"가 정답이 된다. |
| 아이가 고른다 | 판정은 **후보를 추릴 뿐**이다. 고르지 않을 수도 있다(칭호 없는 마을도 온전한 마을). |
| 멋대로 안 바꾼다 | 마을이 달라져도 고른 칭호는 그대로 둔다 — 아이의 것이다. 새 후보가 생기면 **알려만** 준다. |
| 도배가 답이 아니다 | 문턱은 "그렇게 보일 만큼"이면 끝. 문턱을 넘은 뒤엔 더 많이 놓아도 달라지는 게 없다. |
| 이름은 따로 | 아이가 직접 적는 마을 이름(`name` 12자 — 학교 65차, `sync.js` #369)과 **섞지 않는다**. 보이는 꼴: `🌷 꽃피는 마을 · 햇살마을` |

## 3. 칭호 목록과 판정 (문턱은 **임시값** — 아래 '정하는 법')
세는 단위는 **놓인 개수**(아이가 손가락으로 셀 수 있게). 길·집은 어느 마을에나 있으니 세지 않는다. 종류 묶음은 쓰임새 탭 표(`USE_TABS`)와 `K` 의 규칙 필드(`need`·`jobs`)를 그대로 쓴다.

| id | 칭호 | 세는 것 | 문턱(임시) |
|---|---|---|---|
| `flower` | 🌷 꽃피는 마을 | 꽃밭 전부(`FLOWER_KINDS`) + 화분 | 20 |
| `forest` | 🌳 숲속 마을 | 나무·큰나무·과일나무·덤불·다듬은 나무 | 25 |
| `market` | 🛒 북적이는 장터 마을 | 가게·온실·풍차(= `jobs` 가 있는 것) | 4 |
| `play` | 🛝 뛰노는 마을 | 놀이터·광장·정자·분수 | 4 |
| `book` | 📚 책 읽는 마을 | 도서관·학교·박물관 ×3 + 표지판(글이 적힌 것) | 5 |
| `water` | 💧 물가 마을 | 연못·우물·분수·다리 | 5 |
| `rest` | 🪑 쉬어 가는 마을 | 긴의자·작은 의자·가로등 | 12 |
| `guest` | 🚂 손님 맞는 마을 | 기차역 있음 + 오늘 손님 수(`visitStats`) | 역 1 · 손님 10 |
| `home` | 🏡 오순도순 마을 | (기본 — 늘 후보) | — |

**판정식(순수 함수 둘)**
```
titleCounts(cells)            → { flower: 23, forest: 8, market: 1, … }     // 칸을 한 번 훑는다
titleCandidates(counts, table, max = 3)
  = table 에서  counts[id] / 문턱 ≥ 1  인 것을  비(counts/문턱)가 큰 순으로 max−1 개  +  'home'
```
- '비'는 **후보를 추리는 데만** 쓴다. 화면엔 숫자·막대·등수를 안 보인다 — 후보 카드에는 까닭만: "꽃밭이 23개나 있어요".
- 후보가 `home` 하나뿐이면(작은 마을) 고르기 카드를 띄우지 않는다 — 고를 게 없으니까.

**문턱을 정하는 법**: 창조자의 눈 저장본 2개(`tmp/creator_eye`)와 하네스로 만든 마을(집 10·50·96채)에서 `titleCounts` 를 찍어, "보통으로 지은 마을이 후보 2~3개를 얻는" 값으로 맞춘다. 한 마을이 여덟 칭호를 다 얻으면 문턱이 낮은 것이다.

## 4. ⭐ 마을 별은 어디에 쓰나 — 두 안
돌아오는 목표는 **끝 무렵**(본래 목표가 둘 이하로 남은 뒤)에야 온다. 별을 칭호의 입장권으로 삼으면 대부분의 아이는 칭호를 못 만난다.

| | A안 (추천) | B안 (보스 메모 그대로) |
|---|---|---|
| 칭호 처음 고르기 | **인구 20 + 후보 2개 이상**이 된 순간 카드가 한 번 뜬다(중반 — 광장 즈음) | 첫 ⭐ 를 얻었을 때 |
| 칭호 바꾸기 | 마을 어귀 간판(또는 위쪽 마을 이름)을 누르면 **언제나** | ⭐ 를 새로 얻을 때마다 한 번 |
| ⭐ 의 쓰임 | **간판 꾸밈** — 별 1·3·6·10개에 깃발·테두리·밤 불빛이 하나씩 는다(그림은 디자인 담당). 별은 **줄지 않는다** | 바꿀 기회 + 간판 꾸밈 |
| 걱정 | 언제나 바꿀 수 있으면 가벼워 보일 수 있다 → 바꿀 때 "어제까진 🌳 숲속 마을이었어요" 한 줄로 역사를 남긴다 | 중반의 아이는 마을이 바뀌어도 칭호를 못 바꾼다 · 별이 '쓰는 돈'처럼 읽히면 프리모드 원칙(돈 금지)에 닿는다 |

## 5. 화면 (생김새는 디자인 담당 — 여기엔 동작만)
```
┌──────────── 우리 마을은 어떤 마을일까? ────────────┐
│  [🌷 꽃피는 마을]    [💧 물가 마을]    [🏡 오순도순 마을]  │   ← 카드 3장(≥ 88px), 하나를 누르면 끝
│   꽃밭이 23개나 있어요   연못과 우물이 6개예요   이웃이 31명 살아요   │
│                                   나중에 고를래요 ›          │
└──────────────────────────────────────────────┘
```
- 서는 곳: ① 위쪽 제목 `🧺 우리반 마을` 자리에 `🌷 꽃피는 마을`(이름이 있으면 `· 햇살마을`) ② **마을 어귀 간판**(새 물건 아님 — 첫 길 끝에 저절로 서는 장식, 디자인 담당) ③ 하루 소식 첫 줄 ④ (규칙 게시 뒤) 친구 마을 목록·구경 화면.
- 새 후보가 생기면: 토스트 한 번 "💡 이제 💧 물가 마을이라고 불러도 되겠어요 — 간판을 눌러 봐요". 큰 소식 줄(#498)에 선다. 하루에 한 번까지.
- 첫 안내 중·친구 마을 구경 중·사진 모드에는 안 뜬다.

## 6. 저장
- 마을 저장(v2)에 **선택 키 `title`** 하나: 칭호 id(`'flower'`). 없으면 키를 두지 않는다. 옛 판은 모르는 키를 읽지 않으므로 호환. (옛 판이 **저장**하면 키가 빠진다 — 새 필드 공통의 문제이고 MAC-FRESH #520 이 옛 판을 걸러 준다.)
- 글자가 아니라 **id 를 저장**한다 → 칭호 말을 나중에 고쳐도 아이의 선택이 남고, 모르는 id 는 '칭호 없음'으로 읽는다.
- `sync.js`: `meta.title` 을 `name` 과 **똑같은 방식**으로(문자열 16자, 비면 키 생략 → 칭호 없는 마을의 해시는 그대로). `scripts/village-sync/test.mjs` 에 왕복 1건. **Firebase 규칙은 건드리지 않는다**(meta 아래 자유 키인지 월요일에 학교 보스와 확인).
- 간판 꾸밈 단계는 저장하지 않는다 — 별 수(`goals` 의 `r…`)에서 매번 센다.

## 7. 코드 꼴 (규칙 모듈)
`VRULES.titles = { on: true, minPop: 20, maxCands: 3, nudgePerDay: 1 }` · 순수 함수 `titleCounts`·`titleCandidates` · 표 `TITLES` · 훅 `__titles()`.
비용: 칸 훑기는 **카드를 열 때·별을 얻을 때·하루에 한 번**뿐(틱마다 아님) → 프레임 영향 0. 기존 줄 수정 0(새 블록 + simTick 고리 한 줄 + 저장/불러오기 고리).

## 8. 협업자(사회시뮬)에게 묻고 싶은 것
1. **후보를 추리는 것 자체가 '정답 알려 주기'가 되지 않나?** 아예 아홉 칭호를 다 보여 주고 고르게 하는 편이 가치 6 에 더 맞는가, 아니면 "마을이 실제로 그런 마을일 때만"이 자기 마을을 돌아보게 하는 장치로 더 나은가.
2. 겨울 사회시뮬에서 칭호가 **마을끼리의 관계**(장터 마을에 손님이 간다 등)로 이어질 계획이 있는가 — 있다면 지금 id 를 그 분류에 맞춰 두고 싶다.
3. 칭호를 **반 전체가 볼 때**(친구 마을 목록) 같은 칭호가 몰리면 어떻게 보이길 바라는가 — "우리 반엔 꽃피는 마을이 7곳" 같은 집계는 순위가 아니니 괜찮은가.

## 9. 하지 않는 것
순위·점수·칭호별 보상 · 마을이 바뀌었다고 칭호를 자동으로 바꾸기 · 칭호를 얻으려면 무엇을 몇 개 더 놓으라는 안내("꽃밭 3개만 더!") — 그 순간 칭호가 목표가 되고 등급이 된다.
