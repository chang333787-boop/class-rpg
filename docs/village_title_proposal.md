# 마을 칭호 — 제안 v2 (결정 반영 · 구현 직전 · 2026-09-20 맥북 마을 프로그램 담당)

> 방향(보스 09-20): 사회시뮬의 가치 6 = **복수의 정답, 등급이 아니라 칭호, 20명이면 서로 다른 마을 20개.**
> v1(#541)에 보스가 조언자(사회시뮬 세션) 의견을 걸러 돌려준 결정을 넣었다. **v1 에서 바뀐 곳은 ★.**
> 앞선 메모: `docs/village_engine_gap_20260920.md` §C-3(자동으로 하나를 붙이는 안) → 이 문서가 **아이가 고르는 안**으로 고쳐 쓴다.

## 1. 한 줄
**칭호는 메뉴가 아니라 거울이다.** 마을이 실제로 그런 마을일 때만 "너희 마을은 이런 마을 같아" 하고 후보 두세 개가 떠오르고, **아이가 하나를 고른다.** 고른 칭호는 마을 이름 곁과 마을 어귀 간판에 선다.

## 2. 지킬 것
| | |
|---|---|
| 등급이 아니다 | 칭호끼리 위아래가 없다. 칭호가 **여는 것·주는 것은 없다**(해금·보상·이사 속도 0). |
| ★ 관계는 놓인 것에서 | **마을끼리의 관계는 놓인 것에서 나오고, 고른 칭호에서 나오지 않는다.** 칭호가 손님을 부르면 '가장 이득인 칭호'가 생긴다. 겨울 사회시뮬에서 장터에 손님이 간다면 그것은 **가게가 있어서**지 '장터 마을'이라 불러서가 아니다. |
| ★ 거울 | 후보는 **실제로 그런 마을일 때만** 뜬다. 고르지 않을 수도 있다(칭호 없는 마을도 온전한 마을). |
| ★ 판이 없다 | **전체 칭호 목록을 어디에도 두지 않는다** — 도움말·친구 목록·고르기 카드 어디에도 아홉 칸 판, 회색 잠긴 칸, "n개 중 m개"가 없다. 판이 보이는 순간 도감이 되고 '다 모으기'가 정답이 된다. 아이가 보는 것은 **지금 자기 마을에 떠오른 후보뿐**이다. |
| ★ 숨은 점수가 없다 | 까닭 문장에 **절대 숫자를 쓰지 않는다**("꽃밭이 23개나" ✕). 친구끼리 대 보는 점수가 된다. **자기 마을 안의 비교**로 말한다("집 다섯 채에 꽃밭이 하나꼴이에요") — 자기 마을에서 세어 확인할 수 있고 친구와는 못 댄다. |
| 멋대로 안 바꾼다 | 마을이 달라져도 고른 칭호는 그대로 — 아이의 것이다. 새 후보가 생기면 **알려만** 준다. |
| 도배가 답이 아니다 | 문턱을 넘은 뒤엔 더 많이 놓아도 달라지는 게 없다. ★ 문턱이 **집 수에 견준 비**라서 1×1 을 도배해도 집이 늘면 도로 내려간다. |
| 이름은 따로 | 아이가 직접 적는 마을 이름(`name` 12자 — 학교 65차, `sync.js` #369)과 **섞지 않는다**. 보이는 꼴: `🌷 꽃피는 마을 · 햇살마을` |
| 하지 않는 안내 | "꽃밭 3개만 더!" 같은, 칭호를 얻으려면 무엇을 더 놓으라는 말. 그 순간 칭호가 목표가 되고 등급이 된다. |

## 3. ★ 칭호와 판정 — 자기 마을 안의 비교 (H = 놓인 집 수)
길·집은 어느 마을에나 있으니 **잣대**로만 쓴다. 우물·가게·놀이터·의자는 주민의 *필요*라 어느 마을에나 조금은 있다 → 필요를 채우는 만큼으로는 칭호가 안 된다(우물은 물가에서 뺐고, 가게·의자는 '필요보다 넉넉할 때'만).

| id | 칭호 | 그런 마을일 때 | 아이가 듣는 까닭(숫자 없음) |
|---|---|---|---|
| `flower` | 🌷 꽃피는 마을 | 꽃밭·화분 ≥ H ÷ 5 | "집 다섯 채에 꽃밭이 하나꼴이에요" · (≥ H 면) "집보다 꽃밭이 더 많아요" |
| `forest` | 🌳 숲속 마을 | 나무·덤불·다듬은 나무 ≥ H ÷ 3 | "집 세 채에 나무가 한 그루꼴이에요" · (≥ H 면) "집보다 나무가 더 많아요" |
| `market` | 🛒 북적이는 장터 마을 | 가게·온실·풍차 ≥ 4 이고 ≥ H ÷ 10 | "가게와 일터가 여럿 모여 있어요" |
| `play` | 🛝 뛰노는 마을 | 놀이터·광장·정자·분수 ≥ 4 | "놀 곳이 여럿 모여 있어요" |
| `book` | 📚 책 읽는 마을 | 도서관·학교·박물관 가운데 **두 가지 이상** | "도서관도 학교도 있어요"(있는 둘을 말한다) |
| `water` | 💧 물가 마을 | 연못·분수·다리 ≥ 3 (우물은 필요라 안 센다) | "연못과 분수, 다리가 어우러져요" |
| `rest` | 🪑 쉬어 가는 마을 | 긴의자·작은 의자 ≥ H ÷ 10 (그리고 ≥ 6) | "골목마다 쉴 의자가 있어요" |
| `road` ★새 | 🛣️ 길이 시원한 마을 | 길(길·큰길·자갈길·횡단보도·가로수 열) ≥ H × 2.25 | "집보다 길이 훨씬 길어요" |
| `guest` | 🚂 손님 맞는 마을 | 기차역 + 글이 적힌 표지판 ≥ 3 | "기차역이 있고 손님이 읽을 표지판이 여럿이에요" |
| `home` ★ | 🏡 오순도순 마을 | **사람 사는 집의 80% 이상이 😊**(사는 집 5채 이상) | "이웃이 거의 다 웃고 있어요" |

- ★ **🏡 오순도순은 기본 카드가 아니다.** v1 에서는 늘 세 번째 카드였다 — 까닭이 인구 숫자뿐이라 '꽝·위로상'으로 읽힌다. 이제 돌아섬 규칙(§5-1)과 이어진 **참인 읽기**가 있을 때만 뜬다. 실제로 어렵다(아래 두 마을 다 아님) — 다른 칭호와 같은 급이다.
- ★ `guest` 를 "오늘 손님 수"로 재던 것을 버렸다 — 하루 중 시각에 따라 후보가 나타났다 사라진다. 놓인 것(역·표지판)만 본다.
- `road` 를 더했다 — 아래 pop88 마을처럼 '집과 길이 길게 뻗은 마을'을 비출 말이 v1 에 없었다.

**판정(순수 함수 둘)**
```
titleCounts(cells, homes)      → { H, flower, forest, market, play, bookKinds, water, rest, road, station, signs, lived, happy }   // 칸을 한 번 훑는다
titleCandidates(counts, table) → 조건이 참인 id 들(순서 = 표 순서). 세기·비율·등수를 돌려주지 않는다.
```
- ★ **후보가 셋보다 많으면 '센 순서'로 자르지 않는다** — 그것이 숨은 점수다. 카드를 열 때마다 **돌아가며 셋**을 보인다(연 횟수로 자리를 민다). "다른 것도 볼래요 ›" 로 다음 셋.
- 후보가 하나도 없으면 카드를 띄우지 않는다. 첫 카드는 **인구 20 + 후보 2개 이상**일 때 한 번.

두 마을 모두 후보가 2~3장 뜬다. 가게·우물은 '필요만큼'이라 장터·물가는 둘 다 아니다 — 거울이 맞게 비춘다(두 마을 다 가게가 집 열네 채~열아홉 채에 하나).
**칼날 위의 값**: pop167 의 꽃밭(20 vs 19)·pop88 의 길(164 vs 153)은 문턱 바로 위다. 후보가 **나타났다 사라졌다** 하지 않게, 한 번 뜬 후보는 값이 문턱의 **90% 아래로** 내려가야 사라진다(코드에서 `keep: 0.9`). 고른 칭호는 그와 무관하게 남는다.

## 4. ⭐ 마을 별 — A안 확정

|---|---|

## 5. 화면 (생김새는 디자인 담당 — 여기엔 동작만)
```
┌──────────── 우리 마을은 어떤 마을일까? ────────────┐
│  [🛝 뛰노는 마을]          [🛣️ 길이 시원한 마을]             │   ← 지금 떠오른 후보만(2~3장, ≥ 88px)
│   놀 곳이 여럿 모여 있어요     집보다 길이 훨씬 길어요            │
│                                   나중에 고를래요 ›          │
└──────────────────────────────────────────────┘
```
- 서는 곳: ① 위쪽 제목 자리 `🛝 뛰노는 마을`(이름이 있으면 `· 햇살마을`) ② 마을 어귀 간판(디자인) ③ 하루 소식 첫 줄.
- ★ **반 목록·구경 화면**: 칭호는 **이름 곁에 나란히만.** 집계 문장("꽃피는 마을이 7곳")도, 칭호별 묶음도, "우리 반에 하나뿐" 같은 드묾 표시도 없다. 순서는 번호·이름 순 그대로.
- 새 후보가 생기면 토스트 한 번 "💡 이제 📚 책 읽는 마을이라고 불러도 되겠어요 — 마을 이름을 눌러 봐요". 큰 소식 줄(#498)에 서고 하루에 한 번까지. **이미 칭호를 고른 마을에도** 알린다(바꾸라는 게 아니라 비춰 주는 것).
- 첫 안내 중·친구 마을 구경 중·사진 모드에는 안 뜬다.

## 6. 저장
- 마을 저장(v2)에 **선택 키 둘**: `title`(칭호 id) · `titleWas`(직전 id — "어제까진…" 한 줄용). 없으면 키를 두지 않는다. 옛 판은 모르는 키를 읽지 않으므로 호환(옛 판이 저장하면 키가 빠진다 — 새 필드 공통의 문제, MAC-FRESH #520 이 옛 판을 걸러 준다).
- 글자가 아니라 **id** 를 저장 → 칭호 말을 고쳐도 선택이 남고, 모르는 id 는 '칭호 없음'으로 읽는다.
- `sync.js`: `meta.title` 을 `name` 과 **같은 방식**으로(문자열 16자, 비면 키 생략 → 칭호 없는 마을의 해시 그대로). `scripts/village-sync/test.mjs` 에 왕복 1건. `titleWas` 는 서버에 안 올린다(이 기기의 한마디일 뿐). **Firebase 규칙은 건드리지 않는다**(meta 아래 자유 키인지 월요일에 학교 보스와 확인 — 확인 전에는 `sync.js` 쪽을 **스위치로 꺼 둔 채** 올린다).
- 간판 꾸밈 단계·후보는 저장하지 않는다 — 별 수(`goals` 의 `r…`)와 놓인 것에서 매번 센다.

## 7. 코드 꼴 (규칙 모듈) · 나눠 올리기
`VRULES.titles = { on: true, minPop: 20, show: 3, keep: 0.9, nudgePerDay: 1 }` · 순수 함수 `titleCounts`·`titleCandidates` · 표 `TITLES` · 훅 `__titles()`(dev 에서만 세기를 보여 준다 — 아이 화면엔 없다).
비용: 칸 훑기는 **카드를 열 때·하루에 한 번**뿐(틱마다 아님) → 프레임 영향 0. 기존 줄 수정 0.
1. **PR ①(이 문서 다음)**: 판정·고르기 카드·위쪽 이름 자리·저장 키·새 후보 알림. `sync.js` 는 안 건드린다(칭호는 이 기기에만).
2. PR ②: `sync.js` `meta.title` + test — 월요일 규칙 확인 뒤.
3. 간판 그림·별 꾸밈: 디자인 담당(보스가 넘김). 프로그램 쪽은 `window.__titleNow()`(id·말·별 수)를 내놓는다.

## 8. 조언자에게 물었던 것과 답 (보스가 걸러 전달)
1. 후보를 추리는 것이 '정답 알려 주기'가 되나 → **아니다, 거울이면 된다.** 단 전체 목록은 어디에도 두지 말 것(§2 '판이 없다').
2. 칭호가 마을끼리의 관계로 이어지나 → **안 된다.** 관계는 놓인 것에서(§2). id 를 교육과정 분류에 맞출 필요 없다.
3. 반 전체가 볼 때 → 이름 곁에 나란히만. 집계·묶음·드묾 표시 없음(§5).
