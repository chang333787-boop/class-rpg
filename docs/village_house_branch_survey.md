# '집' 갈래 조사 — 아파트가 끼면 어디가 흔들리나 (2026-09-21 · **조사만 · 수정 0**)

> 보스: "`k === 'house'` 갈래가 46군데다. 한 번에 '집 가족'으로 묶는 것이 이번 묶음에서 가장 큰 위험이다. **분류표를 먼저 주고 멈춰라.**"
> `CLAUDE.md` §1 **조사 먼저, 수정 나중.** 기준: `main` 7630469 (`village/index.html`).

## 0. 먼저 — 수를 다시 셌습니다. **46이 아니라 96 + 27 입니다**

| 꼴 | 줄 수 | 무엇 |
|---|---|---|
| `… === 'house'` | **55** | 집인가 묻는다 |
| `… !== 'house'` | **41** | 집이 아니면 건너뛴다 |
| **갈래 합** | **96** | |
| `'house'` 를 **인자로 박은 것** | **27** | `centerOf('house', …)` · `footprint('house', …)` · `dims('house', …)` · `canPlace/placeAt('house', …)` · `glbParts('house', …)` · `countKind('house')` · 트레이 탭 · 목표 |
| **합** | **123** | |

보스가 세신 46은 `k === 'house'` 한 꼴만이고, **`!== 'house'` 41군데가 더 있습니다.** 그리고 더 조심스러운 쪽은 오히려 **인자로 박힌 27**입니다 — 여기는 조건문이 아니라서 **눈에 안 띄고, 틀려도 조용합니다**. 예: `centerOf('house', …)` 는 **2×2 를 가정하고 가운데를 잡습니다.** 크기가 다른 아파트가 이 길로 들어오면 **말풍선·카메라·수레가 반 칸씩 어긋난 채 아무 오류도 안 납니다.**

## 2. 그래서 — 길이 둘입니다

| | ⓐ 집 가족으로 묶기 | **ⓑ 집의 곁 값 `세대`** |
|---|---|---|
| 아파트란 | 새 종류(`apart`)가 '집처럼' 행동 | **그냥 `house`** 인데 `hinfo` 에 `세대: 4` 가 붙은 칸 |
| 건드릴 곳 | **96 갈래 + 27 인자** | **다섯 자리** — 모양 고르기(1954) · 자리 수(`houseCap`) · 흐름 소비 · 집 카드 한 줄 · 저장 한 칸 |
| 크기 | 아무 크기나 | **2×2 고정**(`house` 와 같아야 한다) |
| 기존 저장본 | 갈래마다 확인 필요 | **한 줄도 안 바뀐다**(세대 없으면 1) |
| 조용한 어긋남 | `centerOf/footprint('house')` 27군데 | **없다**(같은 종류라 같은 길로 간다) |

**추천은 ⓑ입니다.** 마침 `city.json` 의 아파트가 **이미 2×2**라 크기 제약이 지금은 비용이 아닙니다.
층별로 모양이 갈리는 자리(1954)가 이미 있으니, **거기서 `세대` 를 한 번 더 보면** 높은 건물이 섭니다 — 갈래 하나를 늘리는 것이지 새로 만드는 것이 아닙니다.

> 보스가 바라신 "46군데를 다 건드리지 않고도 될 수 있다"가 **됩니다.** 다만 값은 **크기를 못 바꾸는 것**입니다. 나중에 3×2 아파트를 원하면 그때 ⓐ를 별도 묶음으로 합니다.

## 3. 빈 칸 메움 — **아파트에 몇 명이 사나**

**한 세대 = 2명 = 어른 1 = 몫 1.** 그래서 **`세대: 4` 인 아파트는 8명**이 산다.

| 세는 것 | 값 | 왜 이 수인가 |
|---|---|---|
| 자리 수 | `세대 × 2` (4세대 = **8**) | 보통 집 1층이 2명(`HOUSE_CAPS[1]`)이다 — **한 세대의 크기를 그대로** 쓴다 |
| 어른 | `round(8/2)` = **4** | `jobsAdultsOf` 그대로 → **세대마다 어른 하나**. 손 안 댄다 |
| 붐빔 | 8명분 | `res.get` 그대로 → 아파트 앞이 더 붐빈다. 손 안 댄다 |
| 흐름 | **4몫** | 세대 수 그대로 |

**`HOUSE_CAPS` 는 안 건드립니다.** 그 표는 **보통 집의 층**(2·4·6)이고, 아파트는 층이 안 오르므로(보스 결정 2) 표를 탈 일이 없습니다 — `houseCap` 한 함수가 *"세대가 있으면 `세대 × 2`, 없으면 `HOUSE_CAPS[lv]`"* 로 갈리면 끝입니다. 보스가 짚으신 "넷이 여섯이면 1.5명" 문제는 **표를 안 타므로 생기지 않습니다.**
