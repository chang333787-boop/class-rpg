# 세대는 어느 문으로 드나드나 — 칸을 쓰거나 지우는 길 전수 (2026-09-21 · 조사 + 한 곳 고침)

> 보스: "문이 셋이었습니다 — 저장(제가), 되돌리기(담당이), 옮기기(관찰자가). **하나씩 두들겨 잡는 방식으로는 넷째가 없다고 말할 수 없습니다.**
> 칸을 쓰거나 지우는 길을 전부 늘어놓고, 각 길에서 세대가 살아남는지 표로 주십시오. 같은 처방을 네 번째로 복사하게 되면 **한 곳으로 모여야 한다는 신호**입니다."
> 기준 코드: `main` 5262fa3.

## 0. 표를 만들다 알게 된 것 — **문은 셋이 아니라 하나였다**

길을 늘어놓고 보니 **칸을 지우는 길은 `removeAt` 하나**, **칸을 쓰는 길은 `placeAt` 하나**로 이미 모여 있었다.
그 둘에는 집의 상태를 실어 나르라고 만든 고리가 **이미 달려 있다** — `keepStash`(removeAt 고리) · `keepRestore`(placeAt 고리).
주석에도 그렇게 적혀 있다: *"집이 다시 놓이면 맡아 둔 식구·층이 돌아온다(**되돌리기·옮기기·새로 짓기 모두**)"*.

**그런데 제가 거기에 넣은 줄이 틀려 있었습니다.**

```js
const n = …, h = hinfo.get(rec.root), lv = h ? h.lv : 1;
hinfo.delete(rec.root);                                   // ← 여기서 지우고
…
KEEP.stash.push({ n, lv, 세대: (hinfo.get(rec.root)||{}).세대 | 0, … });   // ← 지운 뒤에 읽었다 → 늘 0
```

**세대를 `hinfo.delete` 뒤에 읽고 있었습니다. 언제나 0 이었습니다.**
그래서 KEEP 이 아무것도 안 실어 날랐고, 문마다 처방이 따로 필요해 **보였던** 것입니다. 되돌리기에 따로 붙인 처방(`homeUndo`)도 그래서 필요했습니다.
**고칠 곳은 한 줄이었습니다** — 지우기 **전에** 읽기. 그리고 빈 아파트도 맡도록 조건 하나(`n === 0 && lv <= 1` → `&& hh <= 1`).

## 2. 그대로 둔 것 하나 — `__snapshot`(20번)
시험 도구(`run.mjs`)가 읽는 훅입니다. `res` 를 훑어 만들기 때문에 **식구가 없는 아파트가 '사는 집'에 안 잡힙니다.**
아이 화면에는 안 나오고, 통과 기준 ①②③은 **식구가 있는 판**으로 재므로 지금 결과에는 영향이 없습니다.
다만 **빈 아파트만 있는 판을 도구로 재면 0으로 보입니다** — 도구 쪽 일이라 여기서 손대지 않고 적어만 둡니다.

## 3. 넷째 문이 없다고 말할 수 있나
**칸을 쓰거나 지우는 길로는 없습니다.** `cells[…] = …` 를 하는 곳은 `placeAt` 뿐이고, 지우는 곳은 `removeAt` 뿐이며, 표의 1~19가 그 둘을 다 지나갑니다.
**세대를 읽는 쪽**(세기·말)은 다른 축이고, 거기서 둘을 찾아 함께 고쳤습니다 — 15(목표)·16(가게 카드).
남은 위험은 **새로 생기는 문**뿐입니다: 앞으로 집 상태를 나르는 새 길을 만들면 `keepStash`/`keepRestore` 를 지나게 하거나, 안 지나면 여기 한 줄 더합니다.
